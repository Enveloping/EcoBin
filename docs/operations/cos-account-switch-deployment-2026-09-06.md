# COS 新账号切换记录（2026-09-06）

## 1. 范围与结果

本次只切换今后新照片和新软件制品的 COS 写入位置，不迁移、不删除旧对象，也不修改数据库
中已经保存的照片 URL。最终目标为：

| 用途 | 地域 | 存储桶 | 读取边界 |
|---|---|---|---|
| 设备投递、清运和验收照片 | `ap-beijing` | `ecobin-photo-1436310712` | 普通 HTTPS 地址可读，写入只使用作业前缀短期凭证 |
| 香橙派业务发布包及后续 MCU 固件 | `ap-beijing` | `ecobin-update-package-1436310712` | 私有读写，只向单个已确认对象签发短期读取授权 |

旧上海图片桶不再用于新上传。旧图片仍由原 URL 直接读取，不做复制、重写或代理兼容。

## 2. 配置与秘密边界

本地开发配置写入 Git 忽略的 `.ecobin/application-local-secrets.yml`。生产服务器把两套 COS
用途分别暂存为 `/run/secrets/cosSecretId`、`cosSecretKey` 和
`businessReleaseCosSecretId`、`businessReleaseCosSecretKey`；长期原件只存在于
`/etc/ecobin/secrets` 的 root-only 文件中。没有把凭据写入 `runtime.env`、容器环境变量、
Git、文档或命令输出。

生产非秘密配置同时固定两个桶、地域和 HTTPS 基础位置。业务程序远程下发开关保持
`false`，因此这次存储切换不会向任何设备发送更新命令。

部署工具同步增加以下保护：

- 真实模式要求业务更新包桶的凭据和非秘密位置配置完整；
- 图片桶与更新包桶必须不同，基础 URL 必须与桶和地域精确一致；
- 生产预检拒绝把新增凭据放入 `runtime.env`；
- 容器探针要求真实模式只读挂载新增凭据，Fake 模式不得残留；
- 本地配置模板和旧 `.env` 迁移工具保留新增字段。

## 3. 切换过程

切换前数据库只读检查确认没有正在投递、正在清运或仍持有租约的可靠任务；MCU 固件发布数
和非终态部署数也均为 0。候选脚本与新凭据先进入服务器 root-only 暂存目录，经文件权限、
长度和 Bash 语法检查后，才在稳定部署锁内停止应用。

运行配置、持久凭据和三个部署脚本均通过同目录候选原子替换。秘密暂存服务随后重新生成
容器只读视图，生产预检通过后再启动后端与 Web。部署成功后删除暂存目录；用于失败自动恢复
的旧 COS 凭据备份在独立验证通过后也被精确删除，因此服务器已不能自动退回旧账号。

## 4. 验证事实

真实 COS 探针确认：

- 两个桶及凭据均可访问；
- 图片测试对象通过普通 HTTPS 返回原字节；
- 更新包测试对象通过普通 HTTPS 返回 403，通过短期签名地址返回原字节；
- 更新包桶版本控制状态为 `Off`，满足原子禁止覆盖前提；
- 照片 STS 凭据只能在本次作业前缀内上传和读取，越界写入返回拒绝；
- MCU 固件 STS 凭据只能读取私有桶内指定发布前缀，写入被拒绝；
- 所有随机探针对象均已删除。

生产切换及独立复核确认：

| 检查 | 结果 |
|---|---|
| 生产预检 | PASS，真实外部服务模式 |
| 运行秘密隔离探针 | PASS；新增两项凭据只读挂载 |
| 后端 / Web | `running / healthy` |
| 新图片桶服务器网络 | 不存在对象返回 404 |
| 私有更新包桶服务器网络 | 未签名请求返回 403 |
| 切换后后端启动错误 | 0 |
| 公网首页 | HTTP 200 |

## 5. 尚未随本次上线的内容

生产当前仍运行 V64 后端镜像。本次已经让照片和业务程序发布包使用新账号；把 MCU 固件读取
授权从图片桶改到私有更新包桶的代码及专项测试已进入仓库，但需随下一次受控后端发布上线。
由于现场没有任何 MCU 固件发布或进行中部署，这一延期不会影响现有业务，也没有存量对象需要
迁移。

本次没有创建正式业务发布签名根，没有导入第八阶段 OneNet 物模型，没有迁移 V65/V66，也
没有开启或触发真实业务程序远程更新。腾讯云侧旧账号凭据是否彻底撤销仍需在旧账号控制台
确认；服务器和本地活动配置已经不再使用它。
