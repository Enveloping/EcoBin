## 故障与数据安全

平台管理员结束异常投递时返回 `DATA.ACCESS_ERROR`，请求号为 `435f3764-750e-4389-aed5-3816a248b872`。完整日志显示，会话版本检查已经通过，事务在把设备安全置为“已禁用”时被 MySQL 检查约束 `ck_dev_asset_control_shape` 拒绝。

## 根因与修正

异常结束流程原 SQL 先把 `lifecycle_status` 改成 `DISABLED`，随后用 `CASE WHEN lifecycle_status = 'NORMAL'` 决定是否写入禁用原因。MySQL 对单表 `UPDATE` 的赋值按从左到右求值，后面的 `CASE` 读取到已经变为 `DISABLED` 的值，于是保留原来的空原因。数据库约束要求已禁用设备必须同时具备非空禁用时间和原因，因此拒绝整条更新。

修正后先写禁用时间和禁用原因，最后再写生命周期状态，使条件判断读取原始状态。已禁用设备再次经过幂等路径时仍保留原原因。回归测试固定了字段赋值顺序，防止后续格式调整重新引入同一故障；正常手动禁用路径直接写入原因，不存在这项条件判断问题。
