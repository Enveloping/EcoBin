# 反向 SSH 远程维护排障与验收手册

本文记录 2026-08-29 在 Orange Pi Zero 3、Air780E USB RNDIS 和封版 nftables 规则上
完成 Web 按需反向 SSH 闭环时遇到的问题。它用于后续部署、诊断和回归，不改变远程维护
的短期授权、低权限账号、回环监听和失败关闭边界。

## 1. 先区分控制面与数据面

正常链路为：

```text
Web 开启会话
  → 后端创建短期租约和证书
  → OneNet 下发 OPEN
  → 香橙派硬件进程把意图交给独立远程维护代理
  → 代理执行 ssh -R 并连接跳板
  → 跳板形成 actual 和 127.0.0.1:短期端口监听
  → 后端收敛为 OPEN
  → 操作员经 ProxyJump 登录设备 sshd
```

`OPEN`、服务器 `actual` 和监听端口属于控制面或连接状态证据。只有从跳板回环端口读到
香橙派 OpenSSH 标识，并且操作员能够使用短期证书实际登录，才证明数据面也已连通。

远程维护不是设备正常注册、配置或开展投递/清运的必经步骤；它只是出现故障时按需开启的
维护通道。

## 2. 本轮遇到的故障及判断方法

| 现象 | 实际原因 | 关键判断 |
|---|---|---|
| 会话最终为 `FAILED / CONNECT_TIMEOUT`，设备 `ssh` 退出码 255，跳板无监听 | 封版输出链没有允许专用代理访问跳板 SSH；部分新建 SSH SYN 又被判为 conntrack `invalid` | 先核对设备是否建立到跳板的 TCP 连接，再检查精确出站规则是否位于 `invalid-output` 丢弃之前 |
| 后端、设备和服务器均显示 `OPEN`，跳板也有监听，但回环端口读不到 SSH 标识，约一分钟后断线 | 返回数据在 RNDIS 输入方向被判为 conntrack `invalid` | 控制状态不能关闭问题；观察回环 banner、TCP 队列和 ServerAlive 超时，并核对返回例外是否位于 `invalid-input` 丢弃之前 |
| 新规则刚生效，约 3 秒后又消失 | `ecobin-first-boot` 常驻进程仍加载旧 Python 模块，并周期性重放封存防火墙 | 磁盘文件正确不代表常驻进程已更新；部署后跨多个协调周期复查实际 nftables 规则 |
| 蜂窝服务修复后规则仍被覆盖 | 生产防火墙有蜂窝协调器和首次启动封存清理两个写入者 | 规则实现更新时必须同时重启两个协调器，不能只重启蜂窝服务 |
| 排障回退后相关服务保持 `inactive` | 临时 systemd mask、drop-in 或人工 hold 没有清理 | 恢复时只清理本轮建立且已经核对归属的临时措施，然后 `daemon-reload` 并逐项检查服务状态 |
| 部署时 Web 短暂显示离线 | 受控重启运行目标后，蜂窝和 MQTT 正在恢复 | 以恢复后的 OneNet 生命周期事实、服务状态和后续稳定观察判断；不能把重启窗口当成稳态故障 |

## 3. 防火墙修复边界

最终规则只允许：

- `ecobin-remote` 专用 UID 向受保护凭据中解析出的跳板 IPv4 和 SSH 端口发起 TCP 连接；
- 在选定 Air780E RNDIS 接口上，接收来自同一跳板 IPv4、以跳板 SSH 端口为源端口的
  返回数据；
- 两条精确例外分别位于 `invalid-output` 和 `invalid-input` 丢弃规则之前。

该规则不允许普通账号使用 SSH 出站，不开放设备目标端口 22，也不移动或删除全局
`invalid` 丢弃规则。不得用“临时开放所有 22 端口”代替精确修复。

## 4. 固定诊断顺序

1. 核对后端会话 UID、端口、期限、期望状态、设备上报状态、服务器租约和失败码。
2. 在跳板核对同一会话的 `desired`、`actual` 和 `127.0.0.1:端口`监听，避免把旧租约
   或旧端口当成本轮结果。
3. 从跳板回环端口读取 SSH 标识；读不到时，问题尚未通过数据面。
4. 在设备核对远程维护代理状态、本地会话库、`ssh -R` 进程、到跳板的 TCP 连接及日志。
5. 按实际规则顺序核对 nftables，不只查“是否存在某条 allow”。特别检查精确例外是否在
   对应 `invalid` 丢弃之前。
6. 修改部署后等待超过首次启动协调器的重放周期，再复查规则和服务，排除旧常驻模块覆盖。
7. 至少稳定观察三个 ServerAlive 周期，并完成一次真实操作员登录，不能以单次 banner
   成功代替稳定性。
8. 不主动延长验收租约；等待自然到期或按 Web 正常关闭，确认 `desired`、`actual`、监听、
   设备隧道、维护登录进程和端口占用全部消失。

## 5. 安全部署与复测顺序

1. 先完成本地回归、Python 3.11 兼容检查和待部署文件摘要核对。
2. 保留串口或局域网等已验证的本地恢复路径，记录本轮临时 systemd 措施。
3. 停止两个防火墙写入者，备份目标文件，安装候选后先做 Python 编译和 nftables 语法检查。
4. 启动蜂窝、首次启动、硬件网关和远程维护服务，并等待多个协调周期。
5. 复核四项服务、Air780E、可信时间、MQTT、规则顺序和文件摘要。
6. 从 Web 新建短期会话，依次验证控制状态、回环 banner、真实登录、稳定保持及到期清理。
7. 只清理本轮建立的 hold、mask、drop-in 和临时探针，不改动其他运维状态。

不要手工把数据库会话改成 `OPEN`，不要关闭 Host Key 校验，不要签发长期证书，也不要为
通过验收而延长原会话期限。这些做法会绕过本来要验证的链路。
