## 5. 网络中断与断点续传

在真实私有 COS 对象上，从 52,428,800 字节偏移发起恢复请求，服务返回 HTTP `206`，
`Content-Range` 的起点和总大小均与请求及冻结制品一致；最终文件为 53,755,880 字节，摘要与
健康发布完全一致。

故障发布下载过程中还实际遇到蜂窝网络中断。更新器先后保留约 34,603,008 字节和
53,477,376 字节的可信暂存内容，网络恢复后继续同一更新，没有把临时故障误判为制品错误，也
没有从零重新下载。实现边界为：

- 临时网络错误、读取超时或授权到期保留同一制品的私有暂存文件；
- 新授权到达时重新计算已有片段摘要，并从文件精确长度使用 Range 续传；
- 必须校验 `206`、范围起点和对象总大小；服务若返回完整 `200`，先截断再安全重下；
- 范围、大小、摘要、签名或制品身份不一致时删除暂存并拒绝安装；
- 临时签名 URL 不落盘、不写日志、不进入事件。

## 7. 测试边界和遗留事项

设备直达命令使用的部署编号不存在于后端权威部署表。OneNet 收到的更新进度因此会在重试后以
“找不到部署记录”阻塞。最终只读查询确认 3 个直达测试部署合计 30 条进度任务均已达到
`BLOCKED` 终态，没有仍在重试的任务。这些任务是可追溯的测试噪声，不影响设备当前兼容性或业务准入；不能
直接修改数据库把它们伪造成正式计划成功。另有一条修复前的软件事实任务已经被后续第 39、47
号事实取代，同样不应盲目重跑。

后续需要平台管理员登录后完成：

1. 查看并按审计制度确认上述直达 HIL 告警；
2. 在下发开关的受控单设备窗口内，用平台页面创建真实计划；
3. 补测工作中等待与安全取消、准确 URL 到期换授权、设备离线及后端短时收不到事实；
4. 核对更新器、通信代理、后端部署记录和业务准入四层事实一致，再关闭窗口；
5. 后续灰度批次另行实现和验收，不在本次范围。

v32 镜像负责固化本次断点续传源码，当前只允许离线构建和审计。没有用户再次确认指定磁盘前，

`hardware-runtime-20260907-32`。配置替换具备独立备份和失败回滚；生产预检、双容器健康、运行
