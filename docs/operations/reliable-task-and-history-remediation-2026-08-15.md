# 可靠任务与历史数据收敛审查（2026-08-15）

## 1. 审查目的

本次审查回答两个问题：

1. 当前是否仍有可靠任务在无意义地反复执行或产生重复尝试；
2. 哪些历史数据可以受控压缩，哪些数据仍承担业务、外部渠道或审计证据，不能删除。

`BLOCKED` 表示任务因永久技术失败、证据冲突或必须人工排障而终止自动执行。它不等于任务
仍在后台重试，也不要求全部改成 `DONE`。治理目标是让业务状态与证据一致，而不是把
`BLOCKED` 数量清零。

### 2.3 历史设备入站任务

11 个历史 `PROCESS_INBOX` 任务处于 `BLOCKED`，共有 17,486 次尝试，主要来自早期

## 3. 已确认的剩余生产源头

### 3.1 设备任务等待原因没有在创建时初始化

三个设备任务登记入口插入任务时均省略 `dispatch_wait_reason`。生命周期事件会对既有任务
重新计算闸门，但如果离线设备在任务创建后没有新的生命周期事件，等待原因会一直为空。

修复要求：任务创建事务先锁定 `dev_device_transport_state`，按 `ONLINE / OFFLINE / UNKNOWN`
分别写入空值、`DEVICE_OFFLINE`、`DEVICE_PRESENCE_UNKNOWN`；服务启动时只做一次旧任务对账，
不恢复高频数据库扫描。

### 3.2 授权创建明确拒绝后，关联查询任务没有自动终态收敛

授权行已经进入 `CREATE_REJECTED`，查询执行器也能在不调用微信的情况下返回 `DONE`；缺失的
是创建拒绝事务对精确查询任务的唤醒。修复必须只唤醒同一授权的 `PENDING/BLOCKED` 查询
任务，不重开已经 `DONE/CANCELLED` 的任务。

### 3.3 支付创建明确拒绝后，充值单仍停在待支付

`CREATE_NATIVE_PAYMENT` 的永久失败目前只形成对账问题并阻断技术任务，没有终止本地充值单。
只有在没有二维码、没有微信交易号、没有成功回调或成功查单证据时，明确的创建拒绝才允许
把充值单改成 `CLOSED`；已经超过订单有效期时改成 `EXPIRED`。原技术任务继续保留永久失败
证据，恢复旧任务时不得再次调用微信创建接口。

## 4. 历史尝试压缩边界

生产库当时共有约 58,004 条 `ops_task_attempt`。目前可进一步制作受控压缩工具的候选约为：

- 提现本地等待空转：保留首尾代表后约 10,880 条候选；
- 11 个历史入站任务：按 15 组不同结果和诊断各保留首尾后约 17,456 条候选。

候选总数约 28,336，但本次没有获得执行删除授权。后续如执行，必须同时满足：

1. 任务 UID 精确白名单，且任务已经终止、没有租约；
2. 尝试没有外部调用、请求、响应、HTTP 状态、错误响应或回收租约事实；
3. 没有支付、转账、授权观察或其他外键引用；
4. 删除前导出到仓库外 ACL 受限目录并记录 SHA-256；
5. 默认只预演，设置最大行数、精确确认短语，并在停止写入后用维护身份执行；
6. 每个不同技术结果和诊断组合至少保留最早与最晚样本。

运行快照、支付/转账/授权观察、钱包账本、投递单、清运记录、袋代际事件和仍被外键引用的
任务尝试不在本次压缩范围。

## 5. H02 迁移来源异常与批准边界

本地固定 H02 的 V30 校验值与当前提交不一致。Git 历史显示当前 V30 没有提交后的修改，
说明本地固定环境曾执行过未提交的 V30 草稿。生产 V30 校验值与当前仓库一致，生产不受影响。

禁止对本地 H02 执行 Flyway `repair`，也禁止修改当前 V30 去迎合本地历史。项目负责人已于
2026-08-15 明确批准：先在仓库外保存 ACL 受限逻辑备份与摘要，然后只删除本地固定 H02 的
容器、数据卷和网络；旧本地秘密随备份归档，不直接销毁。随后使用当前已提交 V1～V51 从
空库重新供应。

供应脚本还必须在任何副作用前：

- 拒绝迁移目录中已暂存、未暂存或未跟踪的修改；
- 记录 Git 提交、迁移文件逐项 SHA-256 清单及清单总摘要；
- 允许仓库其他目录存在与数据库无关的用户改动，不把它们误判为迁移污染。
