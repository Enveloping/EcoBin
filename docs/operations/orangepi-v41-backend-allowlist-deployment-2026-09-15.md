## 变更前检查与连接消歧

最初尝试恢复生产连接时，WSL 中的 Termius 密钥均未进入认证阶段；Windows OpenSSH 的
`myserver` 别名又实际指向名为 `vultr` 的其他服务器。两类探测都只执行 `hostname` 等只读
命令，目标主机名不符后立即停止，没有上传或修改文件。最终使用 v40 已提交部署记录中的生产
地址、Windows 已保存的主机指纹，以及 `ubuntu` 用户的既有 RSA 身份连接；远端主机名精确为
`VM-0-16-ubuntu`，并通过免交互 sudo 运行受控脚本。

第一次通过 PowerShell 文本管道发送只读预检时，全部业务检查已经输出 PASS，但管道末尾附带
的 CR 字符令远端 Bash 多执行了一条无效空命令，最终退出码为 1。该过程没有写入服务器配置。
之后改为直接向 SSH 标准输入写入原始脚本字节，获得退出码 0 的完整预检：v40 存在、v41
不存在、认可键唯一、旧配置已经在健康容器中生效、远程下发关闭。

正式部署脚本在应用前经过独立只读审查。审查先发现回滚路径可能在 `set +e` 条件下吞掉前序
激活失败，以及回滚后没有验证容器实际重新读取旧值；修复为每一步显式传播失败，并让正向和
回滚共用完整的激活后检查。第二轮又要求在持锁后证明旧文件、旧容器环境和服务都健康，并约束
`runtime.env` 及备份必须是单硬链接普通文件。全部修复后，审查固定脚本 SHA-256 为
`c69fef97596ff7a23fca78cf735a0d164e7d291423d398aee33749a3c21d76b6`，最终复审结论为可部署、
无剩余生产阻断项。
