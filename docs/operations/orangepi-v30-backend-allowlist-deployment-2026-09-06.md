## 2. 替换原因

v29 的仓库代码具备远程业务程序更新逻辑，但镜像中的正式 systemd 启动命令没有给永久通信
代理和永久更新器传入远程业务更新启用参数；同时，更新器服务禁止访问下载所需的网络地址族。
因此 v29 可以完成普通投递和清运，却不能作为远程更新验收镜像。

v30 修正了这两个结构性问题，并继续保留以下边界：

- 更新器只信任固定的北京私有 COS 基础地址；
- 临时下载 URL 由后端在每次实际发送时生成；
- 包摘要和 Ed25519 签名决定制品身份，URL 不决定身份；
- 更新器没有额外 Linux capability，不能访问业务、通信或硬件设备目录；
- 镜像只有验签公钥，没有签名私钥，也没有预置更新任务。

完整镜像身份和审计结果见
[v30 单卡远程业务更新镜像证据](../../hardware/image-artifacts/evidence/hil-remote-business-update-20260906-30/README.md)。
