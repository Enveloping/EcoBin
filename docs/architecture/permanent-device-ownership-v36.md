> 生效日期：2026-08-07

## 1. 为什么改变

旧模型把一台物理设备拆成“资产、租户分配、机构部署、现场验收、经营开关、回收、再次部署”等多层状态。这个模型适合反复出租和调拨设备，但不符合 EcoBin 当前业务：设备一旦交给一个租户和一个机构，就不会再换归属。

本次把设备模型收敛为四个核心概念：

1. **物理设备资产**：一台真实机器及其长期不变的硬件身份；
2. **永久归属**：平台只分配一次租户，租户只分配一次机构；
3. **新业务准入**：系统根据当前事实实时判断能否开始新的投递或清运；
4. **最终报废**：平台永久终止设备的新业务能力。

因此，部署不再是独立业务对象，部署码也不再存在。

## 2. 本裁决的效力

本文件覆盖所有较早文档和代码中的下列语义：

- 可变租户分配、租户设备池、租户回收、跨租户调拨；
- 可变机构部署、迁址新建部署实例、跨机构重新部署；
- `deploymentCode` / `deployment_code`、部署码下发及部署码二维码；
- 部署级平台验收、机构现场验收和人工确认；
- 租户手动开启投递/清运及租户界面的部署进度；
- 分配时轮换 OneNet Device Key；
- 以部署码拼接 COS 对象路径或识别 OneNet 上下行消息。

旧文档可以保留上述内容作为历史讨论，但不得再指导实现。判断目标行为时，以本文件和 2026-08-07 之后明确引用本文件的基线为准。

## 3. 最终业务流程

```text
平台创建设备资产，并生成永久设备公开码
  → 厂家让设备联网
  → 平台根据软件可重复验证的功能证据自动完成机器验收
  → 平台把设备永久分配给一个租户
  → 租户把设备永久分配给一个机构
  → 平台按该机构的小程序 AppID 生成并打印设备二维码
  → 厂家安装初始空袋并登记每个投口的袋码
  → 机构只负责现场安装、通电和联网
  → 设备自动取得配置并重新测量初始空袋皮重
  → 满足当前准入事实的投口自动可用
```

机构不再执行部署确认、现场验收、开启经营或其他激活动作。设备完成机器验收后，投递和清运资格不保存为人工开关；设备联网且所有实时条件满足时自动允许新业务。

## 4. 永久归属规则

设备资产直接保存 `tenant_id` 和 `organization_id`：

- `tenant_id` 初始为空，只允许由平台从空写入一个值；
- `organization_id` 初始为空，只允许在租户已确定后，由该租户从空写入其下属机构；
- 重复提交相同值属于幂等重试，返回原结果；
- 已有值后提交不同值必须失败，数据库也必须阻止绕过应用层的修改；
- 禁止清空、替换、回收、转租、调拨或重新部署；
- 分配错误时只能由平台报废该设备，不能修改归属；
- 禁用、报废、租户禁用或机构禁用都不清除永久归属。

平台、租户和机构仍可查看各自发生过的业务订单和资金记录；永久归属不表示禁用后仍有设备管理查看权。

## 5. 三种设备身份

### 5.1 硬件身份

正式 IoT（物联网）链路使用 OneNet 已认证的产品 ID 和设备名识别硬件。当前产品下设备名固定等于硬件 SN。后端只信任 OneNet 可信消息元数据，不信任载荷自报的租户、机构或设备身份。

### 5.2 设备公开码

平台创建设备资产时生成随机、不可预测且永久不变的 `device_public_code`：

- 它只帮助小程序定位一台设备，不是密码或控制凭证；
- 不使用数据库自增 ID、硬件 SN、OneNet Device Key 或产品密钥；
- 一个公开码只对应一台资产，并建立唯一索引；
- 报废后永久失效，不能重新绑定到其他资产；
- 用户接受静态二维码可能被拍照或转发的风险，后端仍必须鉴权并检查设备准入条件。

### 5.3 机构小程序二维码

每个机构使用独立小程序 AppID，因此平台在机构永久分配完成后，才通过该机构配置生成小程序码。二维码场景只携带设备公开码，不携带或暗示可信的租户 ID、机构 ID 或部署码。

扫码后的后端流程是：公开码定位资产 → 资产读取永久机构和租户 → 校验请求所在 AppID 与资产机构 AppID 一致 → 鉴权/注册用户 → 检查新业务准入。AppID 不一致、设备未分配、已禁用或已报废时，对普通用户按“设备不存在或不可用”处理，避免泄露跨机构信息。

## 6. 自动机器验收

机器验收属于平台设备资产，发生在分配租户之前，不属于租户或机构部署流程。设备联网后，平台根据可重复验证的功能证据自动判定；不设置人工“通过”按钮。

自动验收至少验证：

- OneNet 产品和设备身份正确、连接事实为在线；
- 香橙派软件版本和协议版本受支持；
- MCU/UART（单片机串口）通信可建立，必要自检结果可用；
- 规定的传感器能够返回格式正确、时间有效的采样；
- 规定的摄像头能够采集并上传测试对象，存储可读取；
- 配置能够可靠保存，时间、持久化存储和安全状态满足要求；
- MCU 和摄像头的模拟来源标记随证据保存，只用于诊断，不参与通过或失败判定。

任一必要功能证据缺失、过期或失败时，验收保持未通过并记录具体原因；仅仅使用模拟 MCU 或模拟摄像头不会导致失败。验收通过后保存证据摘要、首次通过时间和最近复核时间；后续设备故障影响实时准入，但不伪造或删除历史验收事实。

这一修订只改变平台机器验收的自动判定，不表示模拟器能够证明真实线路、门锁、称重精度、镜头安装或机械结构。上述物理质量仍由厂家质检和 H-03 硬件在环验收负责，但不再阻止平台创建、验收和分配资产。

外观、屏幕坏点、镜头安装角度、机械装配、真实门锁行程等软件无法证明的事项由厂家生产质检负责，不由平台自动验收冒充已验证。

### 6.1 未分配设备的可信运行事实

设备已经在平台注册、但尚未永久分配机构，是厂家联网验收期间的正常状态，不是来源不可信。OneNet 已认证设备在这一阶段上报的设备运行快照、设备故障和安全传感器变化按平台资产事实接收，不得只因 `organization_id` 为空写入技术隔离。

- 运行快照可靠写入现有收件箱后直接完成，不建立机构运行状态；
- 故障和安全变化保留平台收件证据，并由平台向香橙派确认，使原可靠事件停止重试；
- 这些平台事实不生成机构告警、不改变已经成立的机器验收结果，也不开放投递或清运；
- 永久机构分配完成后产生的新事实进入该机构现有运行、故障和安全投影；
- 分配前产生、分配后才重投的同一事件仍保持平台作用域，不能因到达时间改变归属；
- 未注册设备、错误产品、错误摘要、非法目标或未分配设备伪造的投递/清运事实仍按原规则隔离。

作用域以可信事件发生时间和不可变 `organization_assigned_at` 判断。事件发生时间早于机构分配时间，或设备时钟不可信而没有发生时间时，属于平台；不早于机构分配时间时属于永久机构。机构分配后的首份配置应用和随后自动上报的新运行快照继续证明当前配置与安全状态，不增加人工确认。

## 7. 初始袋与现场自动启用

厂家出厂前为每个投口安装一个真实空袋并登记唯一袋码。机构安装设备后不录入袋码、不确认皮重，也不点击启用。

设备首次在永久机构现场联网时：

1. 后端识别资产并下发当前配置；
2. 香橙派对每个已登记初始袋执行真实空袋皮重测量；
3. 成功结果可靠上报并形成该袋的有效重量基准；
4. 对应投口在其他准入条件也满足时自动可用；
5. 单个投口失败只阻止该投口的新业务，并向平台产生可解释告警，其他健康投口不受影响。

模拟重量或人工填写数值不能代替正式皮重证据。

## 8. 新业务准入不是人工状态

系统不保存可被机构开启的 `business_enabled`。开始新的投递会话或清运操作时，后端在同一事务中锁定设备资产，并根据权威事实计算是否允许开始。

整机共同条件至少包括：

- 机器验收已通过；
- 永久租户和机构都已确定且当前未被禁用；
- 设备生命周期为 `NORMAL`，不是 `DISABLED` 或 `RETIRED`；
- OneNet 当前明确在线；
- 最新必要配置已经由香橙派可靠应用；
- 没有阻止新业务的严重故障或安全状态；
- 没有与请求冲突的整机独占作业。

投口还要满足自身启用、当前袋及有效皮重基准、满溢、配置和执行器条件。二维码尚未生成会阻止普通用户扫码进入，但不把二维码状态混入硬件机器验收。

租户或机构被禁用时，永久归属不变，但禁止创建新业务；恢复主体后，设备在所有事实重新满足时自动恢复，不需要再次分配或人工开启。

## 9. 管理操作与进行中业务

普通管理操作只关闭新业务入口，不取消后端已经创建的 `delivery_session`（投递会话）或 `clean_operation`（清运操作）：

| 操作或事实 | 新业务 | 已由后端创建的进行中业务 |
|---|---|---|
| 平台禁用设备 | 立即禁止 | 继续按原状态机收敛 |
| 平台恢复设备 | 条件满足后自动允许 | 无额外影响 |
| 平台报废设备 | 永久禁止 | 不自动取消，仍接收属于原作业的可信事件 |
| 修改配置/禁用投口 | 受影响的新业务等待新配置生效 | 使用启动时冻结的配置继续 |
| 设备离线 | 禁止新业务 | 保持原状态，等待可信事实或既有超时规则 |
| 租户/机构禁用 | 禁止新业务 | 不自动取消 |

并发结果以数据库事务提交顺序为准：订单先创建则属于既有业务；禁用或报废先提交则后来的创建请求失败。

火灾、烟雾、失控开门等物理安全事件是例外。安全控制可以停止危险动作，即使这会中断进行中业务；中断事实必须如实记录，不能伪造成正常完成。

## 10. 控制权限与可见性

- 只有平台可以禁用、恢复和报废设备；
- 租户只能把尚未分配机构的本租户设备永久分配一次；
- 机构保留日常价格/配置管理以及健康、容量和告警查看能力，但没有部署、验收、激活、禁用、恢复或报废操作；
- 租户界面不得展示部署进度；
- 设备进入 `DISABLED` 或 `RETIRED` 后，从租户和机构的设备列表、详情、实时状态、配置、故障、摄像头和控制入口中消失；
- 平台仍能查看禁用和报废资产、验收证据与审计记录；
- 历史订单、清运和资金事实通过各自冻结的设备/租户/机构快照继续向原有权利人展示，不反向开放设备详情。

## 11. 最小数据模型（D-047）

### 11.1 设备资产是唯一归属根

`dev_device_asset` 至少保存：

- 不可变 `hardware_sn` 与公开 `asset_uid`；
- 不可变、唯一 `device_public_code`；
- 一次性 `tenant_id`、`tenant_assigned_at`；
- 一次性 `organization_id`、`organization_assigned_at`；
- `acceptance_status`、验收时间和最近证据摘要；
- `lifecycle_status`：`NORMAL / DISABLED / RETIRED`；
- `control_version`、禁用/报废时间及原因；
- 当前配置版本和设备已应用版本的权威引用。

数据库约束或触发器必须保证永久归属和公开码不能被应用漏洞改写。应用层使用条件更新和资产行锁处理并发分配、控制与新业务创建。

### 11.2 直接归属资产的事实

投口、配置版本、配置应用、运行状态、故障、占用、设备命令、边缘事件、物理结果和机器验收证据直接关联资产，不再关联部署实例。配置版本在物理设备整个寿命内单调递增，不能因机构分配重新从 v1 开始。

投递会话、订单、清运操作和记录继续保存创建时的资产、租户、机构及配置快照，使设备后来禁用或报废时，历史业务仍可解释和收敛。

### 11.3 删除的模型

V36 的空库破坏式切换删除或废弃：

- 资产租户分配及“当前分配”表；
- 设备部署及“当前部署”表；
- 部署验收、回收、维护清场和常规密钥轮换确认表；
- 所有部署码字段、索引、命令字段、事件字段和外键；
- 人工经营开关和部署进度状态。

当前确认没有生产业务数据，因此不提供旧数据迁移、旧 API、旧二维码、旧 OneNet Schema v1 或旧边缘 SQLite 的兼容层。V1～V35 仍作为固定历史迁移保留，V36 通过前向迁移完成结构切换；目标环境按 V1～V36 重建空库。

## 12. 接口与设备协议（I-057）

### 12.1 HTTP 与小程序

- 平台：创建设备、查看/重试自动验收、永久分配租户、禁用、恢复、报废、下载机构二维码；
- 租户：查看仍可管理的本租户设备、永久分配机构；
- 机构：查看正常设备、管理允许的日常配置和价格；
- 小程序：统一使用 `deviceCode` 定位资产，不再提交 `deploymentCode` 或可信 `tenantId`；
- 注册来源改为不可变的 `registered_via_asset_id`，不再保存部署实例。

### 12.2 OneNet v2

- 上行载荷不含部署码、租户或机构；资产来自可信 OneNet 产品/设备元数据；
- `eventUid` 保持全局稳定，设备事件序号按物理设备寿命单调递增；
- 边缘持久化库增加稳定 `edgeStoreInstanceUid`，避免本地数据库重建后序号与旧实例碰撞；
- 下行通过 OneNet 设备名寻址，并携带不可变目标设备名供香橙派再次核对；
- Device Key 与产品/设备身份在正常生命周期内保持不变，普通分配不轮换密钥；
- 密钥只存在于安全配置，不进入仓库、HTTP 响应、二维码或日志。

### 12.3 COS

照片仍由设备直传 COS（对象存储）。后端为原作业签发精确、短期上传前缀，香橙派只使用授权返回的完整前缀，不再用部署码自行拼接路径。完成事件继续回传实际四个照片 URL，后端不从路径推导业务归属。

## 13. 切换与验收

切换必须成对完成，禁止新后端与旧设备协议长期混跑：

1. 停止旧后端和边缘进程；
2. 再次确认目标库无生产业务事实并做好可恢复备份；
3. 将目标数据库重建/升级到 V36；
4. 在 OneNet 控制台发布无部署码的 v2 物模型；
5. 部署后端、Web、小程序和香橙派 v2；
6. 清除该测试设备旧边缘 SQLite，并以正式配置首次启动；
7. 重新创建设备资产、自动验收、永久分配租户/机构并生成二维码；
8. 使用当前可用的 MCU 和摄像头完成机器功能证据；真实物理质量另按厂家质检和 H-03 验证。

软件验收至少覆盖：

- 第二次分配不同租户或机构必然失败，相同请求可幂等返回；
- 禁用/报废与新业务创建并发时，结果服从事务提交顺序；
- 禁用或报废前已创建的作业仍可接收可信完成事件；
- 禁用/报废后的伪造新作业和新业务请求被拒绝；
- 租户/机构看不到禁用或报废设备，平台仍可审计；
- 公开码、AppID 和永久归属的跨机构检查生效；
- OneNet 上下行、COS 授权、重试、乱序、重复事件和边缘重启均不依赖部署码；
- 模拟 MCU、模拟摄像头在所有功能证据合格时可以通过平台机器验收，且模拟标记仍如实保存在证据中。

## 14. 给新开发者的判断方法

遇到设备相关需求时先问两个问题：

1. **这是要开始一笔新业务吗？** 如果是，读取资产当前状态并执行完整准入检查。
2. **这是已经由后端创建的作业在继续上报吗？** 如果是，按作业身份、资产一致性、幂等和状态机收敛，不用设备当前禁用/报废状态推翻既有作业。
