## 1. 最终决定

整个平台只保留一个普通设备二维码入口地址。它是应用级非秘密配置，不属于租户、机构
或小程序渠道，也不再通过机构管理页面维护。

配置键与默认值为：

```text
ecobin.miniapp.device-entry-base-url
https://www.jinshoubao.com/device-entry/
```

生产环境可通过 `miniappDeviceEntryBaseUrl` 显式提供同一个值。应用启动时校验它必须是
完整 HTTPS 地址、具有主机名、不含账号信息、URL 片段或已有 `deviceCode` 参数；配置错误
会阻止后端启动，避免生成错误二维码。

## 2. 每台设备的二维码为什么仍然不同

基础地址全局相同，但后端会追加该永久资产唯一的设备公开码：

```text
https://www.jinshoubao.com/device-entry/?deviceCode=<设备公开码>
```

设备公开码只用于查找永久资产。后端依据资产上已经永久写入的租户和机构归属判断用户
进入哪个机构，再校验该机构是否绑定当前 AppID 对应的小程序渠道。二维码不携带租户 ID、
机构 ID、AppID、AppSecret、OneNet 密钥、设备密钥或部署码。

设备尚未永久分配机构，或机构尚未绑定有效小程序渠道时，资产接口不返回
`deviceEntryUrl`。这只表示当前不能展示用户入口二维码，不是人工经营开关，也不改变机器
验收、设备在线或投递资格事实。

## 3. 小程序怎样解析

微信扫描普通链接二维码后，会把原始链接放入启动参数 `query.q`。小程序先进行一次 URL
解码，再从查询参数中提取唯一、大小写精确的 `deviceCode`；缺失、重复或格式不合法都按
无效入口处理。解析成功后，登录接口仍同时提交当前 AppID、微信登录码和设备公开码：

- AppID 只确定共享小程序渠道并取得该渠道下的 OpenID；
- 设备公开码确定永久资产及其机构；
- OpenID 与机构共同确定或创建相互隔离的机构账号和钱包。

因此，微信后台只需配置普通二维码规则前缀
`https://www.jinshoubao.com/device-entry/`，无需为每台设备增加一条规则。

## 4. 管理与数据库边界

- 平台的小程序渠道接口只维护 AppID、AppSecret、展示名称、激活状态和登录状态；
- 租户和机构页面不展示二维码入口，也不能覆盖全局地址；
- V41 删除 `iam_miniapp_channel.entry_base_url` 及其检查约束，不保留旧字段读取、双写或
  兼容分支；
- 设备资产查询在机构存在有效渠道绑定时，用全局地址和设备公开码即时生成
  `deviceEntryUrl`；不生成二维码文件，也不等待异步任务。

## 5. 微信校验文件与部署

Web 静态资源固定包含：

```text
/device-entry/5JOZivQ9vw.txt
```

部署后必须确认该 URL 返回 HTTP 200，响应正文与微信提供的原文件逐字节一致，并且没有
被 SPA 回退页替代。该校验文件只证明域名路径控制权；普通二维码规则、开发版/体验版限制
和微信审核状态仍需在微信公众平台单独完成。

## 6. 验收条件

1. 机构小程序配置请求和响应都不再出现 `entryBaseUrl`；
2. V41 后数据库不存在 `iam_miniapp_channel.entry_base_url`；
3. 未覆盖配置时，设备二维码以默认地址开头并且只追加一个 `deviceCode`；
4. 两台设备得到相同基础地址、不同设备公开码；
5. 未绑定渠道的机构设备不返回二维码入口；
6. 构建后的校验文件与微信原文件 SHA-256 一致；
7. 小程序从普通链接的 `query.q` 正确提取设备公开码，并由后端资产归属决定机构。
