# V52 设备自注册、厂家初始袋与按需远程维护

> 实施日期：2026-08-15。本文是 V52 的跨端权威说明，覆盖后端、Web、共享小程序的设备出厂端、
> OneNet、香橙派、跳板服务器和目标数据库。生产安装步骤见
> [部署手册](../deployment/device-enrollment-and-remote-support-rollout.md)。2026-08-15 的实现审查与
> 修复证据见 [V52 代码审查](../review/device-enrollment-factory-remote-support-v52-review-2026-08-15.md)。

## 1. 已冻结的结论

1. 新香橙派使用厂家全局引导密钥 `K1` 自行生成设备身份并向后端注册。首版不设置厂家
   固定注册名额或业务注册时段，但每个网络挑战仍然短时有效、只能消费一次，并有请求限流。
2. 后端成功创建永久设备资产和 OneNet 设备后，直接把 OneNet 设备密钥及运行配置加密
   返回给本次香橙派。设备验证并原子保存该凭证后，注册即完成；不再等待 OneNet 下发一个
   “完成注册”指令。
3. 香橙派保存正式凭证以后，删除 `K1`、未完成注册状态和注册密钥生成实现。删除是降低
   批量滥用风险的生产清理措施，不把普通 SD 卡伪装成可信执行环境；在离厂前仍必须控制
   镜像、物理接触和厂家网络。
4. 设备注册完成不等于通过机器验收。厂家必须先以独立厂家操作员身份进入共享小程序的
   隐藏设备出厂端并扫描设备码，
   再为每个实际投口扫描平台签发的 EB1 初始袋码。所有投口都完成初始装袋以后，平台的
   自动验收才有资格启动。尚未验收的 Web 历史录入袋不等同于实体扫码，必须逐投口补扫。
5. 平台管理员只需在 Web 个人账户中登记自己的一把 Ed25519 SSH 公钥一次，不需要给
   每台设备重复配置用户公钥。设备统一信任维护用户证书颁发机构（CA）的公钥，后端只在
   一次远程维护会话内给管理员公钥签发短期证书。
6. 后端通过 OneNet 命令要求某台设备开启或关闭反向 SSH。跳板服务器固定复用
   `22011～22014` 四个回环端口，因此首版最多四台设备同时维护，但设备总数不受四个端口
   限制；会话关闭或到期后，只有服务端确认旧监听已经消失才释放端口供下一台设备复用。

## 2. 设备自注册流程

### 2.1 出厂镜像中一次性存在的内容

出厂镜像或生产写卡步骤需要放入：

- `/etc/ecobin/enrollment.key`：厂家全局 `K1`，只允许 root 读取；
- `ecobin-enrollment.service` 和注册运行目录；
- 后端 HTTPS 地址、引导密钥编号和注册模式；
- 普通硬件服务。硬件服务声明 `Requires=ecobin-enrollment.service`，正式设备凭证不存在时
  不启动业务进程。

这些内容不是每台人工生成不同密钥。生产工具只需把同一受控注册包写入待验收设备，设备
第一次启动时自行产生随机身份。

### 2.2 香橙派生成并持久化的身份

首次启动时，香橙派生成：

- Ed25519 注册签名密钥；
- X25519 响应解密密钥；
- Ed25519 反向隧道密钥；
- Ed25519 SSH Host Key，用于管理员确认连接的确是目标设备。

`hardwareSn` 由注册公钥摘要稳定派生，格式为 `ECM0-...`。生成后的完整未决状态先以
`0600` 原子写入 `/var/lib/ecobin/enrollment-state.json`，然后才发网络请求。突然断电后
继续使用同一个 `enrollmentUid` 和同一套身份，不能意外创建第二台 OneNet 设备。

### 2.3 后端认证和创建事实

流程如下：

1. 设备请求短期挑战，后端保存随机 nonce、密钥编号、来源摘要、过期时间和一次性状态。
2. 设备把挑战、注册身份、四类公钥和注册模式组成规范字节串；用 `K1` 计算 HMAC，同时
   用设备自己的 Ed25519 私钥签名。
3. 后端先原子消费挑战，再校验 HMAC、设备签名、`hardwareSn` 派生关系以及请求字段。
   同一个挑战不能注册第二次；同一个 `enrollmentUid` 的相同请求只返回原进度，不同请求
   会产生幂等冲突。
4. 后台续作调用 OneNet 设备详情/创建 API。创建时把本次注册身份写入描述标记；如果网络
   超时或平台返回重名，先查询详情恢复不确定结果。相同设备名但描述标记不同会被判为所有权
   冲突，不能接管别人的 OneNet 设备。
5. 后端创建或采用永久设备资产，保存设备注册公钥、隧道公钥和 SSH Host Key，只保存
   OneNet 设备 ID，不明文持久化 OneNet 设备密钥。
6. 后端用设备本次 X25519 公钥派生 AES-256-GCM 密钥，把 OneNet 密钥、设备公开码、
   MQTT 配置、跳板 Host Key 和维护 CA 公钥加密为 `READY` 响应。

设备收到 `READY` 后校验附加认证数据摘要、完成 AEAD 解密、校验全部正式凭证，再把
`/etc/ecobin/device-credentials.json` 原子落盘。只有落盘后才删除：

- `/etc/ecobin/enrollment.key`；
- `/var/lib/ecobin/enrollment-state.json`；
- 指定的 `device_enrollment.py` 注册实现副本；
- 旧设备采用模式下用于证明原 OneNet 身份的旧密钥文件。

每项删除都对目录执行同步，且操作幂等。断电发生在清理中间时，下次启动先验证正式凭证，
再继续清理剩余文件，不会重新注册。

### 2.4 为什么不需要额外的“完成注册”指令

事实边界是“后端已经创建资产和 OneNet 身份，并把只有本次设备能解密的正式凭证返回；
设备已经校验并保存”。这时设备已经具备连接 OneNet 的全部条件。再依赖尚未建立的 OneNet
链路下发完成指令会形成循环依赖，也会让一次 HTTP 成功与后续命令丢失之间产生悬空状态。

后续连接 OneNet、初始装袋和机器验收是注册后的独立事实；它们失败不会回滚设备身份，也
不会允许同一设备重新注册成另一条资产。

### 2.5 全局 K1 的现实边界

全局 `K1` 能减少生产操作，但泄漏后攻击者可仿造新的注册请求。当前实现通过短期一次性
挑战、请求限流、注册痕迹、OneNet 名称所有权标记、离厂删除和后端审计降低风险，却不能
把可读 SD 卡变成硬件根信任。生产必须做到：

- `K1` 不进入 Git、日志、设备正式凭证或普通应用配置；
- 只在受控厂家镜像/写卡环境和未验收设备短时存在；
- 验收确认设备已删除 `K1` 和注册实现后才能离厂；
- 发现泄漏时新增 `K2`，后端短期同时接受受控密钥编号，重新制作未出厂镜像；已注册设备
  不受轮换影响，因为它们已经删除 K1 并使用各自 OneNet/SSH 身份；
- 若未来要求抵抗设备被拆卡复制，应改用安全芯片、TPM/OP-TEE 或逐台烧录凭证，而不是
  继续叠加软件混淆。

## 3. 厂家首次装袋与自动验收

### 3.1 身份隔离

平台管理员在 Web 的“厂家操作员”页先创建独立工号，再为这个工号生成有效期 5 分钟、
只能使用一次的官方微信小程序码。码中原始令牌不会返回 Web 前端或写入日志。厂家人员用
本人微信扫描后，小程序以 `wx.login` 得到的 OpenID 完成绑定，后端签发独立的
`aud=miniapp-factory`、`entryMode=FACTORY_ACCEPTANCE` 会话。厂家操作员没有 Web 登录名、
密码或平台管理权限；平台管理员停用工号或解绑时，会同步撤销已有厂家会话。

设备出厂端与用户端、清运端使用同一个小程序，但出厂页面位于隐藏分包，用户端和清运端
不显示入口。已绑定厂家身份的微信默认进入设备出厂端；如果同一 OpenID 还具有普通用户或
清运身份，可在出厂端单向切换。切换后普通端没有返回出厂端的按钮，直至普通身份明确退出
才恢复厂家优先。厂家人员从微信外部扫描普通设备码时仍进入出厂端，并直接加载该设备，
不会意外发起用户投递。

### 3.2 初始袋登记

验收员扫描永久设备二维码后，小程序按设备实际 `expectedPortCount` 展示投口：

1. 对每个投口扫描平台已签发且通过防伪认证的 EB1 袋码；
2. 后端锁定设备和标签，确认标签没有被其他设备、投口或周转袋使用；
3. 写入厂家安装袋事实、标签占用、厂家操作员、操作时间和审计记录；
4. `Idempotency-Key` 是平台全局操作身份，同时绑定厂家操作员、平台作用域、动作、设备投口
   和请求摘要；同一绑定重试只返回当前结果，不会重复占袋，换人、换动作或换目标复用同一
   个键统一返回 `409 COMMON.IDEMPOTENCY_KEY_CONFLICT`；
5. 扫错时必须走“更正袋码”，填写原因。系统释放旧标签占用、登记新标签并永久保留前后值。

V52 迁移把已经验收通过或已经分配使用的旧设备标记为 `LEGACY_GRANDFATHERED`（历史设备
豁免），不要求返厂。仍处于待验收、未分配状态的 `PLATFORM_CREATE`（平台历史录入）记录
显示为“待实体补扫”：扫描同一个实体袋码走“核验”并补齐厂家操作者和标签占用；扫描到
不同袋码则走“更正”并记录原因。两条路径都会把记录转换为 `FACTORY_MINIAPP`，旧平台行
本身不能触发验收。

已经通过验收、已经分配租户、已禁用或已报废的设备不能修改厂家初始袋。Web 手工创建设备
资产接口不再接收 `factoryBags`，避免在没有实体扫码的情况下伪造首次装袋。

### 3.3 对后续业务的影响

所有投口都有厂家实体扫码事实和匹配的活动标签占用（或属于明确的历史设备豁免）后，
`allFactoryBagsVerified=true`。设备仍须在线，并提交既有配置持久化、自检、照片、存储和
传感器等机器证据，自动验收才会变为 `PASSED`。缺少或未核验任一初始袋时，自动验收调度
不会开始；它不会阻止继续扫描剩余投口，但会阻止设备被当作可分配、可经营的合格资产。

厂家验收不等待“初始皮重”。新登记袋保持 `tare_status=PENDING`；只有设备验收通过并被
分配给租户、机构以后，V36 既有激活调度才会让设备测量真实空袋皮重。这样不会形成“先
验收才能分配、先分配才能测皮重、先测皮重才能验收”的循环依赖。

每次安装、补扫或更正都会递增资产的 `factory_bag_revision`（厂家袋记录代次），按投口号
重算 `factory_bag_set_sha256`（有序袋集合摘要），并取消尚未完成的旧验收挑战。新的 OneNet
挑战携带这两个值，香橙派在验收证据中原样回传；后端同时核对挑战快照和资产当前快照，
因此更正前采集、在更正后迟到的证据不能改变验收状态。证据代次严格小于资产当前代次时，
后端把它作为正常迟到消息登记 `BUSINESS_APPLIED / NO_ACTION_REQUIRED` 终态确认，不消费新
挑战、不写评价、不改变验收状态；相同代次摘要不符和未来代次仍按非法证据拒绝。

## 4. 按需反向 SSH

### 4.1 管理员只登记一次公钥

平台管理员在本机执行 `ssh-keygen -t ed25519`，只把 `.pub` 公钥登记到 Web。后端保存公钥、
SHA-256 指纹、所有者、状态和版本；不接受也不保存私钥。管理员撤销公钥后，使用该密钥的
进行中会话会被后端收敛为失败并释放端口。

每台设备在注册响应中得到相同维护 CA 的公钥和自身唯一 principal，设备 SSH 只接受同时：

- 由维护 CA 签发；
- 未过有效期；
- 包含该设备专属 principal；
- 对应管理员本地私钥

的用户证书。因此新增设备不需要再次写入管理员公钥，新增管理员也不需要逐台改设备。

### 4.2 开启流程

1. 平台管理员在设备详情选择自己的有效公钥、5～30 分钟时长并填写原因。
2. 后端先以全局 `operationUid` 原子绑定管理员、平台作用域、开启动作、设备和请求摘要；
   同一绑定并发重试等待首次事务后重放，换管理员、换动作或换设备复用同一键统一冲突。
3. 后端确认设备资产正常、OneNet 当前在线、同设备没有活动会话，然后以数据库行锁从
   `22011～22014` 分配一个空闲槽。
4. 后端先在同一个数据库事务中提交会话、端口保留、可靠 OneNet
   `OPEN_REMOTE_SUPPORT_TUNNEL` 命令和审计事实；提交成功后，才在服务器 `desired`
   目录原子发布只含设备隧道公钥、端口、会话和期限的租约。
5. 香橙派可靠保存命令到 SQLite，使用自己的隧道私钥、严格固定的跳板 Host Key 和
   `ExitOnForwardFailure` 发起反向 SSH，并上报 `CONNECTING/OPEN/FAILED/EXPIRED`。
6. 跳板 `ecobin-tunnel` 账号没有普通 `authorized_keys`。`AuthorizedKeysCommand` 只在
   当前 desired 租约与设备公钥、端口和期限完全匹配时临时授权；强制命令确认回环监听
   真实存在后才写入 `actual` 标记，并持续检查租约。
7. 后端只有在设备上报 `OPEN` 且服务器 actual 标记完全一致时，才用 CA 给本次管理员
   公钥签发短期用户证书，把会话置为 `OPEN`，向 Web 返回证书、严格 `known_hosts` 行和
   连接命令。

设备单方面说已连接、服务器单方面出现监听或 OneNet 只确认命令已受理，都不能让管理员
拿到证书。若进程在数据库提交后、发布 desired 前被强杀，协调任务会根据数据库中的会话
和设备身份快照重建 desired；若服务器上出现没有数据库会话的 desired，协调任务扫描固定
四个端口并撤销它。数据库因此是会话事实源，desired 只是可重建投影。

### 4.3 关闭、到期和失败

管理员关闭会话时，后端登记可靠关闭命令并在事务提交后撤销 desired 租约。服务器强制
命令在轮询到租约消失后删除 actual 标记并结束 SSH 进程，因此即使 OneNet 关闭命令延迟，
服务端监听也会先失效。香橙派收到关闭命令后结束本地进程并上报 `CLOSED`。
关闭动作使用同一套全局幂等绑定，但目标是本次会话；因此开启键不能复用于关闭，不同会话
也不能共用关闭键。业务前置检查或整个事务失败时，幂等认领随事务回滚，原意图可继续用原
键重试。

下列事实都会阻止继续维护；撤销 desired 后，只有 actual 已不存在才释放槽位：

- 到达会话期限或连接期限；
- 管理员公钥被撤销；
- 设备上报终态失败；
- desired、actual、设备名、端口、公钥指纹或会话编号不一致。

香橙派重启时，未过期的 SQLite desired 状态会重新发起连接；服务器重启时 `/run` 下的
actual 自动清空。已处于 `OPEN` 的会话如果只观察到 actual 暂时消失，后端进入
`RECONNECTING`（等待重连），保留同一端口、原期限、证书和 desired，不把正常重启误判为
失败；actual 再次与会话完全匹配后回到 `OPEN`，但不会延长到期时间。若 actual 存在却与
设备名、会话、端口、公钥指纹或期限冲突，则按服务端租约冲突失败关闭，并在旧入口真正
消失前继续占住槽位，避免旧监听和新设备重叠。四个槽只限制并发数，不把端口永久绑定给
某台设备。

### 4.4 SSH 信任和权限

- 跳板端口只监听 `127.0.0.1`，不向公网发布 `22011～22014`；管理员必须先以短期证书
  登录 `ecobin-jump` 再转发到对应回环端口。
- 管理员连接设备时必须使用后端返回的稳定 `HostKeyAlias` 和精确 `known_hosts` 行，禁止
  `StrictHostKeyChecking=no`。
- 设备维护账号信任 CA，而不是所有平台管理员的静态公钥。当前受控维护账号可通过
  `sudo` 排障，因此短期证书等同于会话期间的设备管理员权限；开启原因、请求人、密钥、
  时长、状态和关闭原因全部审计。
- 后端持有无口令 CA 私钥是首版自动签名能力的高价值秘密，只能通过只读运行时 secret
  挂载。生产部署使用 `root:10001 0440`：root 拥有文件，后端运行组只有读权限；签名器
  允许这一组合，但拒绝组写、组执行和任何其他用户权限。后续可把签名迁移到独立签名服务
  或 HSM，而不改变设备信任模型。

## 5. V52 数据事实

V52 将目标数据库推进到 52 条迁移、112 张领域表、76 条权限定义。新增 13 张表：

- 注册挑战、注册续作和设备维护身份；
- 平台管理员维护 SSH 公钥；
- 厂家操作员，以及厂家小程序绑定意图、绑定和会话；
- 防伪袋标签占用、厂家袋更正历史；
- 四个远程端口槽、远程维护会话和可信状态事件。

同时为设备资产增加注册来源、厂家袋代次和有序摘要，为厂家袋增加真实扫码来源/标签/操作
者，为验收证据增加袋快照，并为远程会话保存设备身份快照和 `lease_released_at`（服务端
入口确认释放时间）。可靠任务和边缘事件增加远程维护类型。四行端口槽是 V52 的系统种子，
不属于业务数据；空库验证时应排除。

应用账号仍采用列级最小权限。迁移只能由一次性 schema owner 执行，运行后端不能 DDL、
不能读取注册 `K1`，也不能读取管理员私钥或设备私钥。

## 6. 实现入口与验证边界

- 权威 HTTP：`contracts/http/openapi.yaml`
- 权威 OneNet：`contracts/onenet/` 及生成物
- 后端：identity 的厂家操作员小程序/维护公钥，device 的 enrollment/factory/remote，integration
  的 OneNet 设备供应
- 香橙派：`device_enrollment.py`、`enrollment_bootstrap.py`、`device_credentials.py`、
  `maintenance_ssh_setup.py`、`remote_support.py`
- 跳板：`tools/remote-support/`
- 数据库：`V52__device_enrollment_factory_support_and_remote_access.sql`

自动测试能证明加密黄金向量、断电幂等、状态转换、权限目录、契约和租约文件边界；它不能
替代真实 OneNet 创建设备、真实微信绑定、真实 OpenSSH/防火墙、断电重连和厂家实体袋码
验收。启用生产功能前必须按部署手册逐项做受控试点。
