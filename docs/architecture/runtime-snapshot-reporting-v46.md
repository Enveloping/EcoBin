# V46 设备运行快照降频与全局策略

> 状态：**已冻结，获准实施**
> 决策日期：2026-08-10
> 覆盖范围：平台全局设备配置、OneNet 运行快照、香橙派上报调度
> 不在范围：历史数据删除、归档、压缩和维护账号

## 1. 为什么修改

`DEVICE_RUNTIME_SNAPSHOT` 是设备当前配置、串口、传感器、摄像头和本地存储状态的
诊断快照，不是设备在线心跳。设备是否在线只由 OneNet 北向
`deviceOnline/deviceOffline` 事实决定。

原实现正常在线时每 5 分钟兜底上报一次，即使设备没有任何业务或状态变化，也会让
只追加的收件箱和设备事件持续增长。冻结目标是在保留启动、重连和状态变化可观察性的
前提下，从源头降低重复事实的产生速度。

## 2. 最终上报规则

1. 香橙派启动完成和 MQTT 重新连接成功时强制发送一份最新运行快照。
2. 运行状态发生实际变化时请求即时上报；同一设备最多每 5 秒发送一次，窗口内的连续
   变化合并为最后状态，并保留窗口末尾的一次发送。
3. 没有状态变化时，距离上一次成功发送满全局配置周期后兜底发送；初始值为 60 分钟。
4. 状态去重只比较业务状态字段，不包含 `eventUid`、采集时间或发送时间等每次必变字段。
5. 启动、重连和周期兜底不受状态去重抑制。失败的发送不推进下一次兜底时间；MQTT
   恢复后重新强制发送。
6. 全局周期只能由平台管理员修改，单位为整数分钟，最小 10 分钟；不存在单设备覆盖。
7. 历史 `edgeHeartbeatMissThreshold` 不参与在线、告警或业务资格判断；机器配置继续固定
   携带值 `3`，Web 不再展示或允许修改。

## 3. 配置发布与设备生命周期

- 平台发布新周期后，后端自动为已永久分配机构、验收通过且生命周期为 `NORMAL` 的
  设备生成更高的完整配置版本，并复用 `ENSURE_DEVICE_CONFIGURATION` 可靠任务下发。
- 离线的正常设备保留待下发任务，OneNet 再次报告在线后自动继续，不需要机构操作。
- 禁用设备在禁用期间不接收新配置；恢复时先自动补发当前全局策略。报废设备永不恢复、
  永不补发。
- 尚未分配机构或尚未通过验收的设备不提前生成机构配置；以后首次满足自动配置条件时
  直接使用当时最新的全局策略。
- 平台下发批次完成只表示设备配置和可靠任务已经建立，不冒充香橙派已经应用；每台设备
  仍以原有 `configurationProgress: APPLIED` 事实收敛。

## 4. 数据保存边界

后端继续按现有规则把收到的可信运行快照写入只追加收件事实和设备事件，并原地更新当前
运行投影。本次不增加定时删除、归档表、维护身份或应用账号删除权限。默认周期从 5 分钟
变为 60 分钟后，完全空闲设备的兜底快照由每天 288 份降为 24 份，约减少 91.7%；状态
变化、启动和重连产生的快照另计。

## 5. 契约边界

- OneNet `applyConfiguration` 的字段结构和取值范围不变，继续使用
  `edgeHeartbeatIntervalMs` 与固定的 `edgeHeartbeatMissThreshold=3`，因此无需重新导入
  OneNet 物模型。
- Web 配置输入不再接收这两个字段；配置响应可以只读返回实际周期和全局策略版本。
- MCU 不消费运行快照周期，本次不修改香橙派—MCU 协议，也不增加 MCU 或摄像头轮询。
