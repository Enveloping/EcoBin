## 1. 单片机重启后不根据过程记录重建正常结果

当香橙派已经取得可信证据，确认单片机重启，且尚未可靠保存该投递的最终结果包时：

- 保留全部已有的首末重量、结束按钮、动作、原启动/业务身份及其他过程证据。
- 只建立并可靠上报问题记录，不用这些过程记录重建正常投递结果。
- 原因准确表示为“单片机重启，未取得最终结果包”。存在重量记录时，不能写成“重量全部丢失”。
- 不据此生成正常结算订单、增加余额或触发自动提现。
- 过程记录可以证明已记录的动作/测量事实，但没有记录的物理投物、重量或结果不能补造。

例：首重、末重、结束按钮都已保存，但完整最终包尚未交接就发生 MCU 重启；这些数据随问题
保留供客服排查，不计算并提交一笔可正常结算的投递订单。

## 2. 归档后收到完整结果只追加证据

问题归档后若又收到完整最终结果，先校验原设备、原投递/命令、原 MCU 启动身份与结果完整性。
确实属于原业务时，将完整结果关联到原问题记录并追加保存；身份错误或完整性冲突不能关联为可信结果。

- 保留原问题归档结论，不自动改成正常订单或恢复结算。
- 不增加余额、不触发自动提现。
- 不让旧结果改写当前袋、当前皮重或后续业务状态。
- 相同结果重复到达只保留同一份证据；不同结果冲突保留冲突事实，不覆盖第一份原文。

例：投递 A 已按重启缺包归档，设备恢复后又完成清运并换成袋 B。随后收到 A 的滞留结果时，
只关联 A 的问题，不把设备当前袋和基准退回 A 当时的状态，也不补发返现。

## 3. 保持不变的前置边界

1. 在问题归档提交前，若完整最终结果已可靠保存在香橙派，优先处理完整结果，不能误判丢失。
   结果保存与归档裁定必须串行或在同一受控事务中核对，不能同时产生两个可生效终态。
2. 仅通信超时、没有回复或查询暂时查不到，不构成单片机重启证据，不能据此归档。
3. 仅香橙派重启仍继续核对原业务，不因此改成问题记录或重放原机械动作。
4. 问题归档不代表设备永久停用。后续按既定受控关门、检查和准入条件恢复接单；
   归档本身不冒充关门完成或解除永久动作账本。
5. 只确认投递结果取舍，不改变清运换袋恢复，也不改变非重启最终称重失败的既有处理规则。
6. 不复用要求人工现场确认的旧手动隔离接口伪装自动处理，不擅自放宽其授权或打开远程更新。

## 4. 原计划中的落地与验证

- P4：基于已保存的原业务、正向重启证明和全部过程证据，原子冻结问题型终态；
  原完整结果优先，归档后完整结果走独立追加证据路径。永久动作处理和恢复关门仍使用独立许可与账本。
- P5：问题/追加证据使用明确的问题型接收路径和原业务关联，不进入正常订单、钱包、提现、
  当前袋或皮重投影。设备/后端均按稳定身份去重，失败回滚不形成半份结果。
- 必测：完整过程但缺最终包、完全缺重量、通信超时、仅 Pi 重启、先保存完整包再归档、
  结果/归档并发、归档后重复/冲突/错误身份结果、换袋后迟到、任一持久提交边界退出后恢复。
- 同步机器契约、原始证据保管、后端事务和问题展示；不把分类函数或本地测试单独当作全链路实现完成。

可信重启证明、归档事务提交点、稳定身份、冲突校验及恢复准入的实现细节必须在对应代码、
机器契约和测试中落定；本决定记录本身不替代完整实施规格或发布验收。
