# V42｜设备入口 URL 下发到香橙派和 MCU

> 生效日期：2026-08-08
>
> 2026-08-13 补充：固定帧模式在空闲时按默认 60 秒周期重发本地最新 URL，给 MCU
> 单独重启和未来动态二维码刷新提供恢复入口。
>
> 状态：**已由项目负责人确认并冻结；补充 V41 的设备侧交付方式及定时刷新规则**
>
> 数据库版本：V42

## 1. 最终决定

平台仍只保存 V41 的一个全局小程序基础跳转地址，每台设备的完整 URL 仍由该地址追加
永久设备公开码形成。V42 不恢复租户、机构或渠道级入口配置，也不新增人工二维码开关。

后端只在以下两个业务时机把完整 URL 下发给香橙派：

1. 平台为尚未通过验收的永久设备发起自动机器验收；
2. 服务器配置的全局基础跳转地址发生改变。

可靠任务因设备离线而继续同一次下发，不算新的业务触发。租户分配、机构分配、安装、
禁用或普通后端重启均不单独下发 URL。

## 2. 验收与显示边界

香橙派必须先校验并把完整 URL 及其 SHA-256 摘要可靠保存到本地 SQLite，然后才能在
机器验收证据中声明 `deviceEntryUrlStored=true`。后端把证据摘要与当前全局地址和设备
公开码计算出的期望摘要比较；缺失或不一致都不能通过本次验收。

原有 OneNet 在线、SQLite、可信时间、MCU/传感器和摄像头等机器验收条件继续保留。
二维码这一项只验证香橙派已经保存正确 URL，不验证 MCU 是否收到、屏幕是否显示或
二维码是否可扫描。模拟来源仍只作诊断。

验收发生在租户和机构分配之前。MCU 可以立即显示二维码；此时扫码由后端根据设备尚未
分配机构或渠道未就绪返回不可用。机构完成永久分配后，同一个二维码自动生效，不需要
再次下发或人工操作。

## 3. MCU 固定帧边界

香橙派使用 `A0 LEN URL_DATA[192] A0` 固定 195 字节报文发送完整 ASCII HTTPS URL。
协议没有 ACK/NACK、CRC 或二维码状态应答。完整字段、校验和异常处理以
[`../../hardware/docs/单片机-香橙派适配通信协议详细内容.md`](../../hardware/docs/单片机-香橙派适配通信协议详细内容.md)
为准。

香橙派在保存新 URL 后立即发送一次，并在自身启动或串口重新打开后从 SQLite 读取并
立即再发送。除此之外，`fixed-frame` 模式在 MCU 空闲且串口打开时，默认每 60 秒重新
读取一次本地最新 URL 并发送一帧。周期由
`ECOBIN_DEVICE_ENTRY_URL_REFRESH_SECONDS` 配置且必须为有限正数；`uart-v1` 不执行
这项固定帧兼容逻辑。

定时发送复用现有命令消费者线程，不另起串口写线程。投递或清运占用工作槽时不发送
`A0`，以免覆盖 MCU 当前业务屏幕；每 5 秒复查一次，工作结束后恢复。串口关闭或本地
写入失败时也在 5 秒后重试。MCU 当前只把 URL 保存在内存，因此 MCU 单独重启后通常会
在下一次空闲周期重新取得 URL；但协议没有应答，香橙派仍不能据此证明 MCU 已收到、
生成或显示二维码。

## 4. 全局地址改变与存量设备

全局地址仍是服务器环境配置，不增加平台修改页面。后端用数据库中的发布游标记录当前
配置摘要；只有摘要改变时才为所有未报废设备建立幂等可靠下发任务，配置相同的普通重启
不会重复建立任务。

V42 首次上线视为一次全局地址发布。已通过机器验收的存量设备保持 `PASSED`，不因新增
URL 证据被重置；它们通过本次全量任务收到 URL。以后新验收证据只接受 V42 版本，不
保留旧证据协议的运行时双读或双写分支，历史证据记录仍按审计要求保留。

## 5. 安全与长度

完整 URL 只包含公开入口和永久设备公开码，不包含租户 ID、机构 ID、AppID、AppSecret、
OneNet 密钥、设备密钥或部署码。应用启动时必须确保最坏情况下生成的完整 URL 是 ASCII
且不超过 192 字节；配置不满足该条件时阻止后端启动。

当前 URL 是长期公开静态入口。每 60 秒重复发送同一个 URL 只负责刷新 MCU 内存和屏幕，
不能阻止别人拍照后远距离扫码，也不提供防重放能力。

未来改为动态二维码时，可以保留同一 `A0` 帧，但不能只附加一个由设备自行填写的裸
时间戳。至少需要让后端校验不可伪造的短期签名，签名内容应绑定永久设备公开号、签发
时间、过期时间和随机挑战；是否一次性消费由后续业务规则决定。刷新周期必须短于令牌
有效期并预留时钟和网络误差，完整 ASCII URL 仍不得超过 192 字节。短期签名只能限制
旧截图重放；如果还要抵抗实时转发，后续必须再绑定现场按钮、当前设备会话或其他近场
挑战事实。
