# 物理结果未知投递的远程异常隔离收口

> 日期：2026-09-10
>
> 状态（2026-09-11 更新）：OneNet、V69、后端/Web 已部署；v37 设备侧代码已安装并核对一致，
> 经用户确认，当前新卡已保留数据切换并启用永久账本，更新器重启后保持、后台兼容接入正常。
> 异常收口真机验收尚未执行；本次新 F3 为 `0x0B`，不满足收口所需 `0x0F`。
> 现场事实及仅账本启动修正见[部署记录](../operations/delivery-quarantine-deployment-2026-09-11.md)。
>
> 当前范围：固定帧 MCU 的投递异常；不包含清运，不修改串口屏 HMI，也不要求重新烧录 MCU

## 1. 要解决的问题

一次投递的开门命令可能已经发给 MCU，但断电、重启或固定帧协议缺少作业编号，使设备再也
无法证明旧动作究竟完成到哪一步。原系统必须保守地保留投递会话和整机占用，因此后台一直
显示“设备被占用”。直接伪造一次 `DELIVERY_COMPLETE`（投递完成）虽然能释放占用，却会进入
正常业务链，可能创建订单、增加用户余额并触发自动提现；这不符合“结果其实未知”的事实。

本设计增加独立的“异常隔离收口”：平台管理员在故障原因已经排除、设备完成一次整机断电
重启、现场重新确认安全后发起。设备取消并封存原作业，只上报尚能找到的重量、照片和安全
证据。这些数据只有问题展示价值，业务价值固定为 `NONE`（无），不能进入订单或资金链。

这不是把旧投递判为“成功”或“失败”，而是明确记录：

- 旧动作的真实物理结果不可知；
- 原作业不会在本次重启后再次执行；
- 现场已经恢复到允许解除软件占用的安全状态；
- 已有数据仅作为查错证据保存。

## 2. 谁在什么条件下发起

只有平台管理员能在设备管理页发起。按钮只在后台已经确认以下业务事实时出现：

1. 原投递处于 `RESULT_PENDING_RECOVERY`，即“结果待异常处理”；
2. 原开始授权已经过期，系统不会再把它当作有效的新开门许可；
3. 原会话、原开始命令、原可靠任务和当前整机占用精确对应；
4. 后端没有收到该投递的可信物理结果，也没有创建投递订单；
5. 原可靠任务已经结束下发阶段或因等待设备证据超时而阻断；
6. 设备已重新上线并且仍属于原租户和机构。

管理员还必须逐项确认六个现场事实，任一项不能确认都不得发起：

1. 接受“旧动作结果未知”，不把本次操作当作正常投递完成；
2. 导致异常的原因已经处理；
3. 设备已经完整断电并重新通电；
4. 机构运动范围内无人；
5. 投递门已经完全关闭；
6. 机构内没有卡住的物品。

操作原因必须填写。后台把六项确认、原因、原会话版本和原任务身份冻结在一条新的 V69
记录里，不能用一次点击去处理另一条会话。

## 3. 设备如何证明可以收口

后端下发独立命令 `QUARANTINE_DELIVERY_RECOVERY`，中文含义是“隔离结束一笔结果未知的
旧投递”。命令有效期最多五分钟，且不携带 COS 临时凭据。香橙派收到后先做只读检查，检查
不会开门、关门或重新执行旧投递：

- 当前确实只有命令指定的原投递恢复槽；
- 原永久物理动作账本恰好有一条 `ARMED`（已武装但无可信终态）的开始动作；
- 该动作属于 `TWO_PHASE_V3` 两阶段防重协议，工作编号、命令编号、许可编号和动作摘要完全匹配；
- 当前启动身份与异常发生前不同，证明设备经历过一次新的启动；
- 新读取的 F3 状态帧为固定帧模式 1，`safeFlags=0x0F`，证明投递/称重与清运均空闲、方向命令已清零且驱动输出关闭、电磁阀输出关闭；这些位不代替物理门位传感器；
- 新读取的 F1 自检帧同时证明重量和红外有效、烟感通信正常；
- 检查期间如果收到原投递可信的正常 DD 完成帧，正常结果优先，本次隔离命令停止，不能覆盖真实完成事实。

检查通过后，永久更新器在只追加扩展表中写入
`UNKNOWN_EFFECT_QUARANTINED`（物理影响未知、已隔离）结论。原动作账本仍保持原始 `ARMED`
状态，不伪造成执行成功或执行失败；相应永久作业只允许结束为 `CANCELLED`。只有永久层取消
已经提交后，业务程序才释放本地恢复槽。

## 4. 上报什么，明确不触发什么

设备上报独立事件 `DELIVERY_RECOVERY_QUARANTINED`，中文含义是“投递恢复已隔离留档”。事件
包含：

- 原会话、原开始命令和本次恢复命令身份；
- 六项管理员现场确认和文字原因；
- 重启前后启动身份；
- 新 F3/F1 原始九字节帧及其解析结果；
- 原永久动作账本身份、摘要和未知影响隔离证据摘要；
- 本地已经存在的首次开门前测量、最终关门后测量和四个照片槽状态；不存在的字段保持空，
  不用 0 或当前测量补造。

事件的 `businessValue` 固定为 `NONE`。后端可信事务只做四件事：

1. 把精确的原投递会话结束为 `DEVICE_ABORTED / REMOTE_RECOVERY_QUARANTINED`；
2. 删除只属于该会话的整机占用；
3. 把管理员确认、设备安全证据和已有数据归档到问题记录；
4. 用该可信事件结束本次异常收口可靠任务。

该事务明确不会：

- 写入 `rec_delivery_order`，因此没有投递订单；
- 写入或调整钱包流水、用户余额、机构结算；
- 创建待审核返现；
- 触发自动审核、自动提现、退款或补款；
- 更新满溢结论、空袋皮重或正常投递完成投影；
- 发送 `DELIVERY_COMPLETE` 或把未知结果伪装成正常完成。

因此，页面能够查看重量、照片和原始帧，但它们只是问题证据，不具有可兑换或可结算的业务
价值。解除占用后，是否允许下一位用户开始业务仍由设备在线、安全、满溢、兼容性及其他当前
准入事实共同决定。

## 5. 并发、迟到结果和失败处理

- 同一原投递同时最多存在一条 `QUEUED`（等待设备确认）的异常收口记录；重复点击不能产生
  两条设备命令。
- 设备使用恢复编号、会话编号、原命令编号、永久动作摘要和证据摘要做幂等；相同命令重放
  不会再次修改永久账本或再次释放槽位。
- 后端用恢复编号、终态事件编号、消息编号和载荷摘要做幂等；相同事件重投不会重复修改会话。
- 在设备提交隔离结论以前出现原 DD 正常结果时，正常结果优先，隔离停止。
- 后端已经提交 `DEVICE_ABORTED` 以后才到达的旧 `DELIVERY_COMPLETE` 不再有可接受的原会话
  状态，必须拒绝或进入技术隔离，不能补建订单。
- 任一身份、摘要、重启、安全帧、永久账本或现场确认不匹配时都失败关闭：原会话和占用继续
  保留，不把“检查失败”解释为现场安全。
- 异常收口命令只有五分钟现场确认窗口。OneNet 未受理时可靠任务可在该窗口内重试；OneNet
  已受理但设备终态事件未到达时，任务最终会阻断并保留占用。当前首版不自动刷新确认时间、
  不自动新建第二条命令，也不允许工作人员盲目重放。应先查看可靠任务和设备本地证据，再按
  新一轮完整断电与现场确认设计后续恢复，不能直接改库清除。

## 6. 部署和现场使用顺序

最初实现时设备已由项目负责人断电，当时没有向断电设备发送命令或修改设备 SQLite。
以下是部署顺序；其中 1～3 已于 2026-09-11 完成，v37 也已携带第 4 项代码，但只读核验发现
永久动作账本未启用。用户随后授权，已完成保留数据的运行链切换、带证据激活和实际运行核验；
本轮没有执行异常收口。旧直连时期未曾记录的动作不能在启用后补造为可隔离的历史账本。

1. 把仓库生成的 18 服务 / 22 事件 OneNet 物模型导入测试产品，确认新增服务和事件存在；
2. 停止旧后端写入，把数据库从 V68 前向迁移到 V69，并按“目录版本 36”的最小权限清单重新收敛运行账号；
3. 部署理解 V69、新事件和新接口的后端与 Web；
4. 香橙派必须同时部署本次业务程序和永久更新器修改。普通远程业务包不包含
   `updater_agent.py`、`updater_store.py`，不能单独完成本功能升级；现有一次性永久管理层
   安装器也不提供已安装更新器的原位升级。本次以新镜像提供完整软件。新镜像不携带旧卡
   身份、未决作业或动作账本；若要处理当前旧投递，必须先保留旧卡及其完整数据，另行完成
   保留身份和账本的受控升级，不能覆盖后把“本地记录消失”当成异常收口成功；
5. 给设备通电，等待 OneNet 明确在线；
6. 现场再次核对门已关、机构无卡物、运动范围无人和故障原因已修复；
7. 在设备管理页勾选六项确认并填写原因；
8. 等待页面显示“已隔离并留档”，再确认原整机占用消失且没有产生订单或资金记录。

本功能只使用当前 MCU 已提供的 F1/F3 查询能力和永久层账本，不增加串口屏按钮或页面事件，
因此无需修改 HMI。若设备当前烧录的 MCU 固件已经包含已验收的 F1/F3 状态查询，也无需为本
功能再次烧录 MCU；香橙派业务程序及永久更新器、OneNet、数据库、后端和 Web 仍必须部署。清运异常具有换
袋、清运联锁和新袋皮重等不同业务事实，本次没有用投递收口逻辑代替清运恢复。

## 7. 验收要点

自动化至少覆盖：

- 六项确认任一为假、设备未重启、F3 非 `0x0F`、F1 不健康、身份或摘要不符时拒绝；
- 永久动作原账本保持 `ARMED`，只追加未知影响解决记录，永久作业为 `CANCELLED`；
- 正常 DD 与隔离并发时正常结果优先；
- 设备事件只携带已有重量/照片，不产生正常完成事件；
- 后端只结束原会话和精确占用，证据可查看；
- 数据库中没有新增订单、钱包流水、审核、退款或提现记录；
- 重复命令和重复事件幂等，错误会话、错误命令或错误设备不能串单；
- V69 目标库为 132 张领域表、69 条成功迁移，运行账号只有新表所需的精确更新列权限。

真机验收还必须记录新的启动身份、F3/F1 原始帧、永久账本解决摘要、后端问题记录，以及收口
前后订单和资金表的零变化。自动化通过不能代替本轮断电设备的真实验收。
