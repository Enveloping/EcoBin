# V49｜最近登录机构账号选择

> 生效日期：2026-08-14
>
> 状态：**已由项目负责人确认并冻结；D-049 / I-059**
>
> 数据库版本：V49

## 1. 修改原因

V39 允许同一微信身份拥有多个相互隔离的机构账号，但无设备码登录仍按注册时间选择。
用户手工切换到较早注册的机构后，下次需要重新登录时会回到较晚注册的机构，与用户最近
选择不一致。

V49 只替换默认账号选择依据，不改变共享小程序、设备扫码注册、永久机构归属、钱包隔离
或单机构会话边界。

## 2. 冻结规则

- 小程序本地仍有可验证且未过期的会话时继续使用当前机构，不因 `onShow` 重新选择。
- 需要签发新会话且没有设备公开码时，在当前 AppID/OpenID 对应微信主体的可用机构账号中，
  按 `last_login_at DESC, id DESC` 选择第一条。
- 设备扫码是明确的机构选择，继续高于最近登录规则；有效扫码选择或创建目标机构账号。
- 冻结账号、禁用租户或机构、失效渠道绑定不参与自动选择；最近账号不可用时选择下一条。
- 最近登录是同一小程序渠道和微信身份的服务端全局事实，不按手机分别保存。

## 3. 最近登录事实

`iam_organization_user.last_login_at` 保存该机构账号最近一次成功签发小程序会话的服务端
UTC 时间。普通、清运、扫码和管理会话都计入；会话查询、退出、失败事务和幂等重放不计入。

首次创建账号时该值等于不可变的 `registered_at`。以后只允许单调推进，不修改注册时间、
注册设备归因、授权版本或配置锁版本。会话表继续保存逐次历史，`last_login_at` 只是稳定的
当前选择投影，不替代会话审计。

V49 使用现存普通会话和经工作人员绑定关联的管理会话回填历史最大值；没有历史会话时
回退到注册时间。V39 及更早迁移保持原样，不修改已执行迁移的校验和。

## 4. 接口与客户端

HTTP 请求和响应结构不变，不向客户端公开 `lastLoginAt`。账号列表按最近登录排序，但仍
展示既有注册时间。客户端有效会话仍优先复用；会话缺失、过期或被清除后才调用登录接口
触发服务端选择。

因此本变更不要求新增小程序存储键、设备标识或单独的小程序发布。

## 5. 验收

- 先注册 A、后注册 B，手工切换到 A 后，无扫码重新登录仍进入 A；
- 再扫描 B 后，无扫码重新登录进入 B；
- 最近账号不可用时回退到次近可用账号；
- 幂等重放、登录失败和当前会话查询不改变排序；
- 不同机构的钱包、手机号、订单和提现仍完全隔离。
