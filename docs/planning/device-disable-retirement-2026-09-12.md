# 设备禁用、报废与任务收口

状态：已提交并部署；2026-09-13 01:01:44 最终发布 `20260912165854-db67124ba87e` 生效，数据库 V72、134 张业务表、授权清单 38；[部署与回退记录](../operations/device-lifecycle-deployment-2026-09-13.md)。

## 最新修订：禁用暂停配置与更新

以下为最新实施规则；首轮验证结果保留在文末，报废规则不变。

1. 禁用仍先检查投递、清运、远程维护和已经发出的升级。通过后保留配置应用、控制板升级、业务程序升级待办；停止下发和重试，不删除记录，不因暂停而消耗重试次数；禁用前已经发出的请求仍按实际结果记录。验收、测量、检测等现场任务仍按首轮规则结束，启用后按当前现场条件重新安排。
2. 启用后解除暂停；若设备仍离线，继续等待上线。没有更新配置时继续原有效配置任务；禁用期间统一配置策略发生变化时先生成最新版本、替代旧待办。已经失败、取消或结束的任务不因启用而重开。
3. 禁用期间不把待确认配置判成超时；启用后重新给予原有的两分钟确认窗口。迟到的真实应用结果仍可入库并正常结束任务，不重复执行已经确认完成的配置。
4. 已经排队的升级保留原部署记录与目标版本。发送授权过期且能证明从未发出时，用新指令及新发送记录继续原部署，旧发送记录留存；不修改旧快照，不重放可能已执行的更新，也不替管理员启动尚未批准下发的计划。
5. 报废仍永久取消全部相关待办；已发出的升级仍须先安全结束。历史记录与默认列表规则不变。

验收重点：禁用不取消配置/更新、不发送、不超时；恢复保留目标和任务历史，过期授权安全更新；最新配置替代旧配置；报废仍取消；设备详情及禁用、启用确认用就近状态说明暂停，正常设备不常驻显示解释。

## 已确认的业务规则

1. 平台管理员发起禁用或报废时，先检查设备是否仍有投递、清运或远程维护。包括等待结果、异常恢复以及尚未关闭的维护连接；存在这些业务时拒绝操作，设备状态和已有任务均不改变。
2. 检查通过后，在同一事务内变更设备状态：禁用保留并暂停配置和更新待办，结束验收、测量和检测；报废取消相关待办，停止后续调度和重试。已经开始执行且不能安全中断的升级，必须先结束或通过现有安全取消流程收口，不能仅修改数据库就声称硬件已停止。
3. 历史订单、清运记录、配置版本、命令和审计记录保留，原有租户、机构权限边界不变。不得借禁用或报废强制结束真实投递、清运、维护，或删除历史及已装袋关系。
4. 设备列表默认隐藏已报废设备；可通过状态筛选查看已报废或全部设备。已禁用设备仍默认显示，便于恢复。
5. 恢复禁用设备时依据当前事实重新计算使用资格，同步当前配置，不复活之前已取消的任务。已报废设备不能恢复。

本规则替代 `docs/architecture/permanent-device-ownership-v36.md` 中关于禁用、报废只阻止新业务，以及租户、机构不能访问非正常设备历史详情的旧规则。

## 实施范围

- 设备控制入口：先锁定资产并检查占用和相关未结束业务；失败给出具体原因，成功原子暂停或取消相应任务并记录审计。
- 可靠任务：登记、领取、外部调用前及唤醒重试各处检查设备状态；已取消的任务不可因迟到结果重新启动。已经越过外部调用边界的操作按实际结果处理，不能假定可撤回。
- 配置、验收、检测、升级：保留历史事实，禁用暂停配置及更新、取消其他现场任务，报废取消所有相关待办；对已经执行的升级沿用安全取消边界，避免清空真实执行状态。
- 读取权限与页面：分离历史读取权限和新操作资格；后端默认排除报废，前端提供全部与报废筛选，危险操作确认文案说明忙碌阻断和任务取消，不添加常驻说明段落。
- 并发：创建业务、设备控制与任务发出按一致资产锁顺序复核，避免检查通过后又创建新业务或再次派发。

## 实现与验证记录

### 实现

- `DeviceLifecycleControlService` 在持有设备资产锁的同一事务内检查、变更状态和暂停或取消任务。投递结果待恢复、清运未结束、维护连接或服务器端口租约未释放，均返回具体阻断原因，不产生部分取消。
- 设备模块通过事务内、单次消费的资产引用调用回收模块；回收模块自行检查清运记录、结束待完成的空袋测量和满溢检测，并解除对应检测占用。保留已装袋、已经完成的测量以及原有归属。
- 可靠任务登记、领取和外部调用前复核设备状态；任务取消后，普通唤醒、授权重发、迟到结果均不能将其恢复为待调度。历史事件确认和历史照片上传授权仍可处理，以完成已有事实的接收。
- 禁用时保留配置应用和升级部署状态，待调度任务记录 `DEVICE_DISABLED`（等待设备启用），待设备确认的配置继续保留原等待类型并暂停超时。仅报废时将未完成配置标记为 `CANCELLED`（已取消），尚未发出的升级标记为 `LOCAL_CANCELLED`（下发已取消），保留原部署记录。升级或出厂封存授权只要存在“可能已发出”的记录，就拒绝设备控制，等待真实结果或既有安全取消流程完成。
- 恢复时重新核对当前配置策略；未变化时继续原有效任务，发生变化时先以当前配置替代旧待办，不复活取消记录。待确认配置重新获得两分钟确认窗口；未发出的升级如授权已过期，在恢复及发送前以原目标、原有效载荷生成新指令及新任务，原不可变快照保留，并更新部署引用。平台也不能为禁用或报废设备手动重新核对验收结果。
- 已取消的升级记录不再预占新升级计划的设备名额。业务程序升级取消后，用最新真实软件事实重新计算投递、清运准入，解除旧升级的临时暂停；不会凭空声明设备健康或伪造设备上报。
- 平台、租户、机构列表默认排除报废，支持显式查看报废或全部；禁用设备继续显示。原权限范围内可查看历史详情和配置版本，修改入口另行检查设备是否正常。前端在操作确认和阻断处提示后果，禁用设备的详情就近显示暂停待办说明。
