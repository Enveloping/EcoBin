# H-03｜固定帧 MCU 线路与真机基础验收

> `status: in-progress`：F-11 已于 2026-07-28 按已接受的软件范围转为 `done`；项目
> 负责人于 2026-08-29 明确确认指定单卡 v8 写入并恢复本轮 HIL。真实 MCU、称重、屏幕和
> 物理机构证据仍必须由现场人员参与取得，单卡授权不扩展为其他介质或正式量产放行。

## 目标

在不要求修改现有单片机固件架构的前提下，验证协商后的 `115200 / 8N1` 固定帧协议、
MCU 屏幕状态机、称重、投递门机构和清运电磁阀在真实香橙派与设备上的行为；明确协议无法
表达的恢复和安全事实，禁止适配层伪造。

## 两类验证结论

本任务关联但不混用以下两类结论；下列英文名称只用于文档和证据分类，不是设备运行时
状态码：

1. **接入流程正确性验证（`FLOW_VALIDATION`）**：验证 P7 本地验收、Air780E 联网、可信
   校时、HTTPS 注册、OneNet 正式运行、P8 云端授权和单向封存能否按状态事实自动推进。MCU 可以是真实固件，
   也可以是按相同固定帧协议返回相同语义数据的模拟固件；数据进入香橙派后，下游状态机、
   后端处理和封存路径完全相同，来源标记只进入证据元数据，不改变通过判定。该结论已经可以
   独立取得，不等待真实硬件资格。
2. **真实硬件资格/HIL（`PHYSICAL_HIL`）**：验证真实 MCU、UART 电气线路、称重精度、屏幕、
   传感器和执行机构在现场的物理行为、时序与故障恢复。只有评价这些物理能力或正式量产
   放行时，才要求真实硬件证据。

状态汇报必须直接说明当前流程到达的阶段和阻断事实。未进入第 2 类验收时，不在每个流程
节点后重复附加“模拟不能证明真实硬件”的保留说明；模拟来源只在证据清单和进入真实硬件
资格评审时说明一次。

## 要执行什么

- 核对并抓取 `BB PRICE BB`、`AA 01 AA`、`EE 01 EE`、`DD PRE POST FULL DD` 和
  `EF PRE POST FULL EF` 的真实原始字节。
- 验证半帧、粘包、前导噪声和载荷内出现帧标志时，香橙派仍按固定长度正确解析。
- 验证一次投递只发送一次开始命令；MCU 保留整场首次重量，用户继续投递不上报，结束时
  只发送一次 DD。
- 验证一次清运只发送一次开始命令；电磁阀在 3～5 秒后自动断电，工作人员换袋、关门并
  在屏幕确认后才发送一次 EF。
- 对照真实秤值验证 uint24 大端克数、`FULL=00/01` 和香橙派生成的规范测量/业务事件。
- 执行香橙派重启、单片机重启、迟到 DD/EF、无活动工作时收到结果、重复结果和串口断开
  场景，确认不会自动重放物理命令或把未知事实冒充为成功；同类型迟到 `DD/EF` 无法
  在线路层区分的残余错绑风险按项目负责人已接受的范围记录，不伪造“绝不会错绑”证据。
- 记录单投口、无 ACK/CRC/流程编号/状态查询/故障枚举等已知限制，并确认试点启用范围。
