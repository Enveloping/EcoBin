# EcoBin P0 目标接口设计：全局契约（I-001～I-005）

> 总索引：[interface-design-draft.md](../interface-design-draft.md)
>
> 状态：**I-001～I-005 已确认**
>
> 说明：本文件定义所有自有 HTTP、外部协议和模块公开端口必须遵守的横切语义；具体业务 URL、DTO、状态和错误码在后续专题中继续设计。

## I-001 接口分区、版本与命名

**已确认：目标 HTTP 接口进入新的 `/api/v1` 契约纪元，按受信主体拆分入口；旧接口只能作为过渡适配器，不能继续决定目标 DTO、权限和状态模型。**

1. 自有 HTTP API 使用以下入口根：
   - `/api/v1/web/**`：Web 管理端；平台特权操作在其下使用显式 `/platform/**`；
   - `/api/v1/miniapp/**`：普通用户和清运员；
   - `/api/v1/miniapp-staff/**`：工作人员小程序管理端。
2. 微信通知使用精确独立路径，不开放匿名通配目录。生产不保留匿名 `/api/iot/**`；测试或维护直连必须使用独立配置和设备认证。
3. OneNet 消息 Schema、微信 APIv3、UART 和 Java 模块 `.api` 端口各自拥有独立版本，不因 HTTP 使用 `/v1` 而共享版本号。
4. 集合资源使用复数 `kebab-case`，JSON 属性使用 `lowerCamelCase`。
5. 查询使用 `GET`，创建资源使用 `POST`。审核、纠错、取消、恢复、配置发布等业务状态转换使用语义明确的命令或决定子资源，不开放能任意覆盖业务状态的通用 `PUT/DELETE`。
6. `/api/v1` 内只允许向后兼容地增加可选响应字段、可选请求能力或新资源；删除字段、改变字段含义、收紧已有合法输入等破坏性变化必须进入新主版本并制定迁移窗口。
7. 当前 `/api/system/**`、`/api/business/**`、`/api/app/**` 和 `/api/iot/**` 不属于目标命名空间。切换期如确需保留，只能把旧 DTO 转换后调用新应用用例，禁止新模块重新依赖旧 Controller、Entity 或状态枚举。

## I-002 响应、错误与公共数据格式

**已确认：自有 HTTP API 使用统一 JSON 信封、真实 HTTP 状态、稳定字符串错误码和无损公共数据格式；微信、OneNet 等外部协议继续遵守对方应答规范。**

普通成功响应：

```json
{
  "code": "OK",
  "data": {},
  "requestId": "01..."
}
```

普通错误响应：

```json
{
  "code": "DEVICE.DEVICE_BUSY",
  "message": "设备正在使用中",
  "requestId": "01...",
  "retryable": false,
  "details": {}
}
```

1. `code` 是供客户端分支判断的稳定英文错误码；`message` 只供人阅读，客户端不得匹配中文文案决定行为。`details` 仅在安全且有必要时返回字段错误、当前状态或重试提示，不能包含异常栈、SQL、密钥、渠道原文或其他主体的身份信息。
2. HTTP 状态使用统一边界：
   - `400`：JSON、类型、字段格式或字段间基本校验失败；
   - `401`：未认证、会话失效或令牌受众错误；
   - `403`：主体已认证且资源可见，但缺少动作能力；
   - `404`：资源不存在或不在当前可见作用域；
   - `409`：状态、版本、当前占位或幂等摘要冲突；
   - `422`：请求格式正确，但当前业务资格或规则不允许执行；
   - `429`：超过入口限速；
   - `500`：未预期的内部错误；
   - `503`：临时依赖不可用或安全的内部重试已经耗尽。
3. `201` 表示本地资源已经创建；`202` 表示操作已经可靠受理但目标动作尚未完成；`204` 不返回响应体。禁止继续使用“HTTP 200 + 数字业务失败码”。
4. 有界目录和确需总数的普通管理列表使用 `data.items`、`data.page`、`data.pageSize`、`data.total`，页码从 1 开始，默认每页 20，最高 200。订单、资金流水、设备事件、审计等按时间持续追加的列表默认使用稳定的“业务时间 + ID”游标或同序方式，具体游标字段在对应专题确认；不得把无索引大偏移作为主要方案。
5. 跨端业务 ID、UUID、业务单号和公开码使用 JSON 字符串，不暴露或复用数据库 `BIGINT` 主键。因此，后续端点若需要让客户端寻址当前数据库设计中只有内部主键的工作人员、机构用户、任职或绑定等对象，必须使用已有稳定公开码，或为该对象补充独立公开 ID 并同步回写数据库设计；不得为了避免补字段而退回暴露内部主键。
6. P0 货币固定为人民币。金额使用保留两位小数的元字符串，例如 `"12.30"`；单价使用每千克四位小数的字符串，例如 `"0.8000"`；业务重量使用保留两位小数的千克字符串，例如 `"1.25"`；传感器原始重量使用字段名明确单位的带符号整数克。精确值不得通过 JSON 浮点数传输。
7. 时间使用 UTC、毫秒精度 RFC 3339，例如 `2026-07-23T08:30:15.123Z`；界面按 `Asia/Shanghai` 转换。枚举使用稳定英文字符串，不暴露数据库数字状态。
8. `requestId` 用于关联本次 HTTP 调用；错误响应也必须携带。微信通知应答、OneNet/MQ ACK 和健康端点遵守各自协议，不套用自有 HTTP 信封。

## I-003 会话、可信作用域与资源可见性

**已确认：每类客户端建立独立会话受众，租户、机构、操作者和能力由后端可信上下文确定；业务接口不得把客户端自报作用域当作授权事实。**

1. Web 登录只提交登录名和密码。成功后由后端设置带 `__Host-` 前缀、`Secure + HttpOnly + SameSite=Lax + Path=/` 且不含 `Domain` 的 Cookie，不在 JSON 中向 JavaScript 返回 Token，并为状态修改请求启用 SPA CSRF；具体 Cookie 后缀在认证接口专题确定。
2. 普通用户和清运员通过 `wx.login + AppID` 建立绑定当前机构的 `aud=miniapp` 会话；AppID 仅用于登录阶段定位候选机构，必须由后端根据已启用配置完成校验。
3. 已在 Web 中绑定的工作人员通过 `wx.login` 自动建立独立 `aud=miniapp-staff` 会话并进入机构精简管理端，不要求再次输入 Web 密码。
4. 所有会话使用唯一 `jti`，后端依据数据库中的账号状态、会话状态、当前能力和机构授权实时构造可信执行上下文；Token 内角色或作用域不是最终权限事实。
5. 普通业务写 DTO 不接收 `tenantId` 或 `organizationId` 作为授权依据。Web 总部跨机构查询可以提交机构公开 ID 作为筛选条件，但结果必须与服务端授权范围求交；写操作还必须从目标资源反查并再次核对作用域。
6. 普通/清运小程序和工作人员小程序会话固定一个机构，不能通过请求参数切换机构。平台跨租户操作只能通过显式平台特权用例并记录审计。
7. 资源不在当前主体可见范围时统一返回 `404`，避免通过接口探测其他租户或机构；资源可见但缺少动作能力时返回 `403`。
8. OneNet 入口从可信设备身份和原稳定作业 ID 定位冻结部署；微信入口从验签后的商户单号定位已有业务。两者都不能相信消息正文单独上报的租户或机构字段。

## I-004 业务命令、幂等与并发控制

**已确认：所有可能因网络、超时或用户重复点击而重试并产生业务效果的人机命令，在业务效果发生前取得稳定幂等身份；幂等、预期版本、数据库锁和唯一约束共同保证正确性。**

1. 开门、提现、充值、审核、纠错、人工调账、取消、恢复、人员绑定和配置发布等可重试写请求，要求客户端在首次动作前生成 UUIDv4 `Idempotency-Key`。该值一对一成为全局唯一 `operationUid`，一个逻辑动作只生成一次；同一动作的所有重试复用原值，改变动作内容必须生成新值。登录和纯查询不要求该键。
2. 稳定主体、租户/机构作用域、命令类型和规范化请求摘要都是该全局 `operationUid` 的绑定校验维度，不是允许同一个 UUID 在其他主体或命令中复用的命名空间：
   - 已经可靠受理或成功的同一 `operationUid` 且摘要相同，返回首次动作的已有结果；
   - 已经可靠受理或成功的同一 `operationUid` 但摘要、主体、作用域或命令类型不同，返回 `409 COMMON.IDEMPOTENCY_KEY_CONFLICT`，不得执行第二种内容；
   - 在可靠受理或业务效果发生前被拒绝或失败的请求，不占用“成功操作”唯一槽，也不永久缓存失败结果；调用方使用新的 `requestUid` 和原 `operationUid` 重试原意图，服务端重新执行当前认证、授权和业务前置检查，每次失败尝试分别审计。
3. `requestId`、`correlationId`、MQ message ID 或时间戳只用于传输追踪，不能代替领域幂等身份。
4. 审核、纠错、配置发布等依赖当前版本的命令携带 `expectedVersion`。服务端锁定最新状态后复核；版本、状态或当前占位已经变化时返回 `409`，不能允许客户端强制覆盖。
5. 设备/OneNet 使用投递会话 ID、清运操作 ID、命令 ID 和事件 ID 等已经冻结的领域身份；不存在投递周期 ID。投递 session 单独是最终物理结果和订单的业务唯一根，event 只作可靠事件去重/冲突身份；微信使用固定 `out_trade_no`、`out_bill_no` 和渠道单号，不强行套用人机 HTTP 幂等键。
6. 幂等命中只证明同一意图不会重复生效，不替代能力校验、当前状态校验、行锁、条件更新、唯一约束或资金不变量。
7. MySQL 死锁、锁等待超时或可安全重试的临时失败必须保持原幂等键和领域身份；重试耗尽时返回稳定错误码及 `retryable=true`，不能换 ID 制造第二笔业务事实。

## I-005 同步响应、异步操作与分层成功语义

**已确认：接口必须区分传输收到、可靠持久化、外部/物理执行以及 EcoBin 业务提交；任何一层的应答都不能冒充后一层成功。**

统一区分以下事实：

1. 请求或消息已被传输入口收到；
2. 请求、命令或事件已经可靠持久化；
3. 外部系统或设备已经受理、执行，或已经观察到物理/渠道结果；
4. EcoBin 领域事务已经提交并形成权威业务状态。

具体规则：

1. `201` 只声明本地资源已创建。例如提现单和双方冻结创建成功，不代表微信零钱到账。
2. `200` 只声明本次同步本地转换已经提交。响应中的领域状态仍决定整个长流程是否终结。
3. 当端点只可靠受理了尚待执行的操作时返回 `202`，至少提供 `operationId`、`resourceId`、`status`、`statusUrl`，并通过 `Location` 指向权威查询资源。
4. P0 客户端通过查询权威资源状态收敛，不依赖 WebSocket 或 SSE。每个业务专题继续定义可见状态、建议轮询间隔和合法 `nextActions`。
5. 只有动作已经可靠持久化，或者已经记录“外部调用可能开始”而结果不明确时，HTTP/外部超时、系统错误或渠道未知结果才保留 `PROCESSING/UNKNOWN` 等非终态，并使用原业务身份查单、重试或续办。可靠受理前明确失败的请求可以直接返回失败且不创建业务资源，但仍不得把失败尝试伪装成已受理操作。
6. OneNet 北向 MQ ACK 和微信通知应答只表示可信 inbox 及唯一处理任务已经可靠落库，不表示订单、清运、充值或提现已经完成。
7. 设备命令的 `accepted` 只表示香橙派已经把命令可靠保存到 SQLite，不表示门已经打开或作业已经完成。门开、门关、传感器结果和失败原因必须作为独立物理事实报告。
8. 设备完成事件只有在后端形成权威领域事实并返回业务确认后，香橙派才可以清理本地待确认事件；传输 ACK、设备 ACK 和业务确认必须使用不同字段和状态。
9. 外部业务动作只能在本地事务提交后由唯一可靠任务执行。HTTP 请求线程不得持有数据库事务等待门动作、照片上传、OneNet 或微信终态。I-012 为不把 AppSecret 正文落入业务数据库而使用唯一窄化存储例外：先以 `operationUid` 向外部秘密设施幂等写入一个不可变、尚未被业务引用的秘密版本，再由短数据库事务切换 `secret_ref`；孤立版本没有业务效果并可清理。该例外不能用于设备、资金、微信、COS 或其他外部业务动作。

## 后续细化边界

本批不提前决定以下专题细节：

- 每个业务端点的完整 URL、DTO、能力码、状态枚举和字段可见性；
- CSRF Header 名、Cookie 名、Token TTL、会话数量和限流阈值；
- 各命令幂等记录的具体保留年限及领域动作 ID 字段；
- 投递、清运、充值和提现的轮询间隔、`nextActions` 与完整错误码表；
- OneNet Topic、消息字段、照片对象规则、UART 逐字节帧和微信 APIv3 请求/通知字段；
- Java `.api` 包中的 Command、Query、Event 方法签名和契约测试实现。

这些内容按总索引的后续章节逐批确认，不得改变 I-001～I-005 已冻结的语义。
