## 本轮发现并关闭的问题

1. 首次第 1 代封存授权被设备以 `ACCEPTANCE_EVIDENCE_MISMATCH` 拒绝。原因是活动设备端
   只接受验收证据 Schema 3，而后端已经生成 Schema 4。提交 `00af96dc` 让设备明确接受
   Schema 3/4；提交 `cb9952c0` 让后端在终态拒绝后保留旧事实并启动新验收代次。第 1 代
   保持 `CANCELLED`，没有被覆盖。
2. 第 2 代授权到达后，局域网页的封存按钮看似没有反应。设备始终保持 `SEAL_READY`，
   证明请求没有进入封存状态机。根因是明文 HTTP 出厂门户调用了只在安全网页环境可用的
   `crypto.randomUUID()`，且异常发生在页面错误处理之外。提交 `8e83f997` 改用普通 HTTP
   也可使用的安全随机 UUID v4，并保证浏览器能力错误可见。完整设备侧回归为
   `980 passed, 46 skipped, 5 subtests passed`。

两个修复均已进入版本库；本卡还对活动运行目录做了受控热更新并保留原文件备份。修复后
设备没有重新验收或伪造状态，而是继续使用未消耗的第 2 代授权完成原状态机。
