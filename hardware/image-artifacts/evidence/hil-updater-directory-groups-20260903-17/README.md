## 本次修正

v16 已修正服务组件发布目录不可被低权限用户穿越的问题，但它绑定提交 `42cc922c`。随后在
v13 设备执行永久层原位安装时，r2 后置审计发现 systemd 启动更新器会按 `StateDirectory`
配置递归改写 `/var/lib/ecobin/updater` 的用户组，连带破坏 `staging` 和 `mcu-firmware` 两个
私有子目录的主组约束。r2 因而自动完整回滚，没有带病放行。

提交 `4120579c5a7d7243e8d3d6db0b537065b9ead529` 让更新器顶层目录直接匹配 systemd 所需的
本机接口组，同时保持两个私有子目录属于更新器主组。v17 包含该提交。除镜像软件审计外，本轮
还对无秘密候选建立只读 loop 设备，并直接读取镜像内
`/usr/lib/tmpfiles.d/ecobin-device-runtime.conf`，确认三个精确事实：

```text
d /var/lib/ecobin/updater 0700 ecobin-updater ecobin-updater-ipc -
d /var/lib/ecobin/updater/staging 0700 ecobin-updater ecobin-updater -
d /var/lib/ecobin/updater/mcu-firmware 0700 ecobin-updater ecobin-updater -
```

只读检查结束后 loop 设备已解除，没有遗留挂载点。对应的 v13 原位安装、自动回滚链、权限
正反例和在线服务审计见
[第三阶段永久层原位安装与在线验收证据](../hil-stage3-live-maintenance-20260903/README.md)。
