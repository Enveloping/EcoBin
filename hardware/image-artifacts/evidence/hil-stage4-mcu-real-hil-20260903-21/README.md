# v21 第四阶段 MCU 更新真机 HIL 候选证据

## 1. 范围与当前结论

本记录对应镜像源码提交
`d97bcca2a6d4943e8c72094b65036d2765cefbac`。v21 把已经完成自动化回归的永久 MCU
更新状态机、候选低权限业务程序、候选通信代理、候选特权助手和一把 HIL 专用 MCU
验签公钥放入同一张可启动镜像，并在受控 HIL 副本中预置一对已签名的目标/回滚包。

截至本记录形成时，结论是“可进入指定单卡写入和真实 MCU 成功路径验收”，不是“真机
验收已通过”：v21 尚未写入 TF 卡、尚未启动，也没有触发 MCU 烧录。候选服务仍为静态、
默认关闭，生产更新器仍拒绝远程 MCU 更新命令。

## 3. 为什么由 v20 递增为 v21

v20 已包含永久 MCU 更新实现并通过离线审计，但镜像中原有 MCU 公钥对应的签名私钥在本次
受控环境中不可用。没有绕过签名、伪造验签结果，也没有用业务运行时签名密钥替代 MCU 密钥。
为形成可真实烧录的 HIL 证据，本机在仓库外生成一对 HIL 专用 Ed25519 密钥，只把公钥加入
新的镜像字节，因此必须递增为 v21，不能继续沿用 v20 身份。

HIL 公钥编号为 `HIL_SINGLE_CARD_20260903`，PEM 公钥摘要为
`5585a5a9746e9f13cdfa14f438c88904a9b2c5d25e77406bf6c8c64933819bce`，DER 公钥摘要为
`94460a9c19d0d159197c1bf90d8d0be6d2bb44a458b3c5c4df6d365a5cb6eab2`。私钥只存在于本机
仓库外的受限目录，继承权限已关闭，仅当前用户、SYSTEM 和 Administrators 可访问；本文不
记录私钥内容或私钥摘要。候选和 HIL 镜像均确认只含两把 `.pem` 公钥，没有私钥或其他信任
目录文件。

## 4. HIL 签名包

本轮成功路径使用更新编号 `d1517a4b-d77e-4002-a540-2dfdc89ab708`，命令编号
`a9557e3a-1d7a-4b03-aa1e-82a29be3edcf`。两份包均声明硬件兼容标识
`ECOBIN_MAINBOARD_V1.1`、固件版本 `1.0.0-dev`、版本码 `10000`，并由上述 HIL 公钥独立
验签通过。

目标与回滚二进制的差异严格限于链接地址偏移 `0x3B18`～`0x3B1F` 的 8 字节固件身份；其余
可执行逻辑字节一致。这样可以真实证明“烧录后读取到新身份”，同时不把尚未变化的业务逻辑
伪装成新 MCU 功能。

HIL 镜像没有提前创建更新器的 `incoming` 队列，因为 `ecobin-updater` 的低权限 UID/GID 要到
首次启动时由 systemd-sysusers 创建。两份包仅以 `root:root / 0600` 存放在
`/root/ecobin-hil-mcu-packages/<updateUid>/`，目录为 `0700`；它们不会被自动发现或执行。
真机验收时必须先由 root 明确复制到首次启动后已经存在、属于 `ecobin-updater` 的固定队列，
再通过本机 root 控制接口提交精确更新编号和两个包摘要。
