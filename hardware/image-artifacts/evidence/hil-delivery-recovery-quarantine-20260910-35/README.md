# v35 投递异常隔离镜像构建记录

## 范围与来源

本轮制作包含“物理结果未知投递的远程异常隔离收口”的单卡开发/HIL（硬件在环测试）
候选镜像。它同时更新香橙派业务程序、永久通信代理和永久更新器，不修改 HMI 或 MCU。
构建轮没有连接设备、写 TF 卡或部署后端/OneNet；随后用户另行确认新卡，已完成下文记录的写卡与回读。

管理员手动确认现场安全后，设备核对新的启动身份、MCU 安全与健康证据和原动作账本，
只追加问题证据并取消原投递。原“可能已经发生动作”的记录不改写为成功，也不重放开门。
后端配套实现只归档已有重量、照片等问题资料，不创建订单，不增加余额，不进入审核或
自动提现。该能力只覆盖符合条件的未知结果投递，不是任意异常或清运的强制解锁入口。
完整条件见[异常隔离设计与部署边界](../../../../docs/architecture/delivery-unknown-effect-quarantine-2026-09-10.md)。

原工作区包含尚未提交的跨端功能和 MCU/HIL 修改。本轮未提交、回退或清理原工作区，而是在
独立构建仓库中以原 HEAD 为基线，覆盖选定的 67 个已跟踪修改文件和 15 个新增源码文件，
形成可追溯的干净源码快照。未纳入 `hardware_mcu.zip` 和现场 HIL 原始资料；后续证据文档
不影响已固定的程序源码。

## 自动化测试

冻结依赖后，在 Linux x86_64 / Python 3.11.15 上完整运行硬件测试：
**2080 passed，9 skipped，5 subtests passed，0 failed**，耗时 300.87 秒。
结果与环境说明见 [test-evidence.json](test-evidence.json) 和
[完整测试输出](python311-tests.txt)。

使用 diagnose 技能的复现和对照检查确认了两类构建机环境问题，未为此修改产品代码：

- 六个既有测试默认要求宿主已经完成网络校时，但 WSL 实际报告“时间仅为估计值”。通过
  [逐测试时钟前提夹具](v35_clock_fixture.py) 仅为这六个测试提供已同步前提；专门验证
  不可信时钟的测试不变，专项 10 项通过，未改变操作系统时间或校时标记。
- 第二次全量运行使用的临时目录过长，导致九个本机 Unix Socket 测试超过地址长度上限。
  同一测试在长路径失败、短路径通过；最终统一使用 `/var/tmp/eb35-final` 后全量通过。

测试结果不等于真实门控、称重、断电恢复或云端异常收口已验收。

## 后续使用边界

1. 新镜像是洁净出厂状态，不包含旧设备身份、待处理投递或永久动作账本。用户本次已决定不迁移
   旧数据，按新卡重新开始；这不等于服务器上的旧投递、占用或账本已取消/清除。若未来仍要对原
   未决投递做隔离收口，必须保留原身份和账本证据，不能用本次新卡写入替代。
2. 普通远程业务包不包含永久更新器，不能单独补齐本次能力。要处理当前旧设备的未决投递，
   仍需保留身份和账本的原位永久层升级方案；本轮没有实施这项升级或搬移旧状态。
3. 后端数据库 V69、后端/Web、OneNet 候选 18 个服务/22 个事件，以及新镜像版本的后端认可
   配置尚需部署和核对。本轮只构建镜像，不改变这些外部系统，也不启用远程更新开关。
4. 已具备本次所需 F1/F3 能力的 MCU 不需为此再次烧录，串口屏不需修改；首次启动、设备接入、
   永久运行层切换和安全门启用仍须按现场状态受控操作，不能把离线构建通过当作现场放行。
5. 含厂家接入输入与测试登录的 HIL 镜像按机密制品保管，不公开上传、不提交 Git。公开证据
   只记录镜像整体摘要和审计结论，不记录秘密值或各秘密的单独摘要。
