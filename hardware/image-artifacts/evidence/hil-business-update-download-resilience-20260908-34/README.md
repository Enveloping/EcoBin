不要求重写 TF 卡；v34 是供以后新装或重装设备使用的递增基础镜像。

## 构建与离线镜像审计

无秘密候选构建结果为 `v34-candidate-build=PASS`。目标 Python 3.11、Debian 软件源快照、
ARM64 构建容器、上游镜像、软件载荷锁和 32 GB TF 卡布局均由已有锁文件约束。候选完成账户锁定、
自动登录关闭、根文件系统净化、原始布局、ext4 配置、inode 清单、确定性元数据规范化、五阶段
文件系统检查和软件清单审计。

HIL 镜像只从摘要已核对的 v33 HIL 继承现有单卡接入输入和受控测试登录输入，系统及程序内容全部
来自 v34 候选。注入前后候选与 v33 来源摘要均未改变。HIL 再次通过布局、`e2fsck`、ext4、软件
清单、root 锁定、开发登录、洁净首次启动状态和当前 HSK/Generic USB Camera 双摄配置检查，最终
输出 `v34-hil-image=PASS`。

永久程序边界审计同时只读挂载候选和 HIL，确认：

- 永久通信代理 10 个文件、永久更新器 24 个文件和 2 个 systemd 单元与固定提交逐字节一致；
- 两项服务均启用业务更新协议，更新器的私有下载域名和正式公钥正确；
- 镜像不存在正式签名私钥或旧 HIL 公钥，更新器没有额外 Linux capability 或设备节点权限；
- 自动更新队列为空；候选与 HIL 均输出 `v34-permanent-boundary=PASS`。

## ARM64 用户空间执行

在无网络、只读镜像、无新增权限的 ARM64 容器中，直接执行镜像内文件得到：

- Python 3.11.2 可以运行；
- 永久更新器、永久通信代理和首次启动业务桥接模块均可导入；
- 镜像内 `DOWNLOAD_IO_STALL_TIMEOUT_SECONDS` 的实际值为 120；
- 最终任务仅清理自己的下载与暂存树，活动任务和失败锁定任务保留诊断材料；
- 硬链接越界清理被拒绝，首次清理失败后更新器重启能够完成补偿。

Docker Desktop 在容器退出后短暂保留一个指向已删除临时状态目录的 bind mount。复核确认没有对应
容器或 loop 设备后，仅对该精确 v34 临时挂载点执行卸载；最终没有容器、loop 或挂载残留。再次
复算候选和 HIL SHA-256，与构建输出完全一致。
