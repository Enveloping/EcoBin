## v29 被替换的原因

v29 在事后最终审计中发现两项必须同时满足但当时未进入镜像的运行边界：

- 永久通信代理和更新器的启动命令均未传入“允许处理远程业务更新”参数，所以 OneNet 更新
  命令只会被明确拒绝；
- 更新器服务被限制为仅能访问本机 Unix Socket，并显式拒绝所有网络地址，因此即使接收命令
  也无法从私有 COS 下载发布包。

v30 为两个永久服务显式启用远程业务更新；更新器只接受配置好的固定下载基础地址
`https://ecobin-update-package-1436310712.cos.ap-beijing.myqcloud.com`，允许 DNS/HTTPS 所需的
IPv4/IPv6 网络族，同时继续保留无新权限、空 capability、关闭设备访问、只读信任根及业务/
通信状态目录隔离。临时 URL 仍由后端在实际发送时生成，摘要和 Ed25519 签名仍决定制品身份。
