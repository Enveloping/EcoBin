# v26 永久服务就绪与新旧双摄选择 HIL 候选证据

本目录记录 `0.1.0-single-card.20260904.26` / `hardware-runtime-20260904-26`
的受控构建与独立离线审计事实。v26 包含两组改动：厂家热点网页展示永久服务的真实
就绪结果及蜂窝域名解析重试进度；出厂验收、日常业务和低权限启动自检统一采用“当前
摄像头优先，当前型号缺失时才使用历史型号”的角色选择。

本文证明源码、业务包和镜像字节的离线一致性，以及指定 TF 卡的完整写入和全范围回读
一致性。v26 尚未经过空白冷启动、厂家接入、封存、投递、清运或业务更新/回滚真机验收，
因此不能称为量产镜像。

## 1. 真实摄像头身份与角色

通过香橙派串口读取 `/dev/v4l/by-id`，并分别从两个 `video-index0` 采集预览帧后确认：

| 角色 | 当前首选稳定路径 | USB VID:PID | 预览确认 | 当前型号缺失时的回退 |
|---|---|---|---|---|
| 外部摄像头 | `usb-HSK-260323-J_UNIQUESKY_CAR_CAMERA-video-index0` | `1bcf:0b09` | 画面朝设备屏幕 | `usb-DECXIN_CAMERA_DECXIN_CAMERA_01.00.00-video-index0` |
| 内部摄像头 | `usb-Generic_USB_Camera_200901010001-video-index0` | `0bda:5844` | 画面朝天花板 | `usb-icSpring_icspring_camera-video-index0` |

上一只 HSK 外部摄像头与当前外部摄像头具有相同的稳定型号身份，因此首选路径天然兼容
两者；更早的 DECXIN 外摄仍作为显式回退。新旧型号同时存在时只选当前型号；某一角色的
首选和回退都缺失时，该角色保持缺失并使验收或业务启动失败，不会借用另一角色的摄像头，
也不会退回容易随启动顺序变化的 `/dev/videoN`。

实现提交为 `39e52561f931eff70e5d9a4bf27c5af3e25d5c44`。统一选择器同时供出厂
配置、日常业务配置和永久层启动预检使用，并被安装到旧业务运行时、隔离厂家应用及
`/usr/lib/ecobin` 三处。

## 4. 构建和第二套独立审计

候选构建、HIL 受保护输入注入及最终业务包注入均通过布局、ext4、精确软件清单、账号、
空白首次启动状态、开发登录边界和私钥缺失检查。随后由另一份只读脚本重新计算所有摘要、
验签并解包两份业务包，再分别挂载候选和最终 HIL 镜像。独立审计确认：

- `camera_selection.py` 在三个安装位置与提交源码逐字节一致，`hardware.env` 精确包含两条
  当前路径和两条历史回退路径；当前与回退两种存在性组合的选择结果都通过；
- 永久服务就绪、蜂窝状态投影、热点网页依赖、首次启动协调器、持久切换模块及九个新旧
  业务链 systemd 单元均与当前源码一致；
- 两张镜像的切换状态为空，默认仍使用旧直连链；候选服务、远程业务更新和自动业务包
  队列保持关闭；
- HIL 的两份包及请求元数据与固定发布身份、序号、大小和摘要一致，镜像内没有业务签名
  私钥；审计结束后候选、HIL 摘要未变，也没有遗留挂载或 loop 设备。

独立结论为 `v26-runtime-readiness-cameras-r2-independent-audit=PASS`。

与摄像头选择有关的 Python 3.11 专项共 52 项通过；root 镜像安装器 25 项、生产配置/
运行时发布/照片管理 97 项、业务发布 6 项、镜像工具 40 项（另 1 项跳过、24 个子测试）及
厂家核心/服务/页面/协调 178 项均通过。后端认可版本专项 13 项也通过。以上是聚焦回归，
