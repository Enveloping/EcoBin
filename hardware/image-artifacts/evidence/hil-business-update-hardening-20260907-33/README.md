# v33 业务程序更新恢复加固镜像证据

## 结论

2026-09-08 已从提交 `1b89b7451c7aee413be219371415ef55ea63a3a4` 构建 v33
无秘密候选镜像和受控单卡 HIL（硬件在环测试）镜像。该版本把 v32 真机发现并修复的两项问题
固化进可重复镜像：

- 通信代理或设备更新器单独重启时，不再由 systemd 反向停止正在运行的业务程序；
- 成功、已回滚、已延期和已拒绝的更新会安全清理下载与解压临时目录，更新器重启后会补做中断
  的清理；失败且设备保持安全锁的任务继续保留诊断材料。

修复进入镜像前已在 v32 真机完成分别重启、整机重启、更新后真实投递和真实清运复核。v33
候选和 HIL 镜像随后通过磁盘布局、文件系统、源码一致性、正式验签公钥、私有 COS 下载边界、
最低权限及永久程序边界审计。生产后端厂家验收认可列表已在保留 v31、v32 的同时追加 v33，
业务程序远程下发总开关继续为关闭。

v33 尚未写入 TF 卡，因此不能把上述构建与离线审计等同于 v33 自身的冷启动、热点验收、投递、
清运或远程更新真机通过。

## 构建与离线审计

正式候选构建得到以下明确结果：

- 目标 Python 为 3.11，Debian 软件源快照、ARM64 构建容器和 32 GB TF 卡布局均锁定；
- 业务运行时归档完成摘要和签名校验，软件载荷锁验证通过；
- root 与 orangepi 账户均保持锁定，自动登录关闭，候选镜像不包含接入秘密；
- 根文件系统净化、原始分区布局、ext4 配置、inode 清单、确定性规范化和镜像软件审计通过；
- 构建日志最终输出 `v33-candidate-build=PASS`。

HIL 镜像仅从摘要已核对的 v32 HIL 继承当前单卡接入输入和测试登录输入，业务与系统内容来自
v33 候选。构建后确认：

- 候选和 v32 受控输入源在复制前后均未改变；
- 注入后 `e2fsck` 五阶段、磁盘布局、ext4 配置和软件清单再次通过；
- root 继续锁定，只保留受控 orangepi 测试登录，自动登录关闭；
- 首次启动状态洁净，没有预置业务数据库、活动更新或断电测试钩子；
- 外部摄像头为当前 HSK，内部摄像头为当前 Generic USB Camera，旧型号回退逻辑继续保留；
- 最终输出 `v33-hil-image=PASS`，独立复算 `.sha256` 文件得到 `OK`。

永久程序边界审计同时检查候选和 HIL 两张镜像，结果为：

- 永久通信代理 10 个文件、永久更新器 24 个文件和 2 个 systemd 单元与固定提交逐字节一致；
- 两项永久服务均启用业务更新协议，下载基础地址固定为正式私有 COS；
- 更新器保留受限网络能力，但没有额外 Linux capability，也不能访问设备节点；
- 正式业务公钥存在、旧 HIL 公钥不存在，镜像内没有私有签名材料；
- 自动更新队列为空，最终输出 `v33-permanent-update-boundary=PASS`。

机器可读摘要见 `v33-image-build-evidence.json`。
