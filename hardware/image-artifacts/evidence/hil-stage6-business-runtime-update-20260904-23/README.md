# v23 第六阶段业务程序更新真机 HIL 候选证据

## 1. 范围与当前结论

本记录对应镜像源码提交
`59302a543b3db83410cc55505670b3952e721e6f`。v23 首次把第六阶段本地业务程序更新链放入
可启动镜像：永久更新器能够从固定本地目录接收一份已签名业务包，在暂停新业务、排空当前
作业和备份本地数据库后切换低权限业务版本；目标版本不健康时恢复数据库和上一稳定版本。

截至本记录形成时，结论是“离线审计通过，可进入指定单卡写入和真机验收”，不是“第六阶段
已经通过”。本轮没有写 TF 卡，也没有启动香橙派。候选服务均为静态单元且默认不启动，生产
更新器仍拒绝远程业务更新，后端也没有业务更新下发能力。

## 4. 构建入口修复与本机控制入口

提交 `0e24d17f` 修复业务包专用构建模式的二次模式校验，并用自动化测试锁定入口，避免构建
容器接受参数后又在已安装脚本中错误拒绝。提交 `59302a54` 为 root 控制命令新增：

- `business-queue`：只提交固定更新目录所需的更新编号、部署编号、命令编号、发布身份、包
  摘要、大小和公钥编号，不接受任意文件路径或 URL；
- `business-status`：查询当前业务更新或指定更新编号的持久状态。

镜像外重新挂载后的独立审计确认，候选与 HIL 镜像中的命令行文件均和源码逐字节一致，并
包含 `QUEUE_LOCAL_BUSINESS_UPDATE` 与 `GET_BUSINESS_UPDATE` 两个精确协议动作。
