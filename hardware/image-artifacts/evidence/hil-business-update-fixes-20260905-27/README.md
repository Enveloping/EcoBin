# v27 业务程序更新修复递增镜像证据

## 1. 结论和边界

本目录记录 `0.1.0-single-card.20260905.27` / `hardware-runtime-20260905-27`
的完整递增构建与第二套独立只读审计。v27 从干净提交
`3a4b44624a90964929daa5c73fb7a1580e860fac` 构建，把 v26 真机业务程序更新、自动
回滚和四个关键点物理断电验收期间形成的正式修复固化进可重复写卡镜像。

构建和独立审计均通过。无秘密候选与受控 HIL（真实硬件联调）镜像的软件文件系统完全
一致；HIL 只比候选多出从已核验 v26 单卡来源逐字节继承的两项厂家接入输入，以及测试操作员
登录密码字段。两张镜像都没有预装业务更新包、自动更新任务、设备运行数据库、设备唯一状态、
签名私钥或临时断电测试钩子。

v27 尚未写入 TF 卡、完成写后全范围回读或从空白状态冷启动，因此不能称为真机或量产通过。
当前正在运行的设备和卡没有在本次构建中被修改。v26 上完成的真机验收证明修复逻辑在当前
设备有效，但不能替代 v27 镜像字节本身的写卡和冷启动验收。

## 3. 固化的正式修复

v27 包含 v26 构建提交之后、截至 `3a4b4462` 的设备侧正式修复，主要关闭以下边界：

- 首次切换永久通信代理后，封存事实和目录权限能够跨重启保留，首次启动协调器不会重新拉起
  已被永久代理取代的旧直连链；
- 业务运行时切换的目录、所有权、不可变发布复用、失败状态清理、根错误保留、数据库快照和
  回滚步骤能够在正常失败与重启恢复中安全收敛；
- 业务程序已健康启动但更新器先恢复时，只有重启前已经存在且处于目标验证、观察或回滚验证
  阶段的更新获得最多 210 秒就绪宽限；版本或身份不符仍立即失败，正常在线更新不使用宽限；
- 厂家接入、封存、首次启动状态和业务预检的原子写入与目录可穿越权限保持一致。

独立审计把下列 17 个安装目标与构建提交中的对应源码逐字节比较：业务切换器、业务更新协调
器、低权限激活原语的两处副本、厂家验收交接与存储、封存控制与验证的两处副本、首次启动
原子 JSON 与状态存储、业务启动权限预检，以及六个相关 systemd 单元。全部一致，临时
`power-loss HIL checkpoint reached` 钩子不存在。

## 4. 两套镜像审计

候选构建和受保护输入注入各自先运行布局、ext4 文件系统参数、软件清单、账号、首次启动
空状态、来源身份和秘密边界检查。构建完成后又使用独立脚本从头执行只读复验，结果为：

- 两张镜像的原始分区布局和 ext4 参数通过，镜像软件安装器的精确审计均为 `PASS`；
- 候选清单中的提交、版本、平台、组件、镜像摘要和软件载荷锁摘要均与实际字节一致；
- 排除两项受保护输入和账户密码文件后，候选与 HIL 的路径、类型、权限、属主、硬链接数、
  大小和文件摘要完全一致；账户文件只有操作员密码字段发生获准变化；
- 两项 HIL 接入输入与 v26 来源逐字节一致、权限为 `root:root / 0600`，候选完全不含这些文件；
- 当前外摄 HSK、当前内摄 Generic，以及外摄 DECXIN、内摄 icSpring 两条缺失回退配置均精确
  存在；
- 自动业务更新队列为空，首次启动服务启用，可更新业务目标尚未启用；候选与 HIL 都没有
  业务数据库、通信数据库、更新器数据库、厂家状态、封存状态、私钥或预装业务发布包；
- 审计结束后候选、HIL 和 v26 受保护来源摘要均未改变，也没有遗留挂载或 loop 设备。

最终独立结论为 `v27-independent-audit=PASS`。

## 5. 下一步

在写卡前，应先把 `hardware-runtime-20260905-27` 加入测试后端的机器验收允许列表，并完成
服务器配置备份、生产预检、容器健康、回环请求和秘密隔离复核。之后只有在项目负责人明确
确认目标磁盘时，才可把最终 HIL 镜像写入指定 TF 卡并做完整写入范围回读。

写卡后仍须从断电状态完成空白启动、热点接入、封存、永久服务就绪、双摄、正常投递和正常
清运复验。由于 v27 固化的是已经在 v26 当前卡上通过的更新器修复，可以在上述基础业务通过
后选择聚焦重跑一次健康业务程序更新与失败回滚；正式私有 COS、正式业务签名根、后端实际
安装事实闭环及第八阶段远程下发仍是独立未完成项。
