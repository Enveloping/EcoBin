## 本轮进入镜像的能力

永久设备更新器现在拥有独立的 MCU 更新数据库和可断电恢复状态机。root 只能把同时包含目标
固件、回滚固件、精确硬件兼容标识、版本身份和离线签名的本地包放入固定队列；更新器先核对
设备实际安装的 MCU 身份，再等待已有投递或清运结束，并阻止新业务进入。

排空完成后，低权限业务程序主动停止使用 UART，候选业务辅助程序停止业务服务，候选 MCU
辅助程序才可切换 BOOT0/复位并调用固定 `stm32flash`。每一次 root 动作都必须与更新数据库中
预先落盘的更新编号、动作编号、载荷摘要和维护围栏完全一致；授权只能消费一次。目标与回滚
各最多尝试 3 次，烧录回复未知时先读取实际固件身份，不会盲目重复烧录。出现无法归属的身份、
无法确认的物理动作或无法恢复业务程序时，设备保持维护锁定。

候选更新器使用静态 systemd 单元，默认没有开机启用链接，并与正式更新器互斥。候选进程启用
了 `PrivateNetwork=yes`，只能读取 `/var/lib/ecobin/updater/mcu-firmware` 的本机包；通信代理收到
远程 MCU 或业务更新命令仍明确拒绝。正式更新器没有候选参数，正式辅助程序也没有候选动作
授权，因此构建镜像本身不会改变当前生产行为。

## 镜像构建与独立审计

受控构建使用锁定的 Orange Pi Debian 基础制品、锁定 ARM64 构建器、精确 APT 快照和已接受
的指定单卡介质证据。最外层构建命令在 30 分钟保护时限到达后退出，但当时隔离构建容器仍在
执行最后的文件系统归一化；容器随后以退出码 0 完成。没有把该退出码单独作为资格依据，而是
从最终制品重新运行了完整候选校验、HIL 注入后校验和独立最终边界审计。

无秘密候选和受控 HIL 镜像均通过以下检查：

- 固定原始分区布局、镜像长度、ext4 参数和只读 `e2fsck`；
- 软件载荷锁、全部组件精确文件清单、发布身份和源码提交；
- 12 个永久层及候选 systemd 单元的精确内容和运行时围栏；
- 候选更新器默认关闭、与正式更新器互斥、无网络权限且只使用本机固件队列；
- 正式更新器未启用第四阶段或 MCU 更新，正式辅助程序未取得候选授权能力；
- 候选辅助程序必须回查永久更新器的一次性持久授权，不能凭 Socket 可达性直接执行 root 动作；
- 无秘密候选不含出厂密钥、热点密钥、设备凭据、业务数据库、`machine-id` 或 SSH 主机密钥；
- HIL 镜像只从 v19 继承出厂接入密钥、热点密钥和已批准的本地调试登录，不继承设备业务数据库、
  已封存状态或机器唯一凭据；本文不读取、不拆分也不记录任何秘密值；
- 审计前后候选镜像、HIL 镜像、运行时、载荷锁、源码 bundle 和受保护 v19 来源摘要保持不变；
- 全部只读挂载点和 loop 设备均已清理。

## 下一道现场门禁

在取得以下证据前，不能启用远程 MCU 更新，也不能把 v20 称为已验收镜像：

1. 将 `hardware-runtime-20260903-20` 加入后端机器验收允许列表，并确认不会误删当前 v19；
2. 由项目负责人重新确认目标 TF 卡，写入 HIL 镜像并对同一物理盘做全范围回读；
3. 断电冷启动后完成厂家接入、单向封存、普通投递和普通清运回归；
4. 受控启用静态通信代理、低权限业务程序和候选更新器，证明新业务可经通信代理正常收发；
5. 使用为该单板和当前 MCU 实际身份制作的签名目标/回滚包，完成成功升级及恢复原版本；
6. 分别在排空、停止业务、烧录、验证和恢复业务阶段做进程终止或断电故障注入，证明重启后
   不重复不可确认的硬件动作，并能按实际身份继续、回滚或保持维护锁；
7. 再次证明远程更新命令仍被拒绝，然后才讨论接入后端发布控制面。
