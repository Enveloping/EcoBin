# v8 单卡扫码、投递与运行快照准入闭环证据（2026-08-29）

## 结论

指定设备在后端发布 `20260829102341-71eba405a04e` 后，已经通过“小程序扫码准入 →
设备开门与称重 → 设备上报完成 → 后端建单与自动审核 → 释放设备占用”的完整成功路径。
同一轮操作还触发了多条运行快照，后端均按可信遥测接收，发布后没有新增隔离消息。

本次现场结果关闭了两个会阻断正常流程的软件问题：

1. 小程序扫码准入曾读取设备运行快照中的临时配置回报；当可靠配置任务已经是
   `APPLIED`（已应用）、但设备尚未再次上报运行快照时，会误报“设备配置尚未生效”。
   现在扫码准入与正式开始投递事务统一读取可靠配置进度投影。
2. 固定帧设备会同时省略 UART 协议主、次版本。旧逻辑在存在 MCU 固件身份时错误地把它
   当作新版 UART 设备，从而隔离运行快照。现在只依据 UART 主、次版本是否同时存在来
   分类；只出现其中一个仍按格式错误永久拒绝。

发布提交为 `71eba405a04e55575d36fea2c66184c76fbaef6f`。现场数据库时间均为 UTC；北京时间
需要加 8 小时。
