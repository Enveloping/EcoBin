# STM32F103C8T6 MCU—香橙派固定帧串口通信协议

> 契约标识：`ecobin-mcu-fixed-frame-v2`
>
> 协议版本：`2.0.0`（fixed-frame revision 2）
>
> 状态：当前 MCU 应用与香橙派固定帧适配器的完整线路依据

## 1. 协议目标与完整性声明

本文件完整定义当前 STM32F103C8T6 MCU 应用与香橙派之间的项目自定义串口协议。
MCU 开发、香橙派适配、联调和真机验收只阅读本文件即可获得全部帧格式、字段规则、
发送时机、解析要求、异常处理和固件升级切换边界；其他文档只能提供实现记录或运维步骤，
不能替代或补充本文件中缺失的线路字节定义。

当前版本负责：

- 香橙派通知 MCU 启动投递流程；
- 香橙派通知 MCU 启动清运流程；
- 香橙派向 MCU 设置垃圾单价；
- 香橙派向 MCU 设置用于屏幕生成二维码的完整小程序跳转 URL；
- 香橙派主动读取一次重量、红外和烟雾自检快照；
- MCU 一次性上传投递前后重量和红外原始标志；
- MCU 一次性上传清运前后重量和红外原始标志；
- MCU 在烟雾状态变化时主动上传当前烟雾状态；
- 香橙派查询 MCU 当前固件版本、版本码、发布身份和执行状态；
- 香橙派在自行完成升级准入判断后，命令 MCU 停止输出并锁存远程升级执行状态。

当前版本不包含：

- 校验和或 CRC；
- 通用 ACK/NACK 确认；
- URL 接收结果或二维码显示结果应答；
- 投递、清运等业务命令的线路执行状态；
- 推杆位置或输出状态的独立主动上报；
- 清运门门磁或门位上报；
- 除“烟感数据无法获取”以外的详细传感器故障原因；
- 业务流程编号、命令身份或消息序号；
- 协议级自动重发和断电作业恢复。

### 1.1 revision 兼容关系

- revision 2 是当前完整协议，包含本文件全部业务帧、传感器帧、URL 帧以及 F2/F3。
- 已部署的 revision 1 MCU 不响应 F2，也不能形成 revision 2 固件身份和远程升级准备事实；
  收到 F2 时不得把其他帧误作应答。
- revision 1 设备首次迁移到 revision 2 只能通过受控本地维护完成。迁移并复位后，香橙派
  必须使用 `F2 01 F2` 和成功 F3 重新登记身份，之后才允许参加云端自动升级。
- F2/F3 的加入不改变 AA、BB、CC、DD、EE、EF、F0、F1 和 A0 的字节格式或业务含义。

### 1.2 固件升级职责边界

固件升级任务的准入和生命周期状态机只属于香橙派。香橙派收到平台升级命令时，以本地
SQLite 中的维护锁、唯一工作槽和未决物理命令为事实来源，在一个事务内完成以下选择：

- 已有维护任务、正在投递/清运，或存在其他执行中的物理命令时，记录并可靠上报本次升级
  `REJECTED`，不向 MCU 发送 `F2 02 F2`，也不阻止这些既有业务继续收敛；
- 本地空闲时，同时创建 `QUEUED` 升级记录并取得维护锁。从这一刻起，香橙派阻止新的
  投递、清运和其他物理命令，随后自行推进取包、验签、预检、擦写、验证、回滚和终态。

香橙派在发送 `F2 02 F2` 前，必须先将本次 F3 查到的升级前固件版本码、版本文本、
8 字节发布身份和协议修订号持久化，同时标记“F2 从此可能已执行”。该标记跨进程重启
保留；它存在时，香橙派只有在复位 MCU、重新核对这份固件身份并通过 F1 自检后才能
记录 `REJECTED` 和解除维护锁，否则必须进入 `FAILED_LOCKED` 继续阻止业务。

MCU 不读取也不裁决这些香橙派业务事实。收到 `F2 02 F2` 只表示香橙派已经准入；MCU 必须
执行“锁存升级执行状态、终止本地投递/清运/称重活动、关闭推杆与电磁锁输出”，再用 F3
报告执行结果。F3 是执行结果，不是 MCU 对升级是否获准的第二次投票。这里不改变 MCU 已有
的投递、清运和屏幕状态机边界，只调整固件升级任务的决策归属。

## 2. 串口参数与运行模式

MCU 正常应用运行时固定使用：

| 参数 | 值 |
|---|---|
| 波特率 | `115200 baud` |
| 数据位 | `8` |
| 停止位 | `1` |
| 校验位 | 无 |
| 流控 | 无 |
| 简写 | `115200/8N1` |

远程擦写时，香橙派先完成本地业务准入，再通过本文件定义的 F2/F3 命令 MCU 停止输出并
确认执行结果，然后关闭正常应用串口，
通过 BOOT0 和 RESET 让 STM32 进入芯片内置的系统 ROM Bootloader，并把同一 UART 临时切换
为 `115200/8E1`。擦写期间不得发送或解析本文件的 AA～F3 应用帧；正常应用串口和 ROM
Bootloader 串口不得同时打开。擦写完成并复位回应用后，香橙派重新使用 `115200/8N1`，
再通过 F2/F3 和 F0/F1 验证新固件身份与传感器通信。

STM32 系统 ROM Bootloader 是芯片内置的厂商协议，当前由香橙派上的 `stm32flash` 执行；
它不是本项目自定义固定帧的一部分。本文件已经写全 MCU 应用需要实现的全部自定义帧。

## 3. 数据编码规则

### 3.1 十六进制原始字节

  所有通信内容均为原始十六进制字节，不发送十六进制字符串。

  例如：

  AA 01 AA

  串口实际发送3个字节：

  0xAA 0x01 0xAA

  不能发送以下 ASCII 字符：

  "A", "A", " ", "0", "1", " ", "A", "A"

  协议文档中的空格只用于方便阅读，不会通过串口发送。

### 3.2 帧格式

  保持原有通信风格：

  帧头 + 数据字段 + 帧尾

  每种报文的帧头和帧尾使用相同字节。

  例如：

  DD + 投递数据 + DD
  EF + 清运数据 + EF

### 3.3 多字节数据顺序

  重量采用3字节无符号整数，高字节在前：

  WEIGHT_H WEIGHT_M WEIGHT_L

  重量计算公式：

  重量（克） =
  WEIGHT_H × 65536
  + WEIGHT_M × 256
  + WEIGHT_L

  例如：

  00 01 1C = 284克
  00 2E E0 = 12000克
  05 57 30 = 350000克

  注意：

  01 3C = 316克
  01 1C = 284克

### 3.4 URL 字节编码

  小程序跳转 URL 使用 ASCII 字节发送，不发送以十六进制表示的字符串，也不发送
  字符串结束符。

  URL 必须满足：

  - 是完整的 HTTPS 地址；
  - 实际长度为1～192个 ASCII 字节；
  - 不包含空格、中文或其他非 ASCII 字符；
  - `LEN` 表示实际 URL 字节数，不包含后续补齐的 `00`。

  URL 数据区固定占192字节。实际 URL 后剩余的字节全部填 `00`，MCU 只读取前
  `LEN` 个字节，不能把补齐字节作为 URL 内容。

### 3.5 固件版本与发布身份编码

- `VERSION_CODE_BE` 是 4 字节无符号大端整数，合法范围为 `1..4294967295`；发布新版本时
  必须单调增加。
- `VERSION_ASCII[32]` 是固定 32 字节区域；前 `VERSION_LEN` 字节为可打印 ASCII
  `0x21..0x7E`，其余字节必须全部为 `00`。
- `VERSION_LEN` 的线路合法范围是 `1..32`。要形成云端 revision 2 准入事实，当前版本文本
  还必须满足 5～32 字节；不满足时仍可解析 F3，但不得作为可信固件身份上报。
- `FIRMWARE_IDENTITY[8]` 是固件发布身份的原始 8 字节。打包工具使用发布 UID 的 SHA-256
  前 8 字节生成该值；F3 中的 8 字节必须与签名固件 Manifest 的
  `firmwareIdentityHex` 一致，且不得全部为 `00`。

## 4. 重量字段定义

  重量单位统一为克。

  每个重量占3字节：

  WEIGHT_H WEIGHT_M WEIGHT_L

  有效范围：

  00 00 00 ～ 05 57 30

  对应：

  0克 ～ 350000克

  也就是最大350千克。

  DD/EF 结果帧不定义称重失败、超载和重量无效标志。MCU 应当在获得稳定、有效的重量后
  再发送结果帧。只读自检 F1 可以通过 `VALID.bit0=0` 明确表示当前重量采样无效。

---

## 5. 红外原始标志定义

  `FULL` 字段占1字节，表示单片机采集到的红外遮挡原始结果：

| 十六进制值 | 含义       |
| ---------- | ---------- |
| 00         | 红外未遮挡 |
| 01         | 红外被遮挡 |

  `FULL` 不是最终业务满溢结论，香橙派和后端不得仅凭该字段认定设备实际满溢。

  最终业务满溢状态由既有业务链路按照后端下发并由香橙派本地保存的判断标准，
  结合 `FULL` 红外结果、结果帧中的流程后总重量及其他已配置条件计算。

  当前 MCU 协议不接收业务满溢阈值或判断配置，这些配置暂时只保存在香橙派本地。

  投递结果中的 `FULL` 表示投递完成后采集的红外状态。

  清运结果中的 `FULL` 表示清运完成后采集的红外状态。

  当前版本不会在红外状态发生变化时单独主动发送消息。红外状态只随 DD/EF 结果上传，
  或在香橙派发送 F0 后随 F1 查询应答返回。

## 6. 香橙派发送给 MCU

### 6.1 启动投递流程

#### 帧格式

  AA CMD AA

  固定长度：3字节。

  字段定义：

| 字段 | 长度  | 含义         |
| ---- | ----- | ------------ |
| AA   | 1字节 | 投递命令帧头 |
| CMD  | 1字节 | 投递流程命令 |
| AA   | 1字节 | 投递命令帧尾 |

  命令定义：

| CMD  | 含义             |
| ---- | ---------------- |
| 01   | 启动一次投递流程 |

  完整命令：

  AA 01 AA

#### 执行含义

  收到该命令后，单片机自行启动完整投递流程。

  该命令仅表示：

  开始一次投递流程

  不表示：

  直接打开推杆

  也不表示：

  直接关闭推杆

  推杆、屏幕、限位开关、称重和流程控制均由单片机自行处理。

#### 投递流程

  1. 单片机收到：

  AA 01 AA

  2. 单片机测量并保存本次流程最初的投递前重量。
  3. 单片机按照自身程序打开投递口。
  4. 用户完成投递。
  5. 单片机通过屏幕让用户选择：

  继续投递
  结束投递

  6. 如果用户选择“继续投递”：

  - 单片机继续执行下一次开盖和投递；
  - 不向香橙派发送重量结果；
  - 不得覆盖本次流程最初保存的投递前重量。

  7. 如果用户选择“结束投递”：

  - 单片机关闭投递口；
  - 等待重量稳定；
  - 测量投递结束后的总重量；
  - 采集投递完成后的红外原始状态；
  - 向香橙派发送一次投递结果帧。

  同一次流程无论用户继续投递多少次，最终只发送一个投递结果帧。

#### 限制

  当前协议没有确认帧和流程编号，因此香橙派发送一次 AA 01 AA 后，不应因为没有收到立即响应而自动重复发送，否则可能重复启动投递流程。

### 6.2 设置垃圾单价

#### 帧格式

  BB PRICE BB

  固定长度：3字节。

  字段定义：

| 字段  | 长度  | 含义     |
| ----- | ----- | -------- |
| BB    | 1字节 | 单价帧头 |
| PRICE | 1字节 | 垃圾单价 |
| BB    | 1字节 | 单价帧尾 |

  PRICE 有效范围：

  00 ～ 09

  每增加 01，表示增加：

  0.1元/千克

  对应关系：

| PRICE | 单价       |
| ----- | ---------- |
| 00    | 0.0元/千克 |
| 01    | 0.1元/千克 |
| 02    | 0.2元/千克 |
| 03    | 0.3元/千克 |
| 04    | 0.4元/千克 |
| 05    | 0.5元/千克 |
| 06    | 0.6元/千克 |
| 07    | 0.7元/千克 |
| 08    | 0.8元/千克 |
| 09    | 0.9元/千克 |

  例如，设置单价为 0.4元/千克：

  BB 04 BB

  香橙派收到的业务单价使用“元/千克的万分位整数”保存，发送给 MCU 时按以下规则
  生成 `PRICE`：

  PRICE = min(业务单价万分位整数 // 1000, 9)

  即先向下截断到一位小数，再将超过 0.9元/千克的屏显值饱和为 `09`。例如业务
  单价 0.45元/千克发送 `BB 04 BB`，业务单价 1.20元/千克发送 `BB 09 BB`。

  后端仍使用未截断的原始业务单价计算返现金额，因此 MCU 屏显单价允许与实际返现
  单价不一致。

  单价可以在设备启动时发送，也可以在单价发生变化时重新发送。

  当前协议不要求单片机回复单价接收结果。

### 6.3 启动清运流程

#### 帧格式

  EE CMD EE

  固定长度：3字节。

  字段定义：

| 字段 | 长度  | 含义         |
| ---- | ----- | ------------ |
| EE   | 1字节 | 清运命令帧头 |
| CMD  | 1字节 | 清运流程命令 |
| EE   | 1字节 | 清运命令帧尾 |

  命令定义：

| CMD  | 含义             |
| ---- | ---------------- |
| 01   | 启动一次清运流程 |

  完整命令：

  EE 01 EE

#### 执行含义

  该命令仅通知单片机：

  开始一次清运流程

  该命令不直接表示继电器保持通电，也不要求香橙派控制继电器断电。

  清运门继电器的具体控制逻辑全部由单片机负责。

#### 清运流程

  1. 单片机收到：

  EE 01 EE

  2. 单片机测量并保存清运前总重量。
  3. 单片机给清运门继电器通电。
  4. 经过3～5秒后，单片机必须自动断开继电器。
  5. 继电器断开后，清运门由工作人员进行操作。
  6. 工作人员取出旧垃圾袋并更换新垃圾袋。
  7. 工作人员关闭清运门。
  8. 工作人员通过单片机屏幕确认清运完成。
  9. 单片机等待重量稳定。
  10. 单片机测量清运后总重量。
  11. 单片机采集清运完成后的红外原始状态。
  12. 单片机发送一次清运结果帧。

  香橙派不再发送以下命令：

  EE 00 EE

  继电器断电必须由单片机自身的定时逻辑完成，避免继电器或门锁长时间通电造成损坏。

#### 钥匙开门

  工作人员仍可以使用机械钥匙打开清运门。

  如果希望钥匙清运也形成正式清运记录，应当先由工作人员通过小程序启动清运，使香橙派发送：

  EE 01 EE

  之后工作人员可以使用钥匙完成实际开门。

  如果完全使用钥匙开门，并且没有发送 EE 01 EE，单片机没有保存清运前重量，因此不应发送正式的 EF 清运结果帧。

#### 限制

  当前协议没有确认帧和流程编号，因此香橙派发送一次 EE 01 EE 后，不应自动重复发送。

### 6.4 获取一次传感器自检快照

#### 帧格式

  F0 CMD F0

  固定长度：3字节。

  字段定义：

| 字段 | 长度  | 含义         |
| ---- | ----- | ------------ |
| F0   | 1字节 | 自检查询帧头 |
| CMD  | 1字节 | 自检查询命令 |
| F0   | 1字节 | 自检查询帧尾 |

  命令定义：

| CMD  | 含义                   |
| ---- | ---------------------- |
| 01   | 返回当前传感器自检快照 |

  完整命令：

  F0 01 F0

#### 执行含义

  该命令是只读查询，只要求单片机返回当前重量、红外和烟雾状态，不启动投递、清运、
  推杆、继电器或其他机械动作。同一条查询既可以用于机器自检，也可以用于平台已经
  明确确认空袋后的皮重测量；两种情况使用完全相同的 F0/F1 帧，不增加新的协议命令。

  单片机收到命令后，应使用当前或最近一次稳定采样，在3秒内发送一帧 F1 自检应答。
  如果当前没有有效的重量或红外采样，应通过 F1 的 `VALID` 位明确表示无效，不能为了
  通过自检而伪造数值。

#### 发送时机和限制

  香橙派在以下情况下发送：

  - 香橙派启动并成功打开串口后；
  - 平台每次发起机器验收时。
  - 平台发起空袋皮重测量，并且命令中的 `emptyBagConfirmed=true` 时。

  每次自检或皮重测量只发送一次 F0 01 F0，不立即重试。F0 是可重复执行的只读查询，
  但它不是通用 ACK，也不能用于判断投递或清运命令是否执行。皮重测量只能使用本次
  F0 查询之后收到的 F1；禁止复用启动自检、历史投递或历史清运留下的重量。

### 6.5 设置小程序跳转 URL

#### 帧格式

  A0 LEN URL_DATA[192] A0

  固定长度：195字节。

  字段定义：

| 字段          | 长度    | 含义                         |
| ------------- | ------- | ---------------------------- |
| A0            | 1字节   | URL 设置帧头                 |
| LEN           | 1字节   | 实际 URL 的 ASCII 字节数     |
| URL_DATA[192] | 192字节 | URL 内容以及尾部 `00` 补齐区 |
| A0            | 1字节   | URL 设置帧尾                 |

  `LEN` 有效范围为 `01`～`C0`，十六进制 `C0` 等于十进制192。

  例如，实际 URL 为：

  https://www.jinshoubao.com/device-entry/?deviceCode=Dv_example

  香橙派应当：

  1. 将完整 URL 编码为 ASCII 字节；
  2. 将实际字节数写入 `LEN`；
  3. 将 URL 字节放入192字节数据区开头；
  4. 将数据区剩余位置全部填 `00`；
  5. 在报文首尾分别写入 `A0`。

#### MCU 处理要求

  MCU 收到完整且字段合法的报文后：

  - 读取前 `LEN` 个 URL 字节；
  - 用新 URL 替换当前内存中的旧 URL；
  - 立即使用完整 URL 生成并显示二维码；
  - 不向香橙派发送 ACK、NACK、URL 接收结果或二维码显示结果。

  如果帧尾不等于 `A0`、`LEN` 不在合法范围内、URL 数据不是合法 ASCII HTTPS
  地址，MCU 应忽略整帧并保留当前 URL，也不发送错误应答。

  MCU 当前不要求把 URL 写入自身 Flash，也不增加 MCU 启动通知或 URL 查询机制。
  MCU 单独重启而香橙派没有重启时，下一次空闲定时刷新可以重新写入 URL；由于没有
  MCU 应答，这仍不是二维码已经恢复显示的证明。

#### 香橙派保存和发送时机

  香橙派必须先把后端下发的 URL 可靠保存到本地 SQLite，再向 MCU 发送本报文。

  香橙派在以下情况下向 MCU 发送：

  - 平台机器验收命令携带新的 URL，并且香橙派已经保存成功；
  - 后端全局小程序基础跳转地址改变，香橙派收到并保存新的 URL；
  - 香橙派启动或串口重新打开后，本地已经存在保存成功的 URL；
  - 固定帧模式运行期间没有投递或清运作业占用，并且距离上次定时发送已达到配置周期。

  定时周期默认 60 秒，由 `ECOBIN_DEVICE_ENTRY_URL_REFRESH_SECONDS` 配置。定时发送
  复用香橙派现有命令消费者线程，不与物理命令并发；投递或清运进行中暂停并每 5 秒
  复查，工作槽释放后恢复。串口关闭或本地写入失败时也在 5 秒后重试。

  每次触发只发送一帧，不等待 MCU 应答。串口写入是否成功、MCU 是否生成二维码以及
  屏幕是否显示，都不作为平台机器验收条件。平台只验证香橙派是否保存了后端期望的
  URL 及其摘要。当前定时发送的是同一个静态公开 URL，不能防止截图或远距离扫码；
  未来若发送带时间信息的动态 URL，必须同时包含后端可验证的短期签名，裸时间戳不能
  防伪或防重放，且完整 URL 仍须满足 ASCII 和最多 192 字节限制。

### 6.6 查询固件身份或命令执行升级准备

#### 帧格式

```text
F2 CMD F2
```

固定长度：3 字节。

| 字段 | 长度 | 含义 |
|---|---:|---|
| `F2` | 1 字节 | 固件查询帧头 |
| `CMD` | 1 字节 | 查询模式 |
| `F2` | 1 字节 | 固件查询帧尾 |

`CMD` 定义：

| CMD | 名称 | 含义 |
|---|---|---|
| `01` | 查询身份 | 只读查询当前固件身份和执行状态，不改变 MCU 业务状态 |
| `02` | 执行升级准备 | 香橙派已完成准入，命令 MCU 停止输出并锁存升级执行状态 |

其他 `CMD` 均非法，MCU 应忽略整帧，不发送猜测性应答。

#### `CMD=01` 查询身份

香橙派在启动、受控本地升级完成后以及需要重新证明当前固件身份时发送：

```text
F2 01 F2
```

MCU 应在 3 秒内返回一帧 `MODE=01` 的 F3。该查询不得启动或停止投递、清运、称重、
推杆、继电器或屏幕业务流程。只有 F3 同时满足 `STATUS=00`、`PROTOCOL_REV=02`、
版本字段合法且发布身份非全零时，香橙派才可以把它作为 revision 2 固件身份事实。

#### `CMD=02` 执行升级准备

远程擦写前，香橙派发送：

```text
F2 02 F2
```

发送前，香橙派必须已经完成 1.2 节的本地准入并持有升级维护锁。MCU 收到命令后不得再按
投递、清运、称重或输出状态否决升级，而必须按以下固定顺序执行：

1. 先锁存升级执行状态，阻止后续本地输入重新启动执行器；
2. 终止 MCU 内存中的投递、清运和称重活动，清除清运计时；
3. 把推杆方向设为停止，关闭两个推杆继电器和清运电磁锁输出，并丢弃待处理屏幕输入；
4. 从执行后的真实状态生成 `SAFE_FLAGS`。全部五位成立时返回
   `MODE=02 + STATUS=00 + SAFE_FLAGS=1F`；内部执行结果不完整时返回 `STATUS=03` 和实际位。

该命令是幂等的；重复执行仍应保持全部活动停止、输出关闭和升级状态锁存。当前 revision 2
MCU 不得用 `STATUS=01/02` 表示忙碌或不安全，因为是否发出本命令已经由香橙派决定。

升级执行状态成功锁存后，MCU 必须忽略新的投递、清运、称重和执行器启动输入，直至 MCU
复位。香橙派只有收到与本次 `CMD=02` 匹配、结构合法且
`STATUS=00 + SAFE_FLAGS=1F` 的 F3，才允许关闭应用串口并切换到 ROM Bootloader。
超时、错模式、坏帧或任何非零状态都禁止开始擦写；由于 MCU 可能已经执行但应答丢失，
香橙派必须先复位回原应用并重新验证原固件身份和 F1 自检，确认恢复后才能记录
`REJECTED` 并解除维护锁，无法确认恢复则进入 `FAILED_LOCKED` 并继续阻止业务。

每次查询只发送一帧 F2，并等待与 `CMD` 相同模式的第一帧合法 F3。F2/F3 不是通用
ACK，不确认 AA、BB、EE、A0 或其他业务帧。

## 7. MCU 发送给香橙派

### 7.1 投递完成上报

#### 帧格式

  DD
  + 投递前重量
  + 投递后重量
  + 红外原始标志
  + DD

  完整字段格式：

  DD PRE_H PRE_M PRE_L POST_H POST_M POST_L FULL DD

  固定长度：9字节。

  字段定义：

| 字段   | 长度  | 含义                     |
| ------ | ----- | ------------------------ |
| DD     | 1字节 | 投递结果帧头             |
| PRE_H  | 1字节 | 投递前重量高字节         |
| PRE_M  | 1字节 | 投递前重量中字节         |
| PRE_L  | 1字节 | 投递前重量低字节         |
| POST_H | 1字节 | 投递后重量高字节         |
| POST_M | 1字节 | 投递后重量中字节         |
| POST_L | 1字节 | 投递后重量低字节         |
| FULL   | 1字节 | 投递完成后的红外原始标志 |
| DD     | 1字节 | 投递结果帧尾             |

#### 发送时机

  只有在用户点击“结束投递”后发送。

  用户点击“继续投递”时不发送。

  一次完整投递流程只发送一次。

#### 示例

  投递前重量：

  12000克 = 00 2E E0

  投递后重量：

  12284克 = 00 2F FC

  投递完成后红外被遮挡：

  FULL = 01

  发送：

  DD 00 2E E0 00 2F FC 01 DD

  香橙派计算：

  投递净重
  = 投递后重量 - 投递前重量
  = 12284 - 12000
  = 284克

  红外原始状态：

  01 = 红外被遮挡

#### 净重处理原则

  单片机只负责上传真实的前后总重量。

  单片机不需要计算投递净重，也不要把重量减少强制处理成零。

  香橙派根据前后重量进行计算：

  NET_WEIGHT = POST_WEIGHT - PRE_WEIGHT

  如果投递后重量小于投递前重量，香橙派仍保留真实的负净重，不强制归零。当前
  适配版本的 `negativeWeightAnomaly` 暂时固定为 `false`，不因此阻断投递完成；
  后续异常处理由业务规则另行定义。

### 7.2 清运完成上报

#### 帧格式

  EF
  + 清运前重量
  + 清运后重量
  + 红外原始标志
  + EF

  完整字段格式：

  EF PRE_H PRE_M PRE_L POST_H POST_M POST_L FULL EF

  固定长度：9字节。

  字段定义：

| 字段   | 长度  | 含义                     |
| ------ | ----- | ------------------------ |
| EF     | 1字节 | 清运结果帧头             |
| PRE_H  | 1字节 | 清运前重量高字节         |
| PRE_M  | 1字节 | 清运前重量中字节         |
| PRE_L  | 1字节 | 清运前重量低字节         |
| POST_H | 1字节 | 清运后重量高字节         |
| POST_M | 1字节 | 清运后重量中字节         |
| POST_L | 1字节 | 清运后重量低字节         |
| FULL   | 1字节 | 清运完成后的红外原始标志 |
| EF     | 1字节 | 清运结果帧尾             |

#### 发送时机

  只有满足以下条件后才发送：

  - 已经通过 EE 01 EE 启动清运流程；
  - 已保存清运前重量；
  - 继电器已经自动断电；
  - 工作人员已经完成垃圾袋更换；
  - 工作人员已经关闭清运门；
  - 工作人员已在单片机屏幕确认清运完成；
  - 单片机已获得稳定的清运后重量；
  - 单片机已采集清运后的红外原始状态。

  一次清运流程只发送一次。

#### 示例

  清运前重量：

  100000克 = 01 86 A0

  清运后重量：

  50000克 = 00 C3 50

  清运完成后红外未遮挡：

  FULL = 00

  发送：

  EF 01 86 A0 00 C3 50 00 EF

  香橙派计算：

  清运减少重量
  = 清运前重量 - 清运后重量
  = 100000 - 50000
  = 50000克

  红外原始状态：

  00 = 红外未遮挡

### 7.3 传感器自检快照应答

#### 帧格式

  F1 VALID WEIGHT_H WEIGHT_M WEIGHT_L FULL SMOKE F1

  固定长度：8字节。

  字段定义：

| 字段     | 长度  | 含义                 |
| -------- | ----- | -------------------- |
| F1       | 1字节 | 自检应答帧头         |
| VALID    | 1字节 | 重量和红外采样有效位 |
| WEIGHT_H | 1字节 | 当前稳定重量高字节   |
| WEIGHT_M | 1字节 | 当前稳定重量中字节   |
| WEIGHT_L | 1字节 | 当前稳定重量低字节   |
| FULL     | 1字节 | 当前红外原始标志     |
| SMOKE    | 1字节 | 当前烟雾读取结果     |
| F1       | 1字节 | 自检应答帧尾         |

  `VALID` 是位标志：

| 位      | 值为1时的含义     |
| ------- | ----------------- |
| bit0    | 重量采样有效      |
| bit1    | 红外采样有效      |
| bit2～7 | 必须为0，暂不定义 |

  重量和红外均有效时，`VALID` 为 03。

  如果重量无效，bit0 必须为0，三个重量字节填 00 00 00；如果红外无效，bit1 必须
  为0，`FULL` 填 00。香橙派只在对应有效位为1时使用该字段。

  `SMOKE` 定义：

   SMOKE    含义

| 值   | 含义                     |
| ---- | ------------------------ |
| 00   | 成功读取烟感，未触发报警 |
| 01   | 成功读取烟感，已触发报警 |
| 02   | 单片机无法获取烟感数据   |

  03～FF 均为非法值。`02` 只表示单片机仍能通信，但无法读取烟雾报警器；如果香橙派
  完全收不到 F1，那是串口或 MCU 通信超时，香橙派不能自行伪造成 `02`。

#### 示例

  当前重量12000克、红外未遮挡、烟雾未触发，重量和红外均有效：

  F1 03 00 2E E0 00 00 F1

  当前重量和红外有效，但单片机无法获取烟感数据：

  F1 03 00 2E E0 00 02 F1

#### 验收含义

  收到结构和字段都合法的 F1，可以证明本次香橙派与 MCU 通信成功。机器验收还必须
  同时满足：重量和红外有效、重量范围合法、烟雾为 00。烟雾为 01 表示设备当前处于
  报警环境，烟雾为 02 表示烟感不可用；这两种情况都不能通过机器验收。

  当 F1 用于空袋皮重测量时，香橙派只在 `VALID.bit0=1` 且重量范围合法时把本次重量
  作为稳定皮重上报。红外和烟雾字段仍照常更新设备状态，但不改变这次重量事实；安全
  状态是否允许后续投递或清运，由香橙派和平台按各自安全规则另行判断。如果 F1 超时、
  格式错误或重量无效，本次皮重测量必须明确失败，不能回退到历史重量或 0 克。

### 7.4 烟雾状态变化主动上报

#### 帧格式

  CC SMOKE CC

  固定长度：3字节。

  完整报文：

| 报文     | 含义                   |
| -------- | ---------------------- |
| CC 00 CC | 烟感可读，当前未触发   |
| CC 01 CC | 烟感可读，当前已经触发 |
| CC 02 CC | 当前无法获取烟感数据   |

#### 发送时机

  单片机在 00、01、02 三种稳定状态之间发生变化时发送一次，包括报警、报警恢复、
  读取失败和读取恢复。相同状态没有变化时不周期发送。

  香橙派发送 F0 01 F0 时，当前烟雾状态已经包含在 F1 中，单片机不再重复发送 CC。
  如果烟雾状态恰好在生成 F1 时变化，单片机应先完整发送 F1，再发送包含最新状态的
  CC；两个报文的字节不能交叉。

#### 安全边界

  烟雾报警时，单片机必须立即执行自身已有的本地安全保护。CC 上报用于通知香橙派和
  平台，不能把本地安全动作交给 OneNet 或后端完成。

### 7.5 固件身份与升级准备执行结果应答

#### 帧格式

```text
F3 MODE STATUS PROTOCOL_REV VERSION_CODE_BE[4] VERSION_LEN
   VERSION_ASCII[32] FIRMWARE_IDENTITY[8] SAFE_FLAGS F3
```

固定长度：51 字节。逐字节偏移如下，偏移从 0 开始：

| 偏移 | 字段 | 长度 | 规则 |
|---:|---|---:|---|
| 0 | `F3` | 1 | 固定帧头 `F3` |
| 1 | `MODE` | 1 | 必须等于触发本次应答的 F2 `CMD`：`01` 或 `02` |
| 2 | `STATUS` | 1 | 当前查询或升级准备执行结果，见下表 |
| 3 | `PROTOCOL_REV` | 1 | 固定为 `02` |
| 4～7 | `VERSION_CODE_BE` | 4 | 当前固件单调版本码，uint32 大端，不能为 0 |
| 8 | `VERSION_LEN` | 1 | 实际版本文本长度，`01..20`（十进制 1～32） |
| 9～40 | `VERSION_ASCII[32]` | 32 | 可打印 ASCII 版本文本，尾部用 `00` 补齐 |
| 41～48 | `FIRMWARE_IDENTITY[8]` | 8 | 当前固件发布身份，不得全为 `00` |
| 49 | `SAFE_FLAGS` | 1 | 当前执行结果位；字段名为兼容既有线路保留，bit5～7 必须为 0 |
| 50 | `F3` | 1 | 固定帧尾 `F3` |

`STATUS` 定义：

| STATUS | 名称 | 含义 |
|---|---|---|
| `00` | `OK` | `MODE=01` 时表示身份快照有效；`MODE=02` 时表示停止输出并锁存升级状态执行成功 |
| `01` | `LEGACY_BUSY` | 仅为修订期间旧实现保留；当前 revision 2 MCU 不得发送，香橙派按执行失败处理 |
| `02` | `LEGACY_UNSAFE` | 仅为修订期间旧实现保留；当前 revision 2 MCU 不得发送，香橙派按执行失败处理 |
| `03` | `INTERNAL_ERROR` | MCU 查询或升级准备执行发生内部失败 |

`SAFE_FLAGS` 定义：

| 位 | 掩码 | 值为 1 时的含义 |
|---|---:|---|
| bit0 | `01` | MCU 本地投递活动已终止且称重状态为空闲 |
| bit1 | `02` | MCU 本地清运活动已终止 |
| bit2 | `04` | 推杆方向为停止且两个方向输出均关闭 |
| bit3 | `08` | 清运电磁锁输出关闭 |
| bit4 | `10` | 升级执行状态已经锁存 |
| bit5～7 | `E0` | 保留位，必须全部为 0 |

`MODE=02 + STATUS=00` 时 `SAFE_FLAGS` 必须精确为 `1F`。其他状态仍应如实返回当前
执行位，但香橙派不得把部分执行位当成执行成功。`SAFE_FLAGS` 只描述 MCU 命令执行后的
结果，不表达本次升级在业务上是否获准。

#### 构造示例

假设当前固件版本为 `1.2.3`，版本码为十进制 10203（十六进制 `000027DB`），发布身份为
`01 02 03 04 05 06 07 08`，身份查询时四项机械输出安全但尚未锁存升级状态，则字段为：

```text
帧头                 F3
MODE                  01
STATUS                00
PROTOCOL_REV          02
VERSION_CODE_BE       00 00 27 DB
VERSION_LEN           05
VERSION_ASCII[32]     31 2E 32 2E 33 + 27 个 00
FIRMWARE_IDENTITY[8]  01 02 03 04 05 06 07 08
SAFE_FLAGS            0F
帧尾                 F3
```

同一固件成功进入升级准备状态后的应答把 `MODE` 改为 `02`，并把 `SAFE_FLAGS` 改为
`1F`。

#### MCU 发送与香橙派采信规则

- MCU 只在收到合法 F2 后发送一帧 F3，不周期主动发送 F3。
- F3 的 `MODE` 必须与收到的 F2 `CMD` 相同；香橙派丢弃错模式、迟到和重复 F3。
- 所有状态下都必须提供结构合法的 revision、版本码、版本文本、发布身份和安全位，不能用
  全零身份或非法字段代替错误信息。
- `STATUS=01/02/03` 是明确失败状态。即使版本字段碰巧正确，香橙派也不得把它记录为可信
  revision 2 身份，更不得据此宣布升级成功。
- `MODE=01` 只有 `STATUS=00` 且全部身份字段合法时，才能形成可信固件身份观察；用于云端
  准入时，版本文本还必须满足 5～32 字节，并与同一运行快照的固件版本一致。
- `MODE=02` 只有 `STATUS=00` 且 `SAFE_FLAGS=1F` 时才证明 MCU 已执行停止与锁存，随后是否
  切换 ROM Bootloader 仍由香橙派升级状态机决定；F3 不确认先前 AA、EE 等业务命令，也
  不得补造投递或清运完成事实。

## 8. 完整协议帧汇总

| 方向         | 功能         | 固定格式                                            | 长度  |
| ------------ | ------------ | --------------------------------------------------- | ----- |
| 香橙派 → MCU | 启动投递流程 | `AA 01 AA`                                          | 3字节 |
| 香橙派 → MCU | 设置垃圾单价 | `BB PRICE BB`                                       | 3字节 |
| 香橙派 → MCU | 启动清运流程 | `EE 01 EE`                                          | 3字节 |
| 香橙派 → MCU | 获取传感器快照 | `F0 01 F0`                                          | 3字节 |
| 香橙派 → MCU | 设置跳转 URL  | `A0 LEN URL_DATA[192] A0`                           | 195字节 |
| MCU → 香橙派 | 投递完成上报 | `DD PRE_H PRE_M PRE_L POST_H POST_M POST_L FULL DD` | 9字节 |
| MCU → 香橙派 | 清运完成上报 | `EF PRE_H PRE_M PRE_L POST_H POST_M POST_L FULL EF` | 9字节 |
| MCU → 香橙派 | 自检快照应答 | `F1 VALID WEIGHT_H WEIGHT_M WEIGHT_L FULL SMOKE F1` | 8字节 |
| MCU → 香橙派 | 烟雾变化上报 | `CC SMOKE CC`                                       | 3字节 |
| 香橙派 → MCU | 查询固件/执行升级准备 | `F2 CMD F2`                                   | 3字节 |
| MCU → 香橙派 | 固件与执行状态快照 | `F3 MODE STATUS PROTOCOL_REV VERSION_CODE_BE[4] VERSION_LEN VERSION_ASCII[32] FIRMWARE_IDENTITY[8] SAFE_FLAGS F3` | 51字节 |

香橙派额外实现的固定帧。

## 9. 接收解析要求

每种报文都是固定长度报文。接收方识别到帧头后，必须按该报文的固定长度读取，不能把
数据区中偶然出现的同值字节当作帧尾。

例如投递重量数据中可能出现：

```text
DD 00 DD 10 00 EF 20 01 DD
```

中间的 `DD` 和 `EF` 都是重量数据，真正帧尾是第 9 个字节。

| 帧头 | 固定长度 | 接收方 |
|---|---:|---|
| `AA` | 3 | MCU |
| `BB` | 3 | MCU |
| `CC` | 3 | 香橙派 |
| `DD` | 9 | 香橙派 |
| `EE` | 3 | MCU |
| `EF` | 9 | 香橙派 |
| `F0` | 3 | MCU |
| `F1` | 8 | 香橙派 |
| `F2` | 3 | MCU |
| `F3` | 51 | 香橙派 |
| `A0` | 195 | MCU |

串口一次读取可能只包含半帧、刚好一帧、多个粘连帧，或者前导噪声。双方必须使用有界
接收缓冲区逐帧解析，不能假设一次串口 `read` 等于一帧。香橙派当前接收缓冲上限为
4096 字节；超过上限时丢弃最旧字节并重新同步。

候选帧必须同时通过以下检查：

1. 首尾字节等于该帧类型规定的同一个值；
2. 总长度精确等于固定长度；
3. CMD、状态、有效位、保留位、重量、ASCII、补零和枚举值满足对应章节约束；
4. F1/F3 查询应答必须发生在本次查询之后，F3 `MODE` 还必须匹配本次 F2 `CMD`；
5. DD/EF 必须能够绑定香橙派当前唯一活动且类型匹配的本地工作。

无效候选帧从当前疑似帧头后的下一个字节继续搜索，不能丢弃整个缓冲区。香橙派发送
F0 或 F2 前会排除旧的同类应答，错模式、迟到、重复或无法安全归属的结果只能隔离，
不能生成业务完成或升级成功事实。

## 10. 完整交互时序与恢复边界

### 10.1 启动和自检

1. 香橙派以 `115200/8N1` 打开串口。
2. 本地已经保存 URL 时，香橙派可以发送一帧 A0 重新刷新 MCU 内存和屏幕。
3. 香橙派发送 `F0 01 F0`，等待一帧新 F1；合法 F1 证明本次串口通信，但重量、红外和
   烟感仍分别按其字段判断健康。
4. 自检通信成立后，香橙派发送 `F2 01 F2`，等待 `MODE=01` 的 F3；只有成功且完整的
   revision 2 身份才可以向云端登记。
5. 自检或身份查询失败时不得伪造正常值；香橙派保持降级或不具备远程升级资格。

### 10.2 投递

1. 香橙派在本地可靠保存并取得唯一工作槽后，依次完整写出 `BB PRICE BB` 和
   `AA 01 AA`；两帧在当前实现中一次串口写入，但仍按两个独立固定帧解释。
2. MCU 保存整场首次重量并自行控制屏幕、推杆和用户继续/结束选择。
3. 用户选择继续时不发送中间结果，也不覆盖最初重量。
4. 用户最终结束并取得稳定重量后，MCU 发送一次 DD。
5. 香橙派只把能够绑定当前唯一活动投递的 DD 转换为投递完成事实。

AA/BB 没有 ACK。香橙派不得因为暂时没有 DD 而重发 AA 或 BB。

### 10.3 清运

1. 香橙派在本地可靠保存并取得唯一工作槽后完整写出一次 `EE 01 EE`。
2. MCU 保存清运前重量，短时给电磁锁继电器通电并在 3～5 秒后自行断电。
3. 工作人员换袋、手动关门并在 MCU 屏幕确认完成。
4. MCU 取得稳定清运后重量和红外状态后发送一次 EF。
5. 香橙派只把能够绑定当前唯一活动清运的 EF 转换为清运完成事实。

EE 没有 ACK，香橙派不得自动重发。协议不再使用 `EE 00 EE`；继电器断电责任在 MCU。

### 10.4 URL 刷新

香橙派先把 URL 可靠保存到 SQLite，再在启动、串口重开、地址变更或空闲定时周期发送
A0。投递或清运占用期间暂停定时发送。A0 没有应答，因此串口写出不能证明 MCU 已经
生成或显示二维码。

### 10.5 远程固件升级

1. 香橙派收到平台升级命令后检查本地维护锁、工作槽和未决物理命令。忙碌时由香橙派记录
   并上报 `REJECTED`，不发送 F2；空闲时原子创建升级记录和维护锁，阻止新业务进入。
2. 香橙派完成取包、验签、目标身份和版本预检，再把当前 F3 身份快照与“F2 可能已执行”
   标记持久化，成功后才发送 `F2 02 F2`。
3. MCU 无条件执行停止本地活动、关闭输出和锁存升级状态，返回执行后的 F3。只有
   `MODE=02 + STATUS=00 + SAFE_FLAGS=1F` 才证明执行成功；其他应答或超时均禁止本次擦写。
4. 香橙派关闭 `115200/8N1` 应用串口，通过 BOOT0/RESET 进入 STM32 系统 ROM
   Bootloader，以 `115200/8E1` 擦写并校验目标镜像。
5. 香橙派复位 MCU 回到应用，重新打开 `115200/8N1`。
6. 香橙派发送 `F2 01 F2`，要求 F3 的版本文本、版本码和 8 字节发布身份与目标 Manifest
   完全一致，并且 `STATUS=00`。
7. 香橙派再发送 `F0 01 F0`，要求本次 F1 能证明 MCU 通信和传感器快照符合升级后验证
   条件；两项都成立才记录升级成功。

F3 明确返回非零 `STATUS`、身份不一致或传感器验证失败都不能判为成功。F2 执行失败、应答
不确定、`PREPARED` 写库失败或香橙派在两步之间重启时，香橙派先复位并重新证明原应用恢复，
不能直接解除维护锁。需要回滚时重复同一
执行准备、ROM Bootloader 擦写和 F3/F1 验证流程，只是目标换为上一稳定固件。

### 10.6 掉线、重启和迟到帧

- 物理启动命令最多发送一次；线路无 ACK 时不能靠重发补偿。
- 香橙派重启后不恢复或重放投递、清运命令，不伪造 DD/EF；未决工作按明确失败或人工
  恢复处理。
- 固定帧没有 MCU 启动代际、业务作业身份或通用作业状态查询。迟到、重复、类型不匹配
  或无活动工作可绑定的 DD/EF 必须隔离。
- F0/F1 只查询传感器，F2/F3 只查询固件身份或执行升级准备；两者都不能查询或恢复投递、
  清运作业。
- MCU 状态、门位和未定义传感器事实保持 `UNKNOWN`、`NOT_SAMPLED` 或明确不支持，
  不得用 0、成功或历史缓存冒充当前事实。

## 11. 当前香橙派适配边界

  - 当前固定帧协议只支持一个物理投口，对外固定为 `portNo=1`。
  - 后端下发的设备配置完整保存到香橙派本地并报告本地生效，但不发送给 MCU。
  - MCU 尚不支持的远程控制直接返回失败或 `MCU_FEATURE_NOT_SUPPORTED`，并且不得
    占用工作槽。
  - MCU 提供当前重量、红外、烟雾的只读自检快照，以及有限的固件身份和升级执行位；
    它仍不提供门位、活动作业、配置版本或待确认事件等通用状态查询。
  - 烟感在线路上只有 00、01、02 三种结果；02 不能进一步区分断线、传感器自身故障、
    MCU 驱动错误或其他读取失败原因。
  - 启动投递和启动清运命令均只发送一次，不自动重发。
  - 小程序跳转 URL 由香橙派可靠保存；验收或全局地址变化时保存并发送，香橙派启动、
    串口重新打开以及固定帧空闲运行期间按默认 60 秒周期从本地读取并发送。投递或清运
    占用工作槽时暂停，MCU 不应答，屏幕结果不进入平台验收。
  - 香橙派重启后不重放未决物理命令，也不伪造 DD/EF 完成结果；未决命令标记失败
    并释放本地工作槽。
  - 后续 MCU 增加功能时在适配层逐项接入，不修改香橙派与 OneNet、后端之间的既有
    业务协议。

### 11.1 兼容层能力声明

  本协议是当前 MCU 与香橙派之间已经协商确定的线路协议，不是香橙派—OneNet—后端
  完整业务契约的等价实现。香橙派继续接收和保存完整云端契约，是为了让后续 MCU
  能力可以逐项补齐；当前不得据此宣称对应硬件功能已经可用。

  - “配置已本地生效”只表示配置已经可靠保存到香橙派，不表示 MCU 已接收或应用。
  - “串口写入成功”只表示操作系统接受了字节，不表示 MCU 已完成开门、清运或其他动作。
  - 不存在对应固定帧的远程控制必须返回失败/不支持，不能先返回成功等待未来实现。
  - 状态接口中的 `UNKNOWN`、`NOT_SAMPLED` 是真实的“协议不可观测”，不是传感器正常值。
  - DD/EF 的满溢字节仅代表 MCU 红外观测；香橙派仍按已下发并本地保存的业务判断标准
    形成实际满溢结论。
  - 协议不提供 ACK、CRC、流程编号或通用状态查询。F0/F1 只读取传感器快照，不提供
    MCU 作业恢复。香橙派只发送一次启动命令；掉线或重启后不重发、不恢复 MCU 物理
    流程，并把未决本地工作置失败后释放工作槽。
  - F1/CC 只补充当前传感器快照和烟雾变化；DD/EF 仍只提供最终重量和红外结果，无法
    产生规范协议中的中间称重、门状态或按钮事实。
  - 单价在线路上允许截断/饱和，后端返现继续使用原业务单价，因此两者允许不一致。

本文件已经完整定义线路协议本身。代码映射、降级矩阵或测试报告只用于追踪实现证据，
不包含 MCU 还需要另行实现的隐藏帧或字段。
