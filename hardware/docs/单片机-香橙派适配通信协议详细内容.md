## 1. 协议目标

  本协议用于单片机与香橙派之间的串口通信。

  当前版本只负责：

  - 香橙派通知单片机启动投递流程；
  - 香橙派通知单片机启动清运流程；
  - 香橙派向单片机设置垃圾单价；
  - 香橙派向单片机设置用于屏幕生成二维码的完整小程序跳转 URL；
  - 香橙派主动读取一次重量、红外和烟雾自检快照；
  - 单片机一次性上传投递前后重量和红外原始标志；
  - 单片机一次性上传清运前后重量和红外原始标志；
  - 单片机在烟雾状态变化时主动上传当前烟雾状态。

  当前版本暂不包含：

  - 校验和或 CRC；
  - ACK/NACK 确认；
  - URL 接收结果或二维码显示结果应答；
  - 命令执行状态；
  - 推杆状态上报；
  - 清运门状态上报；
  - 除“烟感数据无法获取”以外的详细传感器故障原因；
  - 流程编号；
  - 消息序号；
  - 重发机制。

---

  ## 2. 串口参数

  建议使用：

  波特率：115200
  数据位：8
  停止位：1
  校验位：无
  流控：无
  模式：8N1

---

## 3. 数据编码规则

  ### 3.1 十六进制原始字节

  所有通信内容均为原始十六进制字节，不发送十六进制字符串。

  例如：

  AA 01 AA

  串口实际发送3个字节：

  0xAA 0x01 0xAA

  不能发送以下 ASCII 字符：

  "A", "A", " ", "0", "1", " ", "A", "A"

  协议文档中的空格只用于方便阅读，不会通过串口发送。

  ### 3.2 帧格式

  保持原有通信风格：

  帧头 + 数据字段 + 帧尾

  每种报文的帧头和帧尾使用相同字节。

  例如：

  DD + 投递数据 + DD
  EF + 清运数据 + EF

  ### 3.3 多字节数据顺序

  重量采用3字节无符号整数，高字节在前：

  WEIGHT_H WEIGHT_M WEIGHT_L

  重量计算公式：

  重量（克） =
  WEIGHT_H × 65536
  + WEIGHT_M × 256
  + WEIGHT_L

  例如：

  00 01 1C = 284克
  00 2E E0 = 12000克
  05 57 30 = 350000克

  注意：

  01 3C = 316克
  01 1C = 284克

  ### 3.4 URL 字节编码

  小程序跳转 URL 使用 ASCII 字节发送，不发送以十六进制表示的字符串，也不发送
  字符串结束符。

  URL 必须满足：

  - 是完整的 HTTPS 地址；
  - 实际长度为1～192个 ASCII 字节；
  - 不包含空格、中文或其他非 ASCII 字符；
  - `LEN` 表示实际 URL 字节数，不包含后续补齐的 `00`。

  URL 数据区固定占192字节。实际 URL 后剩余的字节全部填 `00`，MCU 只读取前
  `LEN` 个字节，不能把补齐字节作为 URL 内容。

---

## 4. 重量字段定义

  重量单位统一为克。

  每个重量占3字节：

  WEIGHT_H WEIGHT_M WEIGHT_L

  有效范围：

  00 00 00 ～ 05 57 30

  对应：

  0克 ～ 350000克

  也就是最大350千克。

  当前版本不定义称重失败、超载和重量无效标志。单片机应当在获得稳定、有效的重量后再发送结果帧。

---

## 5. 红外原始标志定义

  `FULL` 字段占1字节，表示单片机采集到的红外遮挡原始结果：

| 十六进制值 | 含义       |
| ---------- | ---------- |
| 00         | 红外未遮挡 |
| 01         | 红外被遮挡 |

  `FULL` 不是最终业务满溢结论，香橙派和后端不得仅凭该字段认定设备实际满溢。

  最终业务满溢状态由既有业务链路按照后端下发并由香橙派本地保存的判断标准，
  结合 `FULL` 红外结果、结果帧中的流程后总重量及其他已配置条件计算。

  当前 MCU 协议不接收业务满溢阈值或判断配置，这些配置暂时只保存在香橙派本地。

  投递结果中的 `FULL` 表示投递完成后采集的红外状态。

  清运结果中的 `FULL` 表示清运完成后采集的红外状态。

  当前版本不会在红外状态发生变化时单独发送消息，只会随投递结果或清运结果一起上传。

# 6. 香橙派发送给单片机

  ## 6.1 启动投递流程

  ### 帧格式

  AA CMD AA

  固定长度：3字节。

  字段定义：

| 字段 | 长度  | 含义         |
| ---- | ----- | ------------ |
| AA   | 1字节 | 投递命令帧头 |
| CMD  | 1字节 | 投递流程命令 |
| AA   | 1字节 | 投递命令帧尾 |

  命令定义：

| CMD  | 含义             |
| ---- | ---------------- |
| 01   | 启动一次投递流程 |

  完整命令：

  AA 01 AA

  ### 执行含义

  收到该命令后，单片机自行启动完整投递流程。

  该命令仅表示：

  开始一次投递流程

  不表示：

  直接打开推杆

  也不表示：

  直接关闭推杆

  推杆、屏幕、限位开关、称重和流程控制均由单片机自行处理。

  ### 投递流程

  1. 单片机收到：

  AA 01 AA

  2. 单片机测量并保存本次流程最初的投递前重量。
  3. 单片机按照自身程序打开投递口。
  4. 用户完成投递。
  5. 单片机通过屏幕让用户选择：

  继续投递
  结束投递

  6. 如果用户选择“继续投递”：

  - 单片机继续执行下一次开盖和投递；
  - 不向香橙派发送重量结果；
  - 不得覆盖本次流程最初保存的投递前重量。

  7. 如果用户选择“结束投递”：

  - 单片机关闭投递口；
  - 等待重量稳定；
  - 测量投递结束后的总重量；
  - 采集投递完成后的红外原始状态；
  - 向香橙派发送一次投递结果帧。

  同一次流程无论用户继续投递多少次，最终只发送一个投递结果帧。

  ### 限制

  当前协议没有确认帧和流程编号，因此香橙派发送一次 AA 01 AA 后，不应因为没有收到立即响应而自动重复发送，否则可能重复启动投递流程。

## 6.2 设置垃圾单价

  ### 帧格式

  BB PRICE BB

  固定长度：3字节。

  字段定义：

| 字段  | 长度  | 含义     |
| ----- | ----- | -------- |
| BB    | 1字节 | 单价帧头 |
| PRICE | 1字节 | 垃圾单价 |
| BB    | 1字节 | 单价帧尾 |

  PRICE 有效范围：

  00 ～ 09

  每增加 01，表示增加：

  0.1元/千克

  对应关系：

| PRICE | 单价       |
| ----- | ---------- |
| 00    | 0.0元/千克 |
| 01    | 0.1元/千克 |
| 02    | 0.2元/千克 |
| 03    | 0.3元/千克 |
| 04    | 0.4元/千克 |
| 05    | 0.5元/千克 |
| 06    | 0.6元/千克 |
| 07    | 0.7元/千克 |
| 08    | 0.8元/千克 |
| 09    | 0.9元/千克 |

  例如，设置单价为 0.4元/千克：

  BB 04 BB

  香橙派收到的业务单价使用“元/千克的万分位整数”保存，发送给 MCU 时按以下规则
  生成 `PRICE`：

  PRICE = min(业务单价万分位整数 // 1000, 9)

  即先向下截断到一位小数，再将超过 0.9元/千克的屏显值饱和为 `09`。例如业务
  单价 0.45元/千克发送 `BB 04 BB`，业务单价 1.20元/千克发送 `BB 09 BB`。

  后端仍使用未截断的原始业务单价计算返现金额，因此 MCU 屏显单价允许与实际返现
  单价不一致。

  单价可以在设备启动时发送，也可以在单价发生变化时重新发送。

  当前协议不要求单片机回复单价接收结果。

  ## 6.3 启动清运流程

  ### 帧格式

  EE CMD EE

  固定长度：3字节。

  字段定义：

| 字段 | 长度  | 含义         |
| ---- | ----- | ------------ |
| EE   | 1字节 | 清运命令帧头 |
| CMD  | 1字节 | 清运流程命令 |
| EE   | 1字节 | 清运命令帧尾 |

  命令定义：

| CMD  | 含义             |
| ---- | ---------------- |
| 01   | 启动一次清运流程 |

  完整命令：

  EE 01 EE

  ### 执行含义

  该命令仅通知单片机：

  开始一次清运流程

  该命令不直接表示继电器保持通电，也不要求香橙派控制继电器断电。

  清运门继电器的具体控制逻辑全部由单片机负责。

  ### 清运流程

  1. 单片机收到：

  EE 01 EE

  2. 单片机测量并保存清运前总重量。
  3. 单片机给清运门继电器通电。
  4. 经过3～5秒后，单片机必须自动断开继电器。
  5. 继电器断开后，清运门由工作人员进行操作。
  6. 工作人员取出旧垃圾袋并更换新垃圾袋。
  7. 工作人员关闭清运门。
  8. 工作人员通过单片机屏幕确认清运完成。
  9. 单片机等待重量稳定。
  10. 单片机测量清运后总重量。
  11. 单片机采集清运完成后的红外原始状态。
  12. 单片机发送一次清运结果帧。

  香橙派不再发送以下命令：

  EE 00 EE

  继电器断电必须由单片机自身的定时逻辑完成，避免继电器或门锁长时间通电造成损坏。

  ### 钥匙开门

  工作人员仍可以使用机械钥匙打开清运门。

  如果希望钥匙清运也形成正式清运记录，应当先由工作人员通过小程序启动清运，使香橙派发送：

  EE 01 EE

  之后工作人员可以使用钥匙完成实际开门。

  如果完全使用钥匙开门，并且没有发送 EE 01 EE，单片机没有保存清运前重量，因此不应发送正式的 EF 清运结果帧。

### 限制

  当前协议没有确认帧和流程编号，因此香橙派发送一次 EE 01 EE 后，不应自动重复发送。

## 6.4 获取一次传感器自检快照

  ### 帧格式

  F0 CMD F0

  固定长度：3字节。

  字段定义：

| 字段 | 长度  | 含义         |
| ---- | ----- | ------------ |
| F0   | 1字节 | 自检查询帧头 |
| CMD  | 1字节 | 自检查询命令 |
| F0   | 1字节 | 自检查询帧尾 |

  命令定义：

| CMD  | 含义                   |
| ---- | ---------------------- |
| 01   | 返回当前传感器自检快照 |

  完整命令：

  F0 01 F0

  ### 执行含义

  该命令是只读查询，只要求单片机返回当前重量、红外和烟雾状态，不启动投递、清运、
  推杆、继电器或其他机械动作。同一条查询既可以用于机器自检，也可以用于平台已经
  明确确认空袋后的皮重测量；两种情况使用完全相同的 F0/F1 帧，不增加新的协议命令。

  单片机收到命令后，应使用当前或最近一次稳定采样，在3秒内发送一帧 F1 自检应答。
  如果当前没有有效的重量或红外采样，应通过 F1 的 `VALID` 位明确表示无效，不能为了
  通过自检而伪造数值。

  ### 发送时机和限制

  香橙派在以下情况下发送：

  - 香橙派启动并成功打开串口后；
  - 平台每次发起机器验收时。
  - 平台发起空袋皮重测量，并且命令中的 `emptyBagConfirmed=true` 时。

  每次自检或皮重测量只发送一次 F0 01 F0，不立即重试。F0 是可重复执行的只读查询，
  但它不是通用 ACK，也不能用于判断投递或清运命令是否执行。皮重测量只能使用本次
  F0 查询之后收到的 F1；禁止复用启动自检、历史投递或历史清运留下的重量。

## 6.5 设置小程序跳转 URL

  ### 帧格式

  A0 LEN URL_DATA[192] A0

  固定长度：195字节。

  字段定义：

| 字段          | 长度    | 含义                         |
| ------------- | ------- | ---------------------------- |
| A0            | 1字节   | URL 设置帧头                 |
| LEN           | 1字节   | 实际 URL 的 ASCII 字节数     |
| URL_DATA[192] | 192字节 | URL 内容以及尾部 `00` 补齐区 |
| A0            | 1字节   | URL 设置帧尾                 |

  `LEN` 有效范围为 `01`～`C0`，十六进制 `C0` 等于十进制192。

  例如，实际 URL 为：

  https://www.jinshoubao.com/device-entry/?deviceCode=Dv_example

  香橙派应当：

  1. 将完整 URL 编码为 ASCII 字节；
  2. 将实际字节数写入 `LEN`；
  3. 将 URL 字节放入192字节数据区开头；
  4. 将数据区剩余位置全部填 `00`；
  5. 在报文首尾分别写入 `A0`。

  ### MCU 处理要求

  MCU 收到完整且字段合法的报文后：

  - 读取前 `LEN` 个 URL 字节；
  - 用新 URL 替换当前内存中的旧 URL；
  - 立即使用完整 URL 生成并显示二维码；
  - 不向香橙派发送 ACK、NACK、URL 接收结果或二维码显示结果。

  如果帧尾不等于 `A0`、`LEN` 不在合法范围内、URL 数据不是合法 ASCII HTTPS
  地址，MCU 应忽略整帧并保留当前 URL，也不发送错误应答。

  MCU 当前不要求把 URL 写入自身 Flash。MCU 单独重启而香橙派没有重启时，二维码
  可能暂时不可用；当前协议不增加 MCU 启动通知或 URL 查询机制。

  ### 香橙派保存和发送时机

  香橙派必须先把后端下发的 URL 可靠保存到本地 SQLite，再向 MCU 发送本报文。

  香橙派只在以下情况下向 MCU 发送：

  - 平台机器验收命令携带新的 URL，并且香橙派已经保存成功；
  - 后端全局小程序基础跳转地址改变，香橙派收到并保存新的 URL；
  - 香橙派启动或串口重新打开后，本地已经存在保存成功的 URL。

  每次触发只发送一帧，不等待 MCU 应答，也不进行周期重发。串口写入是否成功、MCU
  是否生成二维码以及屏幕是否显示，都不作为平台机器验收条件。平台只验证香橙派是否
  保存了后端期望的 URL 及其摘要。

  # 7. 单片机发送给香橙派

## 7.1 投递完成上报

  ### 帧格式

  DD
  + 投递前重量
  + 投递后重量
  + 红外原始标志
  + DD

  完整字段格式：

  DD PRE_H PRE_M PRE_L POST_H POST_M POST_L FULL DD

  固定长度：9字节。

  字段定义：

| 字段   | 长度  | 含义                     |
| ------ | ----- | ------------------------ |
| DD     | 1字节 | 投递结果帧头             |
| PRE_H  | 1字节 | 投递前重量高字节         |
| PRE_M  | 1字节 | 投递前重量中字节         |
| PRE_L  | 1字节 | 投递前重量低字节         |
| POST_H | 1字节 | 投递后重量高字节         |
| POST_M | 1字节 | 投递后重量中字节         |
| POST_L | 1字节 | 投递后重量低字节         |
| FULL   | 1字节 | 投递完成后的红外原始标志 |
| DD     | 1字节 | 投递结果帧尾             |

  ### 发送时机

  只有在用户点击“结束投递”后发送。

  用户点击“继续投递”时不发送。

  一次完整投递流程只发送一次。

  ### 示例

  投递前重量：

  12000克 = 00 2E E0

  投递后重量：

  12284克 = 00 2F FC

  投递完成后红外被遮挡：

  FULL = 01

  发送：

  DD 00 2E E0 00 2F FC 01 DD

  香橙派计算：

  投递净重
  = 投递后重量 - 投递前重量
  = 12284 - 12000
  = 284克

  红外原始状态：

  01 = 红外被遮挡

  ### 净重处理原则

  单片机只负责上传真实的前后总重量。

  单片机不需要计算投递净重，也不要把重量减少强制处理成零。

  香橙派根据前后重量进行计算：

  NET_WEIGHT = POST_WEIGHT - PRE_WEIGHT

  如果投递后重量小于投递前重量，香橙派仍保留真实的负净重，不强制归零。当前
  适配版本的 `negativeWeightAnomaly` 暂时固定为 `false`，不因此阻断投递完成；
  后续异常处理由业务规则另行定义。

  ## 7.2 清运完成上报

  ### 帧格式

  EF
  + 清运前重量
  + 清运后重量
  + 红外原始标志
  + EF

  完整字段格式：

  EF PRE_H PRE_M PRE_L POST_H POST_M POST_L FULL EF

  固定长度：9字节。

  字段定义：

| 字段   | 长度  | 含义                     |
| ------ | ----- | ------------------------ |
| EF     | 1字节 | 清运结果帧头             |
| PRE_H  | 1字节 | 清运前重量高字节         |
| PRE_M  | 1字节 | 清运前重量中字节         |
| PRE_L  | 1字节 | 清运前重量低字节         |
| POST_H | 1字节 | 清运后重量高字节         |
| POST_M | 1字节 | 清运后重量中字节         |
| POST_L | 1字节 | 清运后重量低字节         |
| FULL   | 1字节 | 清运完成后的红外原始标志 |
| EF     | 1字节 | 清运结果帧尾             |

### 发送时机

  只有满足以下条件后才发送：

  - 已经通过 EE 01 EE 启动清运流程；
  - 已保存清运前重量；
  - 继电器已经自动断电；
  - 工作人员已经完成垃圾袋更换；
  - 工作人员已经关闭清运门；
  - 工作人员已在单片机屏幕确认清运完成；
  - 单片机已获得稳定的清运后重量；
  - 单片机已采集清运后的红外原始状态。

  一次清运流程只发送一次。

  ### 示例

  清运前重量：

  100000克 = 01 86 A0

  清运后重量：

  50000克 = 00 C3 50

  清运完成后红外未遮挡：

  FULL = 00

  发送：

  EF 01 86 A0 00 C3 50 00 EF

  香橙派计算：

  清运减少重量
  = 清运前重量 - 清运后重量
  = 100000 - 50000
  = 50000克

  红外原始状态：

  00 = 红外未遮挡

## 7.3 传感器自检快照应答

  ### 帧格式

  F1 VALID WEIGHT_H WEIGHT_M WEIGHT_L FULL SMOKE F1

  固定长度：8字节。

  字段定义：

| 字段     | 长度  | 含义                 |
| -------- | ----- | -------------------- |
| F1       | 1字节 | 自检应答帧头         |
| VALID    | 1字节 | 重量和红外采样有效位 |
| WEIGHT_H | 1字节 | 当前稳定重量高字节   |
| WEIGHT_M | 1字节 | 当前稳定重量中字节   |
| WEIGHT_L | 1字节 | 当前稳定重量低字节   |
| FULL     | 1字节 | 当前红外原始标志     |
| SMOKE    | 1字节 | 当前烟雾读取结果     |
| F1       | 1字节 | 自检应答帧尾         |

  `VALID` 是位标志：

| 位      | 值为1时的含义     |
| ------- | ----------------- |
| bit0    | 重量采样有效      |
| bit1    | 红外采样有效      |
| bit2～7 | 必须为0，暂不定义 |

  重量和红外均有效时，`VALID` 为 03。

  如果重量无效，bit0 必须为0，三个重量字节填 00 00 00；如果红外无效，bit1 必须
  为0，`FULL` 填 00。香橙派只在对应有效位为1时使用该字段。

  `SMOKE` 定义：

   SMOKE    含义

| 值   | 含义                     |
| ---- | ------------------------ |
| 00   | 成功读取烟感，未触发报警 |
| 01   | 成功读取烟感，已触发报警 |
| 02   | 单片机无法获取烟感数据   |

  03～FF 均为非法值。`02` 只表示单片机仍能通信，但无法读取烟雾报警器；如果香橙派
  完全收不到 F1，那是串口或 MCU 通信超时，香橙派不能自行伪造成 `02`。

  ### 示例

  当前重量12000克、红外未遮挡、烟雾未触发，重量和红外均有效：

  F1 03 00 2E E0 00 00 F1

  当前重量和红外有效，但单片机无法获取烟感数据：

  F1 03 00 2E E0 00 02 F1

  ### 验收含义

  收到结构和字段都合法的 F1，可以证明本次香橙派与 MCU 通信成功。机器验收还必须
  同时满足：重量和红外有效、重量范围合法、烟雾为 00。烟雾为 01 表示设备当前处于
  报警环境，烟雾为 02 表示烟感不可用；这两种情况都不能通过机器验收。

  当 F1 用于空袋皮重测量时，香橙派只在 `VALID.bit0=1` 且重量范围合法时把本次重量
  作为稳定皮重上报。红外和烟雾字段仍照常更新设备状态，但不改变这次重量事实；安全
  状态是否允许后续投递或清运，由香橙派和平台按各自安全规则另行判断。如果 F1 超时、
  格式错误或重量无效，本次皮重测量必须明确失败，不能回退到历史重量或 0 克。

## 7.4 烟雾状态变化主动上报

  ### 帧格式

  CC SMOKE CC

  固定长度：3字节。

  完整报文：

| 报文     | 含义                   |
| -------- | ---------------------- |
| CC 00 CC | 烟感可读，当前未触发   |
| CC 01 CC | 烟感可读，当前已经触发 |
| CC 02 CC | 当前无法获取烟感数据   |

  ### 发送时机

  单片机在 00、01、02 三种稳定状态之间发生变化时发送一次，包括报警、报警恢复、
  读取失败和读取恢复。相同状态没有变化时不周期发送。

  香橙派发送 F0 01 F0 时，当前烟雾状态已经包含在 F1 中，单片机不再重复发送 CC。
  如果烟雾状态恰好在生成 F1 时变化，单片机应先完整发送 F1，再发送包含最新状态的
  CC；两个报文的字节不能交叉。

  ### 安全边界

  烟雾报警时，单片机必须立即执行自身已有的本地安全保护。CC 上报用于通知香橙派和
  平台，不能把本地安全动作交给 OneNet 或后端完成。

# 8. 完整协议帧汇总

| 方向         | 功能         | 固定格式                                            | 长度  |
| ------------ | ------------ | --------------------------------------------------- | ----- |
| 香橙派 → MCU | 启动投递流程 | `AA 01 AA`                                          | 3字节 |
| 香橙派 → MCU | 设置垃圾单价 | `BB PRICE BB`                                       | 3字节 |
| 香橙派 → MCU | 启动清运流程 | `EE 01 EE`                                          | 3字节 |
| 香橙派 → MCU | 获取传感器快照 | `F0 01 F0`                                          | 3字节 |
| 香橙派 → MCU | 设置跳转 URL  | `A0 LEN URL_DATA[192] A0`                           | 195字节 |
| MCU → 香橙派 | 投递完成上报 | `DD PRE_H PRE_M PRE_L POST_H POST_M POST_L FULL DD` | 9字节 |
| MCU → 香橙派 | 清运完成上报 | `EF PRE_H PRE_M PRE_L POST_H POST_M POST_L FULL EF` | 9字节 |
| MCU → 香橙派 | 自检快照应答 | `F1 VALID WEIGHT_H WEIGHT_M WEIGHT_L FULL SMOKE F1` | 8字节 |
| MCU → 香橙派 | 烟雾变化上报 | `CC SMOKE CC`                                       | 3字节 |

# 9. 接收解析要求

  每种报文都是固定长度报文。

  接收方识别到帧头后，应按照对应报文的固定长度读取，不能把数据区中出现的帧头或帧尾字节当作报文结束。

  例如投递重量数据中可能刚好出现 DD：

  DD 00 DD 10 00 EF 20 01 DD

  中间的 DD 属于重量数据，真正的帧尾是第9个字节。

  解析长度如下：

  AA：读取3字节
  BB：读取3字节
  CC：读取3字节
  EE：读取3字节
  DD：读取9字节
  EF：读取9字节
  F0：读取3字节
  F1：读取8字节
  A0：读取195字节

  串口一次读取可能出现：

  - 只收到半帧；
  - 一次收到一整帧；
  - 一次同时收到多帧。

  因此，接收方应使用接收缓冲区，根据帧头和固定帧长逐帧解析，不能假设一次串口读取刚好对应一帧。

# 10. 当前香橙派适配边界

  - 当前固定帧协议只支持一个物理投口，对外固定为 `portNo=1`。
  - 后端下发的设备配置完整保存到香橙派本地并报告本地生效，但不发送给 MCU。
  - MCU 尚不支持的远程控制直接返回失败或 `MCU_FEATURE_NOT_SUPPORTED`，并且不得
    占用工作槽。
  - MCU 只增加了当前重量、红外、烟雾的只读自检快照，不提供门、继电器、活动作业、
    配置版本或待确认事件等通用状态查询。
  - 烟感在线路上只有 00、01、02 三种结果；02 不能进一步区分断线、传感器自身故障、
    MCU 驱动错误或其他读取失败原因。
  - 启动投递和启动清运命令均只发送一次，不自动重发。
  - 小程序跳转 URL 由香橙派可靠保存；验收或全局地址变化时保存并发送，香橙派启动或
    串口重新打开后从本地读取并再发送一次。MCU 不应答，屏幕结果不进入平台验收。
  - 香橙派重启后不重放未决物理命令，也不伪造 DD/EF 完成结果；未决命令标记失败
    并释放本地工作槽。
  - 后续 MCU 增加功能时在适配层逐项接入，不修改香橙派与 OneNet、后端之间的既有
    业务协议。

  ## 10.1 兼容层能力声明

  本协议是当前 MCU 与香橙派之间已经协商确定的线路协议，不是香橙派—OneNet—后端
  完整业务契约的等价实现。香橙派继续接收和保存完整云端契约，是为了让后续 MCU
  能力可以逐项补齐；当前不得据此宣称对应硬件功能已经可用。

  - “配置已本地生效”只表示配置已经可靠保存到香橙派，不表示 MCU 已接收或应用。
  - “串口写入成功”只表示操作系统接受了字节，不表示 MCU 已完成开门、清运或其他动作。
  - 不存在对应固定帧的远程控制必须返回失败/不支持，不能先返回成功等待未来实现。
  - 状态接口中的 `UNKNOWN`、`NOT_SAMPLED` 是真实的“协议不可观测”，不是传感器正常值。
  - DD/EF 的满溢字节仅代表 MCU 红外观测；香橙派仍按已下发并本地保存的业务判断标准
    形成实际满溢结论。
  - 协议不提供 ACK、CRC、流程编号或通用状态查询。F0/F1 只读取传感器快照，不提供
    MCU 作业恢复。香橙派只发送一次启动命令；掉线或重启后不重发、不恢复 MCU 物理
    流程，并把未决本地工作置失败后释放工作槽。
  - F1/CC 只补充当前传感器快照和烟雾变化；DD/EF 仍只提供最终重量和红外结果，无法
    产生规范协议中的中间称重、门状态或按钮事实。
  - 单价在线路上允许截断/饱和，后端返现继续使用原业务单价，因此两者允许不一致。
