# 香橙派与单片机固定帧串口协议

> 完整线路协议以
> [`单片机-香橙派适配通信协议详细内容.md`](单片机-香橙派适配通信协议详细内容.md)
> 为准。本文只记录香橙派适配层使用的字段及业务映射；香橙派与 OneNet、后端之间
> 仍使用既有业务协议。

## 1. 基本约定

- 串口参数为 `115200 / 8N1 / 无流控`。
- 线路发送原始字节，不发送十六进制 ASCII 字符串。
- 当前只支持一个物理投口，对外为 `portNo=1`，帧内没有投口号。
- 重量为 uint24 大端整数，单位克，有效范围 `0..350000`。
- 协议没有 CRC、ACK/NACK、流程编号、消息序号或重发机制。
- MCU 只在取得稳定有效重量后发送结果；协议没有称重故障表达。

## 2. 帧定义

| 方向 | 功能 | 固定格式 | 长度 |
|---|---|---|---:|
| 香橙派 → MCU | 设置单价 | `BB PRICE BB` | 3 |
| 香橙派 → MCU | 启动投递 | `AA 01 AA` | 3 |
| 香橙派 → MCU | 启动清运 | `EE 01 EE` | 3 |
| MCU → 香橙派 | 投递完成 | `DD PRE:u24 POST:u24 FULL DD` | 9 |
| MCU → 香橙派 | 清运完成 | `EF PRE:u24 POST:u24 FULL EF` | 9 |

`PRICE` 的 `00..09` 表示 `0.0..0.9 元/千克`。香橙派将后端的万分位
单价向下截断到一位小数；超过 `0.9` 的值在线路上饱和为 `09`。后端仍保留并使用
原始单价计算业务金额，因此 MCU 屏显单价与实际返现金额允许不一致。

`PRE` 和 `POST` 分别是流程开始前、流程结束后的总重量。香橙派计算：

```text
投递净重 = POST - PRE
清运减少重量 = PRE - POST
```

投递过程中用户选择继续投递时 MCU 不发送结果，也不覆盖最初的 `PRE`；用户最终
结束后只发送一次 DD。EF 只在下列条件全部成立后发送：

- 清运由 `EE 01 EE` 启动；
- MCU 已保存清运前重量；
- 继电器已自动断电；
- 工作人员已换袋、关门并在 MCU 屏幕确认完成；
- MCU 已取得稳定的清运后重量。

所以收到 EF 可以作为“工作人员确认关门”和“继电器已断电”的协议事实，但不能
推导继电器健康状态。

## 3. FULL 的业务含义

`FULL=00/01` 只作为 MCU 返回的红外未遮挡/遮挡原始结果，香橙派映射为
`DIGITAL_INFRARED + CLEAR/BLOCKED`。它不是最终业务满溢结论。最终判断仍由既有
业务规则结合本地配置、红外结果和 POST 总重量完成。

当前不会为查询主动向 MCU 采样。香橙派可以在后端发起初次满溢采样时复用最近一次
DD/EF 的红外和重量观测；没有历史观测、确认采样和人工复检均返回不支持。

## 4. 接收解析

DD/EF 必须按固定 9 字节解析，不能把数据区内出现的 `DD` 或 `EF` 当成帧尾。
接收缓冲区必须处理半帧、粘包和前导噪声，并验证：

- 第 1、9 字节相同且是 `DD` 或 `EF`；
- 两个重量均不超过 350000 克；
- `FULL` 只能是 `00` 或 `01`。

无效候选帧从当前疑似帧头后一个字节重新同步。

## 5. 可靠性边界

- 启动命令只发送一次，不因无响应而重发。
- 发送启动命令前丢弃本地接收缓存中的旧结果。
- 香橙派重启后不恢复或重放物理命令，也不伪造 DD/EF 完成事件；未决本地命令标记
  失败并释放工作槽。
- 固定帧模式不向 MCU 发送 HELLO、QUERY_STATE、配置或恢复帧。
- 没有流程编号意味着线路无法证明一条迟到 DD/EF 属于哪次启动；现场应保证单次
  流程串行执行。

## 6. 暂不支持的功能

- 设备配置：完整保存并在香橙派本地标记生效，不投影到 MCU。
- 空袋基线测量、满溢确认/人工复检、清运取消和清运恢复：返回
  `MCU_FEATURE_NOT_SUPPORTED`，且不占用工作槽。
- MCU 状态查询：运行快照使用 `UNKNOWN` / `NOT_SAMPLED` 占位事实。
- 烟雾、推杆、门锁输出、传感器故障和 MCU 重启状态：当前线路没有对应上报。

如需上述功能，应在 MCU 明确支持后逐项接线，不修改既有香橙派—后端业务协议。
