# 香橙派与单片机串口通信协议

## 1. 基本约定

- 所有示例均为 UART 线路上的**原始十六进制字节**，不是 ASCII 字符串。
- 当前协议只支持一个物理投口，对外固定为 `doorIndex=1`，帧内不携带门号。
- 各帧采用固定长度，当前不含 CRC、独立 ACK 或自动重试。
- 重量使用 3 字节大端无符号整数，单位为克。五位十六进制数在线路上补齐为
  6 位（3 个完整字节）。

## 2. MCU → 香橙派

| 功能 | 帧格式 | 数据定义 | 发送时机 |
|---|---|---|---|
| 推杆状态 | `AA <状态> AA` | `00`=关盖，`01`=开盖 | 推杆状态发生改变后发送 |
| 红外状态 | `BB <状态> BB` | `00`=未遮挡，`01`=被遮挡 | 每次投递完成后检测并发送 |
| 烟雾报警 | `CC <状态> CC` | `00`=无报警，`01`=报警 | 超过设定阈值时发送 |
| 最终重量 | `DD <高字节> <中字节> <低字节> DD` | uint24 大端，单位克 | 每次投递完成并得到最终重量后发送 |

重量示例：五位数据 `0013C` 补齐并编码为 `DD 00 01 3C DD`，其中
`0x00013C = 316`，因此表示 316 克。

当前 Python 实现将该重量直接作为本次投递最终净增重量上报，不再做毛重减皮重；
并接受开盖事件基线后的第一帧新 DD（包括 `0g`）。因此 MCU 应在本次称重稳定后
只发送一次结果，不应周期发送累计毛重或上一次残留重量。传感器故障时当前协议没有
错误码，MCU 不应使用 `0g` 代替故障，而应不发送 DD，让香橙派按重量超时结束本次流程。

红外被遮挡在当前业务中映射为满溢：香橙派更新 `fullness=100`、
`spillAlarm=true` 并向 OneNet 上报 `spillAlarm`。

## 3. 香橙派 → MCU

| 功能 | 帧格式 | 数据定义 |
|---|---|---|
| 开盖 | `AA 00 AA` | 控制数据 `00`=开盖 |
| 关盖 | `AA 01 AA` | 控制数据 `01`=关盖 |
| 垃圾单价 | `BB <价格位> BB` | `00`–`09` 分别表示 `0.0`–`0.9` 元/kg |

注意：AA 帧的数据位在两个方向上的含义不同。香橙派发送 `00` 是开盖命令，
MCU 完成动作后上报 `01` 表示当前处于开盖状态。

香橙派本地默认单价为 `0.5` 元/kg，对应发送 `BB 05 BB`。OneNet 下发
`unitPrice` 浮点配置后，香橙派使用 `floor(unitPrice × 10)` 生成价格位，例如
`0.45` 发送 `BB 04 BB`。

## 4. 投递时序

1. 香橙派发送开盖帧 `AA 00 AA`。
2. MCU 完成开盖后发送状态帧 `AA 01 AA`。
3. MCU 在投递完成后发送本次最终重量 `DD ... DD`，红外状态可独立发送。
4. 香橙派发送关盖帧 `AA 01 AA`。
5. MCU 完成关盖后发送状态帧 `AA 00 AA`。

香橙派等待门状态默认超时 5 秒，等待重量默认超时 120 秒。超时后本次投递失败、
不发送完成事件，并额外发送一次关盖命令作为安全收尾，但不循环重试。
