# 原生运行入口：MCU重启收口、配置重装与投递末重失败

日期：2026-09-13。依据[精简实施计划](../../../docs/planning/mcu-edge-simplified-implementation-plan-2026-09-13.md)
和[D01-D15决定](../../../docs/architecture/mcu-edge-simplified-recovery-discussion-2026-09-13.md)。
本记录对应本地检查点`7c9570b1`之后的实现；未部署后端、未连接设备、未烧录MCU/HMI，也未写TF卡。

## 已接入实际入口的行为

### MCU重启后的原投递

- Pi只有在收到并保存了更大的真实MCU启动号后，才把原未完成投递判为MCU重启；通信超时本身不冒充重启。
- 归档事务在最后写入前再次检查完整最终包。若最终包已经可靠落入SQLite，即使它恰好在判定与归档之间到达，也优先按原完整结果处理。
- 确实没有最终包时，原业务归档为“单片机重启，未取得最终结果包”。已有重量和其他原始事实继续保留，
  不写成“重量全部丢失”，不拼装正常结果。
- 问题报告收到准确的`BUSINESS_APPLIED`（后台已处理）确认后，永久作业记为取消并只释放匹配的原本地槽；
  不修改袋、皮重或后来业务。归档后到达的完整包只保存为该问题的补充证据，不能恢复订单或覆盖当前状态。
- Pi崩溃在“迟到原始包已写SQLite、问题证据事件尚未建立”之间时，冷启动扫描原问题并补建原事件；不需要当前业务槽。

### MCU重启后的配置

- MCU重启会失去RAM中的已应用配置。Pi从原来已经`APPLIED`（已应用）的云端配置和真实受理字节重装同一配置；
  这不是重新执行过期云端命令，也不生成第二次云端配置进度。
- 每次目标启动号使用新的本地配置分片编号。Pi单独重启复用同一批编号，只查询已登记发送的分片；MCU再次重启后，
  原分片作为旧启动证据保留，新启动另建一批，不把两个启动号混在同一配置事务。
- 重装期间拒绝新业务；重装本身不直接恢复接单。仍须满足网络、当前新鲜称重、门关闭控制、清运锁断电、无维护和无其他阻断故障。

### 投递末次称重始终不可读

- 仅接受实际MCU生成的严格终态：首重有效、末次称重等待5000毫秒后仍只有0至4个样本、末重`UNAVAILABLE`、
  故障为`WEIGHT_TIMEOUT`，且原关闭控制已经下发。首重失败、通用取消、MCU重启问题和清运失败不借用本路径。
- Pi把完整失败包、首重和末重失败事实可靠上报；后端创建待人工处理的系统异常订单。
  订单末重、净重、业务重量和金额为空，不补零；不创建自动审核任务，不改余额，不触发提现，也不投影容量。
- 后端准确处理原失败事件后，Pi将原命令和永久作业记为`FAILED`（失败），取得精确永久回执后才释放原槽。
  回执延迟或Pi在永久提交后重启，不会提前释放或重复完成。
- Pi同时记录称重模块阻断故障。只有来自同一启动号更晚采样/尝试序号，或来自更大启动号的真实有效读数，
  才清除这一条称重故障并允许后续新业务；旧失败订单和原包保持不变，通信/存储等其他故障也不会被顺带清除。

## 验证

- Python 3.11、真实SQLite、真实UpdaterStore以及编译后的实际C执行器统一回归：**235项通过，90.69秒**。
  覆盖真实5秒称重超时、永久回执延迟前后断点、Pi重启、有效新读数恢复、MCU重启归档、归档竞态、
  迟到结果隔离、配置重装和重装途中Pi重启。JUnit位于本机临时目录`ecobin-native-s2-weight-integrated.xml`。
- Java 21离线全模块`install -DskipTests`通过。定向Java单元/SQL检查与两条真实MySQL事务测试共**9项通过**。
  完整链使用仅回环地址的MySQL 8.4.10、V1至V79共79条迁移、137张领域表和运行授权清单40；
  验证真实inbox（收件箱）到设备事实、异常订单、可靠确认、释放占用及无资金副作用。隔离容器已清理。
- 首轮真实MySQL复现过自动审核配置快照约束冲突。修复后保留既有配置快照要求，但`UNAVAILABLE`（不可计算）
  订单不注册自动审核任务；这两个事实不能混为“到期字段存在就会自动审核”。

## 仍未完成及性能边界

- 控制通信故障当前只设置阻断标记，尚未把原当前业务可靠收为失败；START从未登记发送时的释放、清运中断人工袋确认、
  连续断网600秒后台释放占用仍待实现。
- 问题证据每次最多新建10个事件，但现实现会从头复核已存在的历史分片；因此限制的是“每轮新增事件数”，
  不是严格的单轮CPU时间上限。大量历史证据下的耗时须在发布前量化或改成持久游标。
- 运行快照投口结构、热点验收、二维码/固件身份、完整发布清单、真实RS485响应边界和成对现场联调属于S4，尚未完成。

以上只证明本批本地实现和隔离数据库行为，不代表可部署、可烧录或现场硬件已经验证。
