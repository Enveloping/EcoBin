## 代码映射

| 固定帧事实 | 香橙派处理 |
|---|---|
| `BB PRICE BB` + `AA 01 AA` | 一次串口写入，启动投递 |
| `DD PRE POST FULL DD` | 合成两条稳定重量事实，创建既有 `DELIVERY_COMPLETE` |
| `EE 01 EE` | 一次串口写入，启动清运 |
| `EF PRE POST FULL EF` | 合成两条稳定重量事实，创建既有 `CLEAN_COMPLETE` |
| `F0 01 F0` | 香橙派主动请求一次新的传感器自检快照 |
| `F1 VALID WEIGHT FULL SMOKE F1` | 保存真实重量、红外和烟感快照；无效字段按 `VALID` 判断 |
| `CC SMOKE CC` | 烟感在正常、报警、无法读取之间变化时，形成既有安全状态事件 |
| `A0 LEN URL_DATA[192] A0` | 立即下发或空闲定时刷新 MCU 屏幕使用的设备入口 URL |
| `FULL` | 缓存为原始 `DIGITAL_INFRARED` 观测 |
| 无通用 MCU 作业状态查询 | 门、执行器和重启作业状态返回未知/未采样占位 |
| 无配置命令 | 配置只在 SQLite 保存并标记本地生效 |

适配入口为 `fixed_frame_mcu_adapter.py`。`ECOBIN_MCU_PROTOCOL=fixed-frame`
显式选择该实现；保留 `uart-v1` 仅用于明确切回 Registry 协议，不进行自动探测或
失败回退。

## 兼容不等于功能完整

适配层保留的是香橙派—OneNet—后端契约和后续扩展位置，不是把固定帧 MCU 伪装成已经
实现了全部契约。当前实际能力如下：

| 云边功能 | 当前固定帧 MCU 的实际行为 |
|---|---|
| 多投口 | MCU 只支持一个物理投口，对外固定 `portNo=1` |
| 投递单价 | 下发值按协议截断/饱和；后端返现金额仍按原业务单价计算，允许两者不一致 |
| 设备配置 | 完整保存到香橙派并报告本地生效；不发送到 MCU、不代表硬件参数已应用 |
| 远程控制 | MCU 没有对应帧时直接失败并返回 `MCU_FEATURE_NOT_SUPPORTED`，不占工作槽 |
| 运行状态 | F0/F1 提供传感器快照；门、执行器和作业状态仍用 `UNKNOWN/NOT_SAMPLED` 等明确占位 |
| 启动自检 | 启动先查询一次；超时、非法帧或传感器无效时仍联网，但设备降级并阻止新作业 |
| 自检恢复 | 无作业占用时按 5/10/20/40/60 秒退避重查 F0，间隔从上次查询结束后计算，之后每 60 秒一次；完整恢复后停止，健康时不轮询 |
| 二维码 URL | 新 URL、启动和串口重开时立即发送；空闲时默认每 60 秒重新读取 SQLite 并发送，作业占用或写失败按 5 秒复查 |
| 烟感变化 | `00=NORMAL`、`01=ALARM`、`02=无法读取`；相同状态不重复创建云事件 |
| 满溢 | DD/EF 的 `FULL` 只记为红外原始观测；业务是否满溢仍按香橙派保存的判断标准计算 |
| 异常标志 | 协议没有足够事实，`negativeWeightAnomaly` 暂为 `false`；净重仍保留真实差值 |
| 可靠发送 | 没有 ACK、CRC、命令/作业编号；投递/清运物理启动帧只发一次，不因未收到结果自动重发；二维码定时刷新不构成执行证明 |
| 重启恢复 | 不查询或恢复 MCU 作业，不重放物理命令；香橙派把未决工作置失败并释放槽位 |
| 过程事件 | DD/EF 只能形成最终结果，不能还原 UART 1.0 的称重、门和按钮中间事件 |
| 物理执行证明 | 本地保存或串口写成功都不证明 MCU 已执行；只有协议结果帧能形成对应最终事实 |

上述降级是 2026-07-28 项目负责人确认的当前实施边界。保留云端字段是为了后续 MCU
逐项支持时无需改动香橙派—后端协议；占位值和“不支持”结果本身就是当前真实事实。

## 已确认的折中

- 单价按一位小数向下截断并在 0.9 饱和；业务返现继续使用后端原始单价。
- `negativeWeightAnomaly` 暂时固定为 `false`，但净重仍保留真实的 `POST-PRE`。
- EF 的发送前置条件允许上报已断电、人工关门已确认；`solenoidHealth` 只能上报
  `UNKNOWN`。
- 不增加发送重试、重启恢复锁或物理命令重放。重启后未决命令失败并释放工作槽。
- 不能从 DD/EF 还原 UART 1.0 的中间事件，因此只创建最终业务事件。
- F1 必须由本次 F0 查询取得；不以历史 F1、DD/EF 或旧的正常状态代替本次证据。
- F0 查询期间到达的 DD、EF、CC 仍按到达顺序进入正常事件队列，不因自检丢失。
- `SMOKE=02` 表示 MCU 通信正常但烟感无法读取；完全收不到合法 F1 才是查询超时或
  协议错误。
- 自动重查由现有命令消费者串行执行。作业槽有投递或清运时顺延 5 秒，且不推进退避
  档位；它不会与物理启动命令并发，也不会重新打开历史 `FAILED` 命令。
- 完整健康证据要求：F1 查询成功且通信正常、`VALID=3`、重量是 0～350000 克整数、
  红外值合法，并且最新烟感为 `NORMAL/OK` 或 `ALARM/OK`。`ALARM/OK` 会停止通信自检
  重查，但业务安全检查仍拒绝新的投递和清运。
- 只要合法 F1 已证明通信恢复，就精确关闭活动的 `UART_PROTOCOL` 故障；重量、红外或
  烟感仍无效时继续重查。恢复证据固定为
  `FIXED_FRAME_SELF_TEST_RETRY_SUCCEEDED`。
- CC 只能更新烟感，不能单独替代 F0/F1 对通信、重量和红外的证明。相同自检投影不会
  再生成 `SAFETY_SENSOR_EVENT`；相同 UART 故障只增加发现次数和最后发现时间，状态真正
  变化时才建立一次可靠安全事件或故障恢复事件。
- 串口已关闭或活动 `UART_PROTOCOL` 故障尚未关闭时，历史正常 F1 不能放行新投递或清运；
  `WorkManager` 在物理写串口前返回 `SAFETY_SENSOR_UNHEALTHY`。
- 二维码定时刷新由同一个命令消费者线程执行，并且只在工作槽空闲时写 `A0`，不会在
  投递或清运屏幕状态机运行时覆盖界面。周期由
  `ECOBIN_DEVICE_ENTRY_URL_REFRESH_SECONDS` 配置，默认 60 秒；首次定时发送等待一个
  完整周期，保存新 URL、启动和串口重开仍走既有立即发送路径。
- 当前提供者每次从 SQLite 取得静态 URL；代码保留可替换 URL provider，后续可在不改
  MCU 帧格式的前提下生成动态地址。但防重放必须由后端校验短期签名，不能只信任裸
  时间戳，且最终 ASCII 地址仍不能超过 192 字节。

## 测试覆盖

- 半帧、粘包、噪声、载荷内出现帧标志和非法帧重同步；
- F0/F1 新鲜查询、旧响应清理、超时、非法 F1 和查询期间业务/烟感帧交错；
- CC 的正常、报警、无法读取映射，以及同状态去重、状态变化可靠上报；
- 单价截断/饱和及投递命令字节顺序；
- 配置仅本地生效；
- DD 到投递完成、EF 到清运完成；
- 原始红外观测到现有满溢事件；
- 不支持命令不占工作槽；
- 固定帧启动查询传感器但不恢复 MCU 作业；自检失败仍联网、进入降级并阻止新作业；
- 启动超时后无需重启即可按 5/10/20/40/60/60 秒重查，合法 F1 到达后停止；
- 健康不查询、作业占用跳过、uart-v1 禁用此逻辑、退出等待最多受单次 3 秒查询约束；
- 二维码首次等待完整周期、周期读取最新 URL、作业占用暂停、串口断开/写失败短重试、
  无 URL 等待下一周期、uart-v1 隔离以及未来动态 URL provider 替换；
- 重复超时不增长 MCU inbox 或可靠安全事件，故障发现次数单调刷新且恢复事件只产生一次；
- 无效重量、无效红外、烟感读取失败继续重查，烟雾报警停止通信重查但继续阻止业务；
- 运行快照按活动 UART 故障投影 `FAULT`，故障恢复后投影 `READY`，串口关闭投影
  `DISCONNECTED`；历史失败命令保持 `FAILED` 且不重放；
- 生成事件可通过现有 OneNet 投影编码。
- MQTT 掉线重连复用单一 Paho 网络循环，连接等待超时不会停止后台重连；
- 真实子进程被强杀后，命令、工作槽、事件序号、事件、照片和业务确认仍可从 SQLite
  完整读取；
- COS 上传自动测试验证临时授权只在调用 SDK 时使用，不写入持久状态。
