## 1. 香橙派接通的路径

既有完整结果恢复评估入口，在核对原测量和原配置后，继续读取同一业务、同一轮次/
清运动作、同一 START（开始命令）范围内的已保存结束记录。全部读取仍在既有 SQLite
事务快照内完成，不增加串口写入、新按键、开关门、称重或云端任务。

- 投递结果为 `DELIVERY_END`（主动结束）或 `DELIVERY_WINDOW_EXPIRED`（选择等待超时）时，
  必须对应原末重的 `DELIVERY_SELECTION`（选择记录），并分别为 END 或 WINDOW_EXPIRED。
  普通结束必须有可用末重；不把明确的称重失败改成正常结束。
- 清运结果声明 `physicalCloseConfirmed`（工作人员已确认关门）时，必须对应原末重的
  `CLEAN_COMPLETION_CONFIRMED`（人工确认记录）。沿用原存储校验，对照同一清运动作的
  `CLEAN_FINISH_REQUESTED`（请求完成）和末重，核对编号、事件及时间先后。
  电磁锁断电不替代人工确认，也不会由本评估入口推定实际门位。
- 结束操作的时间必须不早于原重量和原满溢组均已结束的时刻，也不能晚于最终结果。
  不用收包时间刷新原事件，不把采样完成时间当作选择窗口启动时间来猜测超时。
- 连续投递第二轮使用第二轮的末重和结束选择；清运先称末重、再开锁、再次请求完成后，
  使用新动作序号下的新末重和人工确认。旧记录继续保留，但不能代替当前候选。

例如清运员第一次请求完成后取得700克候选，又重新打开清运门并取得900克候选，最终
确认必须指向900克对应的原测量；700克只保留为该次清运的过程记录。

## 2. 缺失、矛盾与失败结果

`evidence.completion` 返回原结束记录的消息名、正文和业务范围；没有可用原记录时为空。
缺少所需记录时仍为 `COMPLETE_RESULT_AVAILABLE`（已有完整结果），内层为
`WAITING_FOR_PROCESS_CUSTODY`（等待原过程证据）。不产生“结果不存在”的重启恢复意图。

- 缺结束选择/人工确认时，返回准确的原范围及所对应末重编号。
  WORK_RESULT没有提供结束事件序号，因此不会把末重事件序号冒充结束事件序号。
- 清运的原请求完成记录缺失时，先明确等待这条前置记录；不会把缺前置记录误判成最终包丢失。
- 原末重保存凭据缺失时，先等待末重，再读取依赖它的结束记录；裸重量行仍不能替代原范围凭据。
- 已有记录与最终结果相矛盾、顺序不成立或原文冲突时，保留已归档最终结果并报校验错误。
  不改写结果，不释放设备占用，不生成订单、余额、返现或提现。
- 投递明确称重失败结束时，可以没有正常的 END/WINDOW_EXPIRED 记录，不要求人工补按。
- 清运末重不可用仍允许保留工作人员的真实关门确认；末重被中断时，确认与 FAILED
  （失败结果）并存，不把中断改成成功或把不存在的重量补成测得零。

MATCHED仅表示本入口核对的原始证据一致，不表示称重成功、配置全部已实际应用、动作
账本全部确认、整机安全恢复、当前袋转换或资金处理授权。结果待分类任务仍保持原状态；
没有新增表、消费完成标记、后端处理任务或占用释放路径。

## 3. 本轮诊断并修复的实际 C 问题

默认配置的称重上限是5秒，满溢静置时间也是5秒，因此重量超时可能早于超声波组结束。
实际 C 投递失败分支此前将整场结果完成时间直接写成称重结束时间，未覆盖之后结束的采样组。
香橙派按原阶段时间核对时会正确拒绝这条互相矛盾的结果。

按 diagnose（复现、对照假设、核对来源、修复与回归）流程建立真实 C/SQLite 反馈循环：

1. 同一实际流程中，原重量在159220毫秒超时，原超声波组在159529毫秒结束，原 MCU
   WORK_RESULT却写159220毫秒；清运对照路径没有该错误。
2. 排查三个候选原因：投递失败分支选错时刻、测试时钟不一致、Pi交接改动原文。
   原设备事实快照与实际测试时钟一致，直接查询的 MCU 结果与 SQLite 正文逐字节一致。
3. 只改变交接延迟为0/4000毫秒，两个投递反例都仍写旧重量时刻，定位到 `poll_final`
   （投递结束组装）失败分支；不是入库或查询时刷新时间的问题。
4. 修复为在精确保存的原末重过程记录中读取满溢组完成时间，取它与原称重结束时间的较晚者。
   未采样组的时间为0，保持既有无组行为。原重量、耗时和过程时间戳全部不变。
5. 增加有回波/全无回波、投递/清运、立即/延迟交接8种组合，均验证结果覆盖原完整阶段；
   延迟交接不能把结果时间改成后来接收时间。清运仍使用真实人工确认发生的时刻。

没有缩短满溢静置时间、删样本、放宽Pi时间校验，或把称重超时失败改成成功。
此次缺口来自两种采集完成时间没有一起进入失败结果组装；由真实业务消费者反向核对
原过程记录的测试将它暴露。回归保留在实际执行链路，不用假最终结果掩盖问题。
没有留下临时诊断日志或替代实现。
