# 原生 UART 2 实际控制报文与 Pi 结果接收 P1G

日期：2026-09-12，承接 [P1F](uart2-edge-dispatch-p1f-2026-09-12.md)。继续授权的本地实现，
没有 SSH、烧录、制作镜像、操作实机、修改 HMI、部署或发布。

## 业务含义

MCU 现在通过同一个实际 C 字节流入口处理启动询问/绑定、原命令/业务/结果和设备事实查询，
并生成完整回复，不再由 Python 测试替它组装。查询不动作；业务命令与配置执行尚未接入。

Pi 从原业务查询取得完整结果身份后，发新编号的只读查询。MCU 持有时返回状态及原始正文；
Pi 完整校验、将正文与待分类任务提交到 SQLite 后，才发精确保存确认。确认失败不重开门、
不建第二个任务。Pi 重启后新查询仍显示持有时，重新核对本地完整原文和任务，再确认同一结果。
保存/释放只是原始事实交接：业务占用、袋子、云端订单、余额、提现都不改变。
专用队列仍等待照片/业务上下文分类，不进入现有云端发送器；迟到完整结果不自动决定资金处置。

## 实现与边界

- `mcu_control_endpoint.c/.h` 组合真实会话、业务记录、结果槽、设备事实与生成的 512 字节流解析器。
  单前台所有者，无 Flash、动态分配、GPIO 写、通用 ACK 或重发。发送回调借用内部缓冲到返回，
  必须有界且不可重入；业务/事实生产者只能在 Feed 调用之间更新核心。
- 仅首次 BOUND 初始化业务槽；ALREADY_BOUND 不清结果。Init 仅在实际 MCU 启动调用，不能因 Pi 断连调用。
- QUERY_RESULT 的 HELD 发两帧：91 字节查询回复及 213 字节原始结果，不是一帧 304 字节。
  精确 RESULT_SAVED 才释放；普通 ACK、旧启动/确认、错误摘要、坏包不清当前结果。
  未处理的业务/配置消息不伪造受理、不消耗命令序号，只记录诊断。
- `McuResultQuery` 复用持久唯一查询编号与新鲜精确回显；`McuResultHandoff` 不从缩略快照猜摘要。
  保存后才确认，最多每周期确认一次；短写/异常不补写，下次新查询或完整结果到达后重新核对。
  RESULT_SAVED_REPLY 没有查询编号，不拿它当新鲜状态；下一 QUERY_RESULT 可观察释放引用。
- COMMIT 失败、损坏原文、缺待分类任务都不确认；同编号异文保留原结果、追加冲突证据而不确认冲突正文。
  存储错误向业务所有者传播，不自动清占用，也不新增普遍人工解锁规则。

## 验证及资源

- 实际 Clang C 动态库 + Python 3.11 + SQLite：单字节启动绑定、Pi 单独重启、全部只读查询、完整结果交接；
  普通 ACK 不释放，MCU RAM 真正重置后的旧绑定/确认不清新结果。100 帧共 2200 字节输入逐帧交付一次；
  CRC、过期半帧、反方向帧、零身份被拒绝。
- Pi 写串口前由另一数据库连接证明已提交；短写/异常后重新打开库恢复；重复不增任务、占用不变；
  失效查询、错结果、坏摘要、损坏原文、缺任务、COMMIT 拒绝不确认。
- 定向 C 入口 7 项、Pi 接收端 8 项通过。完成业务由测试通过公开 BeginAccepted/Complete 接口注入，
  **不能声称完整业务命令已经通过报文入口**；查询/结果交接本身走实际 C 帧解析与编码。
- ARMCC 5 / Cortex-M3 / C99 / O2 独立编译无错误警告；endpoint 对象 Code 7772 字节（含数据252）、
  RO286；持久状态静态预算≤2304字节。未加入 main/Keil，不是整机 ROM/RAM/栈证据；
  校验/SHA、解析回调、调用者与中断叠加仍须预算，原512字节栈未证明足够。
