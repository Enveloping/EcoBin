# 原生 UART 2 香橙派启动与单次发送 P1F

日期：2026-09-12，承接 [P1E 设备事实](uart2-device-facts-p1e-2026-09-12.md)。用户授权不再逐批询问，
按既定计划继续本地实现；不包含部署、烧录、真实门控、云端或数据库变更授权。

## 本批业务含义

香橙派先保存询问编号；只处理本轮回复。MCU 回复未绑定时，香橙派先保存一个未用过的启动编号，
再尝试发送一次绑定。回复丢失或香橙派重启后，只发新询问核对，不重新灌入旧编号。
陌生编号、已退役编号或未取得新回复时不认为会话就绪。该确认不释放原业务占用。

动作发送分成：保存原命令与序号 → 检查原业务条件/期限并由永久账本登记动作 →
业务库提交“可能已发送” → 再检查期限与启动观察 → 只写串口一次。
短写、异常或退出不允许重发旧动作；香橙派只查询原命令。ACCEPTED 只表示 MCU 受理，
不是门已经动作、业务完成或永久动作已确认。NOT_SEEN/启动不符/查不到详情都不自行释放占用。

## 实现与边界

- `EdgeStore` schema 20 新增启动分配、命令和命令观察记录，保留 schema 19 的完整结果与待分类任务。
  启动/命令计数先提交再返回；计数损坏、回退、耗尽不复用。单次启动内动作序号为正 uint32，
  查询/启动编号为正 53 位整数；传输序号不是持久身份。
- 同一命令 UUID 永久对应原消息、原启动、原序号和完整字节。重复准备返回原记录，异文冲突拒绝。
  同时只允许一条待受理决定的命令；明确受理/拒绝后才可准备下一条，但真实业务/永久许可仍另行检查。
  “可能已发送”只能从 0 变为 1，没有清零 API；提交失败不得写 UART，提交后退出也不补发。
- 命令观察完整校验并精确匹配原 60 字节身份。原受理/拒绝保持不变，冲突追加证据并阻止新命令；
  不把启动不符改写为原动作失败。重复不变的查询只保留第一份同状态证据，不每秒新增一行。
- `McuBootSession` 每个新实例重新询问，不把数据库中的“曾识别编号”当作当前就绪。
  绑定回复丢失后读回已有编号即可继续观察；0 回复重复不能再分配一次。每条动作仍必须由 MCU
  核对目标启动编号，因为任何回复产生后 MCU 都可能立即重启。
- `McuCommandDispatcher` 不自动扫描/重放持久命令。显式发送先核对新鲜启动观察、调用授权门，
  数据库提交后再执行授权门返回的最终检查，然后才写串口。发送返回真只表示尝试写了一次。
  只保留最近一个原命令查询器，不随历史动作数无限增长；旧查询回复不能匹配当前查询。
- `NativePhysicalActionGate` 使用已有 PermanentJobSafety 和独立 UpdaterStore：禁止 DisabledJobSafety，
  绑定原许可、业务 UUID、稳定动作键、动作 UUID、消息类型及完整原生正文摘要。存量动作不能凭
  恢复旧业务数据库获得新发送许可。实时发送令牌不持久保存，重启不能沿用它再次放行动作。
  原许可/动作/回执必须由业务所有者先持久保存；原始期限不能重置；当前安全、重量/照片前置
  仍由必需的 `revalidate` 回调检查。该接头没有替代尚未完成的 WorkManager 原生业务接线。
  非动作控制、更新、恢复关门等需要各自明确授权范围，不能强塞进此门或使用空门绕过。
- 授权 RPC、SQLite 提交和最终业务检查都可能耗时；最后期限检查已覆盖提交之后。
  若已登记 ARMED 后停止于真正写入前，不自动伪造成功/失败或撤销记录；后续恢复需按已有
  实时证据及永久账本规则收敛。本批没有自动结束原业务或普遍新增人工解锁要求。
- `NativeUartTransport` 只接收调用者独占、已经打开的串口对象，不自行打开真实端口。
  非阻塞读取，每次最多 512 字节；写入超时必须大于 0 且不超过 1 秒。没有输出队列、flush、
  通用重发、重连重放或协议回退；只允许创建它的前台线程读写。原始字节由生成解析器处理，
  完整帧只交付一次，诊断记录最多 32 项。
  该实现不能阻止外部桥接设备复制报文，P0 的直连 UART“不复制完整请求”前提仍然有效。

## 测试证据

依 `tdd` 技能逐个行为先失败后实现。直接使用 Clang 编译的实际 McuSession C 状态核心，
Python/生成编解码、真实业务 SQLite 和独立永久账本 SQLite；只有物理串口/时钟/本地 RPC
边界由隔离测试控制。没有把 Python 模型当作单片机实现。

- 启动分配提交可由另一连接看到；丢绑定回复、Pi 单独重启、MCU 在询问与绑定之间重启、旧回复迟到。
- 命令保存/精确重复/异文拒绝；实际 C 受理后丢回复，Pi 重启只查询，原动作仅写一次。
- 短写、写异常、查询 NOT_SEEN、明确拒绝消耗序号、相互矛盾决定留证据而不覆盖。
- 两个 SQLite 连接竞争仅一方可取得发送权；COMMIT 被拒绝时不写；真实子进程在 claim
  提交前/提交后 `os._exit`，分别证明回滚与重启后不可重新取得发送权。
- schema 18→20、19→20 的迁移中强制退出，版本/新表一起回滚，原业务与已存完整结果保留。
- 实际永久账本先 ARMED 后才允许串口写；测试故意回退业务行但不回退永久库，新进程令牌被拒绝。
- 授权拒绝、授权耗时过期、提交耗时过期都不发送；最后一种先由失败测试复现再补最终检查。
- 实际 pyserial 3.5 `loop://` / 115200 回环测试，30 份回复跨两个有界读取无丢失、无重复，
  回环中的 EDGE 请求不会冒充 MCU 回复；短写不补写、不调用 flush、无界超时拒绝。
- 本批定向：启动/动作/账本 22 项、串口 2 项通过。扩大回归 582 passed、34 skipped、
  1616 subtests passed（68.20 秒），包含旧协议、更新器、业务安装与迁移边界；Windows跳过项不代表Linux验收。
- 103个生成文件检查一致，旧3个UART制品冻结，OneNet未改；`git diff --check`通过，仅CRLF提示。

C 联合测试当前调用状态核心的公开接口，报文组装由测试边界完成；它不等于 MCU 真实 UART
接收入口、完整命令正文校验或业务执行器已接好。本批未改 MCU C，不能拿旧 Keil 产物声称新增
原生入口已构建。物理 TF 卡掉电、真实串口电气/丢字节和整机业务验收尚未执行。
