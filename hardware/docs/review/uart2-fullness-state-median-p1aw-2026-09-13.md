# P1AW：当前袋子满溢状态的中位数接收与保存

日期：2026-09-13。状态：本地候选已实现并验证，未部署，P5 未整体完成。

## 1. 本批业务行为

香橙派在投递或清运完成后自主上报当前袋子的满溢状态。后端先核对对应已完成业务、
袋子、投口和当次配置，再保存原始测量事实，并按现有规则更新当前袋子的满溢状态。
本批让其中的可用中位数不再因测量仍标为“不稳定”而被拒收：

- 必须是 UNSTABLE + TIMEOUT_MEDIAN，有真实重量、5 秒测量耗时、5～32 个样本；
  传感器健康、故障字段明确为 null，测量身份和整数范围合法。
- 保留原重量、测量状态、样本数、耗时、启动/事件编号；新增保存是否有可用重量、
  取值方法。不会将中位数改称稳定均值，也不只因采用中位数而增加异常或人工审核。
- 当前袋子可以按配置变为 FULL 或 NOT_FULL。FULL 仍沿用原有业务规则阻止后续投递，
  后续有效 NOT_FULL 上报可清除这一项满溢阻碍；其他接单条件不因本批被跳过。
- 计算净重和满溢比例时仍使用上报的皮重证据，并核对上报计算结果；不校准硬件，
  不更新已有皮重。数据库历史命名 latest_stable_total_weight_g 仍是当前总重投影，
  真实取值质量看关联 dev_fullness_state_fact，展示侧不能仅凭列名标“稳定”。
- 对应投递订单或清运完成记录尚未入库时不提前应用：本次事务无残留，原可靠接收链可再处理。
  旧袋、较早事件只保留历史证据和确认，不覆盖当前袋子状态；重复事实不重复投影或确认。
- 最后登记业务确认失败时，设备事实、满溢历史、容量投影、设备时间与确认登记整体回滚。
  本路径不创建投递订单、返现或提现，也不下发开门/关门/称重命令。

这不是“称重准确度已修好”，也不是“设备已具备新的原生端到端满溢能力”。
本批只完成后端实际接收路径，香橙派原生结果上云和主程序接线仍待继续。

## 2. 实际入口与退出的历史流程

实际路径是 OneNet FULLNESS_STATE_CHANGED → 可信设备事实服务 →
ApplyFullnessStateChangedService → 当前袋子投影 → 业务确认登记。
OneNet 公共测量解码此前已支持中位数；本次补了该事件的真实公开入口测试，
没有凭空增加新的线级事件或下行任务。

V25 已将满溢改为设备自主上报，取消后端旧 SAMPLE_FULLNESS 的待执行任务，
并退休旧检测代次。当前主代码没有新建 rec_fullness_detection 的入口。
旧 TrustedFullnessSampleCompletionService 的固定帧形状只保留兼容边界，
本批未将其放宽为原生中位数、未重新激活后端分步采样/复测任务。
后续清理旧入口须按实际调用与切换计划进行，不能把旧兼容处理测试当作原生接线完成。
