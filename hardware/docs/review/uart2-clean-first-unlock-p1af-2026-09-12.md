# P1AF：首次清运开锁、独立断电与原始记录交接

日期：2026-09-12。承接 [P1AE](uart2-postclose-interruption-p1ae-2026-09-12.md)，
开始连接清运执行器。不是完整清运、重启恢复或可运行整机固件；未连接设备、部署、烧录或改 HMI。

## 这一批的业务行为

香橙派按原清运业务发送首次开锁命令。MCU 先核对原清运/配置、开锁前重量已被精确保存、
原开始和操作期限，以及必要的外部准入条件；再预留通电和断电两份记录及事件编号额度。
这些都满足后才保存命令受理决定，进入清运锁的定时通电阶段。同一命令再次到达只返回原决定。

例如锁配置通电 1000 毫秒，MCU 已通电，但香橙派此时失联：

- 定时中断仍独立断电，不等待香橙派保存通电记录，更不等待云端回复。
- 即使前台一直没有运行，也保留原通电和断电两个时间，不拿后一次轮询时间冒充动作时间。
- 定时中断本身迟到时，记录实际施加断电的时间，不倒填成配置截止时间。
- 前台恢复后分别冻结两份原事件；断电不会覆盖尚未交接的通电记录。
- 香橙派提交原文后才确认。确认丢失或香橙派重启只查询、补确认，不再次通电或延长脉冲。
- 正常断电记录保留后 MCU 进入 `CLEAN_ACTIVE`（清运仍在进行），不表示清运已完成，
  不释放香橙派的原业务占用，也不生成最终结果或资金效果。

通电/断电只证明 MCU 发出的 GPIO 控制，线圈健康仍为 UNKNOWN（未知），不证明门位。
首次开锁要求投递门有有效逻辑 CLOSE 目标；PB5 防夹暂停不会单独否定这个目标。
清运门最终关闭仍须清运员确认，不增加自动关闭清运门的行为。

## 代码和接口

- `actuator_runtime.c/.h` 增加原生清运脉冲：在临界区检查原截止时间、逻辑 CLOSE、更新标记、
  另一动作占用及不回绕的本次启动内编号，立即通电；定时器独立断电。前台用精确编号释放
  已完成脉冲，释放仅交出记录所有权，不修改门输出或清除更新标记。
- 原生投递/清运共用旧入口隔离开关。进入任一原生动作后，旧 SetDoorTarget/Unlock 不可覆盖
  它；通电或尚未交出的脉冲也不能被另一投递/脉冲改写。旧现场入口没有被改成自动启用新流程。
- 新 `mcu_clean_execution.c/.h` 保存原首次开锁命令和操作截止时间，接原开锁准入核对、
  双记录预留、受理去重、原始通断记录以及前台阶段推进。
- 工作准备层从单一动作回调改成固定投递/清运两个槽位；各槽只可在启动绑定前挂载一次，
  不能运行时替换，仍由一个入口和一个业务槽拥有串口/业务。两个执行器均检查原业务身份。
- 脉冲或向动作池保留双记录尚在进行时，更新停止在返回前断电，保留原通断时间；前台进入
  `CLEAN_RECOVERY_REQUIRED`（清运待恢复），不伪装正常完成、不自动恢复旧动作。此后已经
  进入 CLEAN_ACTIVE 才发生更新的处理，以及待恢复阶段的后续流程，本批仍未接通。
- 使用已有 `UNLOCK_CLEAN_DOOR` 和 `CLEAN_LOCK_POWER_CHANGED`，没有新消息或迁移：
  Registry **2.0.0-rc.17**、schema25 不变，66 消息 / 52 完整守卫 / 47 黄金帧 /
  1421 流轨迹 / 12 摘要样例 / 104 生成物。旧生成制品和 OneNet 模型未改。

## 验证记录

先通过失败测试证实缺少清运脉冲和执行器，再实现第一条实际 C 开锁/断电路径，逐步补反例。
实际 C 编译为主机库，物理时间、GPIO/采集边界由测试注入；不是目标板运行。

- 新增主机 C 脉冲行为测试：独立截止、保留双时间、重复/并行动作拒绝、精确释放、旧入口
  隔离、更新立即断电及不复活、无 CLOSE/非法时长/到期拒绝、32 位时间回绕及迟到中断。
- 新增 **27 项清运执行专项，4.27 秒通过**：原首次命令单次执行；未保存重量、无 CLOSE、
  安全拒绝、空间不足、错误业务/父命令/时长、再次解锁/恢复身份不能冒充首次；原期限不可
  续期；PB5 不单独判故障；缺前台/更新停止；全局编号只剩一份时拒绝、两份时保住通断记录。
- 其中 **8 项**对真实通电/断电记录分别注入确认写异常、短写、请求丢失和回复丢失，再关闭/
  重开 Pi SQLite。确认之前用独立连接证明原文、业务占用已提交；恢复只查询/补确认，
  原始两份数据不变、称重次数仍为 1、无最终上报任务、业务占用保持。
- 已有 Pi/永久动作账本/C/SQLite 联合测试新增真实清运分支。正常和开锁决定丢失后 Pi 重启
  均通过：写前永久账本为 ARMED（已登记待执行），业务库写入权已占用；重启后只查询原命令，
  开锁报文只写一次。连同原投递两例共 **4 项通过，2.84 秒**。
  交接后账本仍为 ARMED；这证明写前登记和单次发送，不是动作效果核对/账本收尾完成。
- 初轮组合 **145 通过 / 8 失败，76.87 秒**。八项均为新测试在查询有效期结束后读取旧观察；
  客户端正确返回未知。测试改为先断言已过期，再取得新的查询后检查 NOT_FOUND，未放宽
  生产有效期、将未知当空闲或排除测试。另有字段/枚举和“改成原值”的测试准备错误已纠正。
- ARMCC5 核心预算 **1 项通过，4.74 秒**：Code 43864 / RO 1900 / RW 64 / ZI 5888，
  ROM **45828** / 静态 RAM **5952** 字节；比 P1AE +1756 / +208。两个执行器和三个脉冲入口
  均实际链接保留。仅 DO_NOT_FLASH 核心探针，不是完整启动、驱动、中断栈或可烧录固件。
- Clang 静态分析本批 `actuator_runtime`、`mcu_clean_execution`、`mcu_work_preparation` 无警告。
  P1AD 记录的底层称重前置条件告警不在本批修复范围。
