## 1. 已接入实际主程序的部分

| 模块 / 调用点 | 已实现行为 | 边界 |
|---|---|---|
| `runtime_clock`、TIM3 中断 | 连续 32 位毫秒时钟，10 ms 一次推进；周期调度不补发错过的请求 | 不是现场实测的精确时间保证；禁止长时间关中断 |
| `door_control`、`actuator_runtime` | PB6/PB7：01=关、10=开；保存最近有效目标和动作有效位；PB5 只暂停关门，释放后继续；开门忽略 PB5 | 目标不是实测门位，PB4 不参与判断，PB5 不单独代表故障或到位 |
| 主程序 GPIO 适配 | 正常输出统一经过一次 BSRR 寄存器写入，主循环更新与中断互斥 | 除上电初始化清零外，没有旧的分散输出写入；没有更换硬件保护 |
| `clean_lock` | 清运锁使用独立 4800 ms 名义通电时长；再次允许开锁会建立新的截止时刻 | 不再把“8 次采样”作为时间，250 ms 采样不会将通电缩短成 2 秒 |
| F2 更新准备 | 先锁存停止、立即清推杆和锁输出，再回复；PB5 释放、后续旧调用不能恢复输出 | 只保留既有更新停止职责，不代表新增业务取消或重启恢复已实现 |
| `smoke_monitor` | 依据持续时钟每次取真实 ADC 样本，不按积压定时次数伪造连续样本；预热完成一次锁存 | 保留原阈值和去抖策略；修复约 49.7 天回绕后重新预热的问题 |
| `scale_reader`、`usart1.c` | 精确校验 9 字节响应的地址、功能码、字节数、CRC；低字在前、有符号解析；范围检查 | 旧固定帧出口仍将负值投影为 0，未在旧协议中偷偷改成有符号字段 |
| 旧称重请求调度 | 目标间隔改为 250 ms，上一请求未处理完不叠加；200 ms 响应等待使用连续时钟 | 主循环仍有屏幕、超声波等阻塞调用，实际请求/响应分布尚未真机测量 |

业务场景：用户关门时触发 PB5，定时服务关闭推杆输出但保留关门目标；PB5 解除后继续关门。
暂停期间若收到新的开门目标，则按开门方向执行，不再恢复旧关门。若进入 F2 更新停止，
动作有效位被清除，此后解除 PB5 也不会恢复输出。这些动作本身不创建订单、不改变后台记录；
香橙派已有业务占用、永久动作账本和更新准入规则未修改。

状态查询区分“当前 PB5 输入”和“最后实际写入的输出命令”。查询不重新推算未执行的输出，
也不通过查询驱动机械；F3 继续读取实际 GPIO 输出寄存器。

## 2. 已验证、但尚未接入投递/清运结果的称重核心

`weight_measurement` 接收经过校验的原始读数、样本编号、实际完整接收时刻和测量编号。
通过独立 C 程序验证以下候选配置：250 ms 输入节奏、最近 5 点全跨度不超过 100 g 取均值、
最多 5000 ms；仅波动时按本阶段全部合法样本取中位数。其余配置使用计划建议值：
稳定窗口跨度最多 1500 ms，末次读数年龄最多 750 ms，中位数至少 5 点，范围由调用方提供。

- 不先做移动平均；零和负数保留；均值/偶数中位数四舍五入到整数克，半克向远离零方向取整。
- 样本缓存上限 32，两个样本/时间数组合计 256 字节，另有配置和结果元数据；超限显式失败，不覆盖旧值。
- 最终结果一经冻结，不因后续采样或上传时间而改变。新测量必须显式开始，工作管理者负责保存前一结果。
- 完整帧第 4.9 秒收到、主循环第 5.1 秒才处理，仍可纳入；真正第 5.1 秒收到的帧不能纳入。
  调用方必须先按顺序排空已捕获帧，再检查测量截止；晚处理不延长 5 秒采集窗口。
- 数据不足、末次已经陈旧等不伪装成“纯波动可用”。准确度不在软件中自动校准。

该模块已加入 Keil 工程并编译，但**没有接入旧 DD/EF 完成事件**，链接器也移除了其未使用代码。
当前真实业务仍运行旧四点显示滤波、旧稳定逻辑和旧结果清理。模块内状态码不是线上协议枚举。
没有声称现有设备已按新算法结算，也没有将中位数伪装为旧协议的稳定均值。
