# 精简MCU完整主入口与本地固件构建

日期：2026-09-13。范围：精简计划S1的实际MCU入口、S2所需的新称重观测基础；仅本地软件实现和验证。
配套入口是[精简实施计划](../../../docs/planning/mcu-edge-simplified-implementation-plan-2026-09-13.md)。
不是现场验收、完整两端闭环完成或发布许可；未SSH、连接UART/GPIO、改HMI、烧录、部署或写TF卡。

## 已接入实际工程的行为

- `hardware_mcu/USER/main.c`为默认原生主入口，Keil工程纳入真实业务执行器、生成协议、启动文件、中断和实际驱动。
  香橙派业务通道是USART1（PA9/PA10，115200/8N1）；USART2（PA2/PA3、PA1方向控制，115200/8N1）是秤的RS485，不能因协议版本名UART 2.0而混用。
- MCU冷启动建立GPIO与执行器，设置投递CLOSE控制、保持清运锁断电；随后在可选模块初始化前启用10毫秒防夹/定时服务。
  这是控制状态，不声称检测到物理门已到位。PB5仅关门时暂停，解除继续；PB4不作门位判断。
- Pi发来的BOOT_PROBE/BIND_BOOT与配置进入现成端点；START是一次业务授权。
  MCU自行完成首重、动作、关门后测量、选择及最终包；主循环不挂载复杂机械恢复执行器，也不再等第二开门授权。
  完整结果保留到Pi可靠保存后确认；查询/重复确认仍使用原身份。
- CONFIG_COMMIT成功后由实际main回调启用相应烟感策略；其余执行/称重/测距消费者读取同份已校验配置。
  准备器随后发布版本/摘要事实，同批串口中的后续START不会误因尚未发布配置而拒绝。
- USART1和HMI接收由中断进入有界环形缓冲，前台按有限块处理；USART1只运行原生解析器。
  溢出会丢弃不完整队列并重同步，不能把截断内容当成成功命令。
  HMI发送也改为中断排队，避免9600波特率的一组页面更新阻塞前台约百毫秒。
- ADC初始化校准/空读使用有限等待；烟感模块异常不再能无限卡住整机启动。
  超声波改接现有TIM4/EXTI12非阻塞源，不和旧阻塞测距共享定时器。

## 称重传输与恢复观察

真实请求仍是`01 03 00 00 00 02 C4 0B`。新主入口直接把捕获的九字节帧交给有符号解码和既定测量核心，
不通过旧unsigned/负值截零接口，不自动校准。单个读取在途、完整帧时间来自中断；前台先交付已捕获响应，再检查超时。
250毫秒目标、单次5秒上限及既定稳定均值/超时中位数由已应用配置控制。

空闲以及投递门OPEN控制期间，无业务测量占用时可以采集新的只读健康值。
它们与业务测量共享单调读取编号，但保留独立读取策略，**不会改写已冻结的首末测量、旧失败或最终结果**。
新START、关门或末次测量开始前取消尚未完成的空闲读取，并清理对应串口缓冲。
因此下一次实际读数可以供Pi决定是否恢复新接单，不需要重建旧业务。

超时后会关闭请求、丢弃旧缓冲并保留50毫秒重新使用等待；空闲字节也被丢弃。
该等待和串口静默只是工程护栏，**不是厂家保证的最大响应时间**。
Modbus回复没有请求编号，在新请求之后才到达的任意迟到旧回复仍无法仅靠软件编号区分。
现场响应速度、迟到回复和250毫秒读取目标仍须受控实测，详见[厂家资料复核](scale-vendor-manual-review-2026-09-13.md)。

## HMI复用及尚未完成的显示校核

已再次只读查看桌面现有4～8页面截图，没有操作上位机或改屏幕工程。

| 输入/页面 | 实际MCU处理 |
| --- | --- |
| 00/04，当前投递已经OPEN | 请求提前关门，复用当前执行周期及100毫秒换向，不发Pi动作命令 |
| 06/02，当前显示有效选择窗口 | 继续/结束；使用显示中的本轮测量身份，旧阶段排队字节不当作新轮点击 |
| 05，当前清运活动 | 一次真实人工已关闭并请求结束；MCU随后称重收口，不由轮询伪造第二次人工按钮 |
| 07，当前清运活动 | 同次业务再次解锁；开锁期间/结束测量等无效阶段不重放 |
| 01/03或空闲清运按钮 | 不绕过START，不直接驱动机械 |
| page6 | 进入新轮先清旧重量并隐藏数字；真实新读数才显示本轮差值，读数失败/过期隐藏，不刷新旧采集时间 |
| page6.n2 | 根据MCU当前自动关门期限刷新剩余秒数 |
| page7 | 显示本次保留首末重量差及开始单价计算的展示金额；不意味着云端已结算 |

现用清运完成和返回同发05，按已确认语义在清运中都作为结束意图；它不提供“返回但不结束”的独立操作。
旧HMI自行跳页和定时脚本没有重写，仍需S4核对实际按钮/页面时序。
page7静态“六十秒”说明与MCU配置选择时间可能不一致，页面计时一致性尚未通过现场验收。
当前单价布局是固定`0.`加数字控件；仅能准确表示的0.x元价格才显示该数字，其他价格隐藏数字，避免显示上单残值或错误比例。
一般小数单价、无读数占位和状态提示应在S4形成最小HMI修改表，而不是默默把显示局限当作业务数据正确。

## 可重复完整构建

复用本机Keil ARMCC 5.06 update 5 build 528，不下载工具、不打开可见IDE：

```powershell
& ./hardware_mcu/build-native.ps1
```

脚本从当前Keil工程源清单编译，不引用旧目标文件；生成协议C仅链接一次。
采用C99、O2及独立函数段，去除未使用的旧固定帧函数；真实内存区域仍为64KiB Flash、20KiB RAM。
本次最终完整构建成功，编译/链接无错误或告警：

| 指标 | 本次完整固件 |
| --- | ---: |
| Code+只读数据 | 54,448字节 |
| ROM含初始化数据 / 65,536 | 54,600字节 |
| RAM含静态变量和栈 / 20,480 | 11,824字节 |
| 已保留栈 | 4,096字节 |
| Heap | 0字节 |
| Flash余量 / RAM余量 | 10,936 / 8,656字节 |

输出：`%TEMP%/ecobin-native-firmware/ecobin-native.{axf,bin,hex,map,htm}`。
BIN长54,600字节，SHA-256为`71f8f970786fbb5996242a132fe3ac0a5720b20270515f962e834652d06e137b`。
这些是本地构建证据，不是已经生成发布声明、经过现场验收的固件包。

### 栈核查边界

旧启动文件仅留512字节栈，真实链接调用图的已知最长前台链已达1,488字节，因此调整到4,096字节。
调用图仍明确标记`Unknown(Cycles, Untraceable Function Pointers)`，不能把1,488直接当成自动证明的全局上界。

人工展开本次实际接线的函数指针：

- `main → control_poll → Feed → parser → receive → command_received`：当前局部栈24+64+56+56+232，
  加`command_received`已知最大1,032，合计1,464字节；其他已挂载配置/输出回调不超过该分支。
- `main → Preparation_Poll → delivery poll`：24+40+1,360=1,424字节；clean对应1,328字节。
- 已知最长HMI选择链仍是1,488字节。
- TIM3已知最大80字节，TIM4为72，EXTI12为56，USART2为36，USART3为32；
  当前优先级组0使这些普通中断不彼此抢占，另计Cortex-M3异常硬件压栈和对齐余量。

这支持当前4KiB预留有余量，但仍不是实机栈水位和所有异常路径的最终证明。
弱缺省异常处理及故障处理的自循环不应解释成无限递归；NMI/HardFault、编译器变化、后续新增回调仍需重新审查。
S4保留实机栈水位与最长前台/中断时序验证，不据本轮静态预算宣布硬件验收通过。

$env:PYTHONPATH=(Join-Path (Get-Location) 'hardware')

新读取编号与下一业务连续；以及实际C执行器投递、继续、提前/自动关门、防夹、清运重开和一次完成。
主入口源接线检查只证明显式接线，真实STM32完整链接则证明工程可构建；二者都不等于现场UART/HMI通过。

旧固定帧源码另存`main_legacy.c`，不在默认native目标编译。

这仅用于保留旧模式对照，不声称该重建制品与已部署版本一致。
