# P1X：关门后独立称重与原文交接

日期：2026-09-12。继续已授权计划；仅本地实际 C 代码、模拟时间/GPIO 边界和合成 SQLite 库。
未 SSH、连接串口、操作 HMI、部署或烧录。P3 正常业务闭环仍未整体完成。

## 本轮实现

首次投递执行器在真实定时器锁存 CLOSE 后保留该时刻，读取本次已验证配置中的
`deliveryDoorTravelWaitMs`。等待满该配置值后，才启动一个新的关门后测量窗口。
契约既有范围为 30000～45000 毫秒：这是固定机械行程等待，不是称重超时，不控制 GPIO
释放，也不是实测关到位或 PB5 故障判断。本轮没有修改该范围或自动关门计时规则。

- 行程等待从实际 CLOSE 时刻算，不从香橙派确认或前台发布动作事件的时刻算。
- 如果前台迟到，新测量从实际开始时刻取得完整的最多 5 秒窗口，不倒填开始时间或读取历史缓存。
- 测量策略沿用原业务已冻结配置：250 毫秒目标采样间隔，最近五点跨度不超过 100 克取均值；
  5 秒仍仅波动且满足既有样本数量/新鲜度规则时取中位数，没有足够可用数据则留下不可用记录。
- 每次阶段重新建立测量序号和样本窗口；首次重量保持独立，关门后重量有不同测量身份。
- PB5 持续触发时仍保留 CLOSE 目标、暂停输出；它本身不阻止本次称重、不证明门位。
  如果在开始称重前已进入更新停止或 CLOSE 动作失效，则保留阻断阶段，不启动新的测量。
- 未等待开门/关门动作证据的保存确认才采样；两份动作记录仍独立保留，不被重量记录替换。
- 结果按原 START 命令、原投递 session、投口、配置版本与轮次 1 组装为
  `WORK_POSTCLOSE_WEIGHT_READY`，通过既有过程槽/查询/精确保存链交接。
- 延迟发布不刷新终态重量时间。保存确认丢失时，香橙派重启后重新查询同一份原文，不重新称重或开门。

准备模块新增共享的 `McuWorkPreparation_PollMeasurement`：负责实际阶段核对、测量观察、
一次分配身份、组装并保留完整过程原文、退休本地采样缓冲。首次重量和关门后重量共用这条路径，
但各自的结果/时间记录互相独立。它不改变业务阶段，不代表香橙派已保存，更不授权机械动作。

成功测量后，执行器进入 `DELIVERY_WAIT_SELECTION`（等待本轮继续或结束选择）；
不可用时进入 `DELIVERY_FINALIZING`（等待异常完成结果组装）。这两个阶段都仍保持原业务占用。
当前**尚未生成选择记录或完整结果**，也不自动上报、清占用、核销永久账本或产生资金效果。

## 本地验证

按 `tdd` 技能先加入公开线级行为测试，实际看到“仍停在关门等待阶段”的失败，再接通新测量。
首条测试及既有执行测试通过后，提取共享测量保存逻辑，105 项准备/首次执行/开门前置回归通过。
随后扩展真实数据和交接边界测试，没有用另一套测试状态机替代生产 C 状态机。

- 新增关门后测量专项 **10 passed**：30 秒边界、45 秒真实配置、不同阶段样本隔离、均值、
  5 秒中位数、零读数/不足五点的不可用记录、PB5 与更新停止、32 位时钟跨界和前台延迟。
- 两项实际 Pi `McuProcessEventHandoff` + C + SQLite 测试覆盖保存确认在发送前丢失、MCU 收到后回复丢失。
  在每次发送精确保存确认前，由第二个 SQLite 连接读回已提交原文；重启后只查询/确认，测量序号保持 2。
- 专项联合测试保留全局事件序列：首次重量、开门、关门、关门后重量依次占不同编号；
  重量事件关联原 START，而开关门事件仍关联真实首次开门授权命令。
- 相关定向组合 **152 passed**（当时为前 9 项新专项，加既有执行/准备/开门前置/称重/交接与容量）；
  后补 45 秒配置专项后，上述 10 项专项全部通过。组合重叠，不相加。
- 104 个生成物一致性检查通过；Clang 对本轮两个生产 C 模块静态分析无诊断。
- ARMCC5 核心链接探针：Code36696、RO1864、RW56、ZI5584；ROM **38616**、静态 RAM **5640** 字节。
  相比 P1W 增加 568 字节 ROM、96 字节静态 RAM；明确保留共享测量入口和实际执行器实例。
  `DO_NOT_FLASH` 仅链接，不是正常 main、全部驱动、中断栈、完整可烧录固件或目标板证明。

- 扩大回归 **1082 passed / 34 skipped / 1624 subtests passed，零失败**，耗时 261.80 秒。
  范围包含全部 `contracts/tests`，本轮投递/称重/过程与动作交接、配置/会话/事实、结果槽、
  SQLite、安装/更新、旧固定帧适配与永久账本相关套件；包含最终 10 项新专项。
  34 个跳过项不计为通过，也不是 Linux/Pi 或真机证明；没有因为历史失败新增跳过。
  SQLite 强杀恢复用例本次通过，但历史偶发问题仍未宣称修复。
- 文档/跟踪改动的 `git diff --check` 和本轮未跟踪源码、测试、记录的空白检查通过。
