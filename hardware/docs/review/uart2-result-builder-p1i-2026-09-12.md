# MCU 实际测量到完整结果组装 P1I

日期：2026-09-12，承接 [P1H](uart2-command-guards-p1h-2026-09-12.md)。本地实现，未部署、烧录或操作实机。

实际 C WeightMeasurement 取得可用终态后，现在可以把它转为明确的测量事实，再由 C 组装完整
WORK_RESULT、计算 SHA-256 并冻结。原业务 UUID、原命令、启动和投口从已受理业务记录读取，
不会由结束调用者重填成另一笔业务。新结果使用递增且不回绕的 RAM 结果号；失败不消耗编号。

## 接口与责任

- 新 `mcu_result_builder.c/.h` 是前台结果生产者，不是业务状态机或动作授权器，不包含 GPIO、串口或 Flash。
  结束原因、轮数、清运动作号、人工关门事实、完成时刻和使用的配置版本由业务所有者提供。
  最终仍通过生成的完整语义/摘要校验及 McuWorkState_Complete 的原业务身份核对。
- `McuResultMeasurement_FromAvailable` 只接受实际核心的稳定均值/超时中位数，不把运行中、
  缺样本、配置错误或容量错误变成可用重量。测量 UUID 与 UART 事件号由其所有者明确提供；
  不悄悄把本地 measurement_id 当作事件号。校准版本只是事实，不自动校准。
- 缺值记录显式选择 NOT_TAKEN / MCU_RESET_LOST 并将其余槽清零；不会从新袋测量补旧重量。
  真实失败可提供明确失败事实，但本批没有自动推断故障原因或实现失败业务分类。
- C 摘要计算由生成器从原有 Registry 摘要定义生成；允许输出写入结果自身摘要槽。
  组装使用调用者外部、不重叠的199字节缓冲；失败可以改变临时缓冲，但不改变保留结果。
  已持有结果只有完全相同的重复组装可成功，改读数/改时间都不能覆盖；释放后不能再完成旧业务。
- 仍不释放 Pi 业务占用、不生成云端订单或资金。测量取值、完整正文与完整业务执行是不同层：
  START/RESUME 受理和机械流程仍由测试经公开接口安排，不能声称完整业务命令已走 UART 执行。

## 证据

依 TDD 先复现缺少实际 C 组装模块，再实现。Clang C99 警告视为错误，15项通过：

- 真正运行 C 测量核心：5点稳定均值（含实测0克和负值）；20点上下波动、5秒到期中位数为0，
  区分“中位数0克”与“旧重量丢失”。Python只解码并核对C算出的摘要，未代组装正文。
- C 结果组装 → C 结果槽 → 实际C字节流查询/回复 → Pi接收/SQLite提交 → 精确确认 → C释放，
  全链路本地通过。UART事件号独立于本地测量号，原文与一个待分类任务保存。
- 精确重复、异文拒绝、释放后拒绝重做、新业务结果号递增、旧确认不释放新结果；
  结果号UINT32_MAX耗尽时不回绕，也不改现有业务/引用。
- 错启动、前后同测量、缺值夹带数值、投递夹带清运事实、短缓冲及非可用核心状态均拒绝。
- ARMCC5 / Cortex-M3 / C99 / O2 无错误警告；独立builder对象 Code1220（含数据46）、RO286。
  不等于整机ROM/栈预算，未加入main/Keil；测量/业务所有者及中断预算仍待完整链接审查。
- 契约24项通过、0 notes，103生成文件一致；三端31帧/566流轨迹/4摘要向量不变。
  扩大回归619 passed、34 skipped、1616 subtests passed（89.72秒）；跳过项不视为真机通过。
