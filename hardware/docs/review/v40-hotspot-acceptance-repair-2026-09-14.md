# v40 热点验收 UART 与称重零点修复

日期：2026-09-14。对象为已写入并启动的 v40 HIL 卡以及真实 STM32、RS485 秤。
本记录只证明“检查控制板与传感器”步骤已经恢复；没有执行投递、清运、摄像头或断电动作验收，
不能据此宣称整机验收完成。

## 1. 现场故障与根因

热点页面点击“检查控制板与传感器”后没有可见响应，称重变送器发送指示灯也不亮。香橙派本地
HTTP 请求复现为 502。工厂验收主线程在进入服务循环前打开 `/dev/ttyS5`，但原实现使用
`ThreadingUnixStreamServer`，把每次网页动作交给另一个线程；`NativeUartTransport`会拒绝非
打开线程访问，因此请求在写出任何 MCU 字节前以“native UART requires one foreground owner”
失败。

工厂 Unix socket 服务改为单线程串行处理。UART 的打开、网页动作和读写现在由同一线程完成；
每个本地客户端仍有2秒读取上限，监听队列保持有界，慢客户端不能无限占用执行器。生产业务
UART所有权没有改动。

## 2. 真实称重事实与范围修复

线程修复后，真实请求立即收敛为 `MCU_WEIGHT_FACT_UNAVAILABLE`。为了区分通信故障和范围策略，
临时只扩大 MCU 的观测范围并读取原始事实，不发机械动作。连续6次均为：

- `scaleReadStatus=VALID`；
- `scaleWeightGrams=-25623`；
- 采集序号持续增长，标定版本与所下发配置一致。

因此RS485地址、115200/8N1、查询命令、CRC和当前字序均能工作。实际失败是工厂配置把绝对值
下限固定为 `-5000 g`，而现场秤存在约 `-25.6 kg` 的稳定零点偏移。工厂称重验收本来就以
“加载值减空载值”和“卸载值回到空载值”作为依据，绝对零点不应代替差值判定。

正式工厂配置版本升为3，绝对观测范围调整为350 kg传感器量程内的
`-350000..350000 g`。参考物仍只允许 `11..350000 g`，误差仍为正负10克；稳定样本、差值和
卸载回零校验均保留。报告、采样轨迹、MCU最终结果映射与本地封存校验同步接受该范围内的有符号
绝对值，不会把负值改写为0。

## 3. 辅助传感器边界

现场同时取得：烟感 `NORMAL`，超声波 `UNAVAILABLE`。按已确认规则，烟感、超声波满溢和摄像头
不是投递或清运结算必需数据；失败要展示和留证，但不单独阻断业务。因此：

- `VALID`仍保存实际距离、阈值和满溢判定；
- `NOT_OBSERVED/UNAVAILABLE`保存真实状态，距离和满溢判定为空；
- 不把不可用伪装成“无遮挡”或“未满”；
- 热点页面增加满溢采集状态及烟感状态文字；
- 称重仍是必要模块，读不到有效重量时仍不能完成称重步骤。

同时修复原生 MCU 启动编号在旧自检清洗器中被误限为32位的问题；当前真实编号
`8000000000000001`属于协议允许的安全整数范围。

## 4. 分层验证

自动验证分两层：

- 原生UART、工厂服务、报告契约、封存、热点投影、首启事实等相关测试共362项通过；测试用的
  丢回复握手窗口由易受主机调度影响的20毫秒改为100毫秒，生产默认值仍为独立验证的250毫秒；
- 修改前新增的同线程UART所有权测试能够稳定复现旧实现失败，修改后通过。相关前序回归另有
  196项通过。

真实设备验证为第三层：

- 修复前真实热点动作返回 `HTTP 422 / MCU_WEIGHT_FACT_UNAVAILABLE`，证明线程故障已消除；
- 范围与辅助传感器修复后，同一热点动作返回 HTTP 200；
- 工厂状态由 `MCU_CHECK_FAILED`、revision 2 变为 `MCU_CHECK_PASSED`、revision 3；
- 下一允许动作是 `CAPTURE_EMPTY_WEIGHT`；公开事实包含固件 `1.0.2-hil.6`、启动编号
  `8000000000000001`、空载 `-25623 g`、烟感正常和超声波不可用。

当前卡已热更新。后续制作镜像时必须从本仓库重新构建，不能只依赖这次对 v40 已安装文件的
原位替换。

## 5. 投递结果被辅助满溢事实阻断

继续真实验收时，MCU已经完成投递、保存最终结果并将完整 `WORK_RESULT` 发给香橙派，但热点页
停在“执行受控恢复”，原因码为 `MCU_FULLNESS_FACT_STALE`。香橙派的UART持久账本证明：原始
结果包存在、结果计数为1、投递 `START` 只发送过1次；故障发生在结果映射阶段，不是机构没有
完成，也不是结果丢失。

根因是香橙派对 `fullnessReadStatus=UNAVAILABLE` 仍检查采集时间。不可用状态不代表一次可用的
物理观测，MCU允许其时间保持启动默认值0；运行一段时间后，该默认值会被错误判断为“有效事实
过期”。自检中的烟感和满溢映射存在同类边界。

修复后的规则是：

- 满溢状态为 `VALID` 时，继续严格校验采集时间以及距离或红外值；
- 烟感状态为 `NORMAL/ALARM` 时，继续严格校验采集时间；
- 辅助传感器为 `UNAVAILABLE/NOT_OBSERVED` 时保留真实警告和空测量值，不对不存在的观测执行
  新鲜度判断，也不阻断投递结果；
- 称重仍是业务必要事实，其有效性和新鲜度校验没有放宽。

先增加现场形态的失败测试，旧实现稳定报 `MCU_FULLNESS_FACT_STALE`；修改后原生UART测试39项
通过，工厂验收服务、测量及报告契约110项通过（3项按测试环境跳过）。随后把修复热更新到
当前v40卡并只重启热点验收服务。

热更新后执行原“受控恢复”，香橙派从持久账本映射已保存结果并向MCU回执保存成功，未重发
投递 `START`：动作序号仍为17、发送次数仍为1、结果计数仍为1。验收状态从
`DELIVERY_WAITING_FINAL_RESULT`进入`DELIVERY_AWAITING_AREA_CONFIRMATION`，等待现场人员确认投递
区域安全；这项人工安全确认完成前，不把投递动作写成验收通过。

## 6. 2026-09-15 后续完成事实

项目负责人随后完成投递区域安全确认及完整清运现场操作。最终热点厂家验收状态为
`PASSED/COMPLETE`、revision 41；控制板、双摄、投递、清运和称重检查均为通过，升级线路为
`NOT_APPLICABLE`。本事实取代上一节“仍等待投递区域安全确认”的现场状态。

该结论只覆盖厂家热点 HIL，不证明后续生产运行时、OneNet、反向 SSH、订单、COS 或资金闭环。
v40 完成注册后又暴露了首次启动 gate 和 UART v2 作业授权入口问题，继续处理前必须阅读
