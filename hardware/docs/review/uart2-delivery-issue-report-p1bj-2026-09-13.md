## 已实现及业务效果

香橙派在 P1BI 已经提交原投递问题判决后，由 `NativeDeliveryIssueReporter.prepare` 为原业务建立
问题上报待办。重启判定和“完整包归档前优先”仍由原归档事务负责，上报器不能根据超时自行归档。

- 新事件 `DELIVERY_ISSUE_ARCHIVED` 表示原问题结论：原因固定为
  `MCU_RESTART_FINAL_RESULT_UNAVAILABLE`（单片机重启，未取得最终结果包），业务价值固定 `NONE`。
  保留原设备、投递、云命令与摘要、原始 MCU START、正向重启回复及已知过程记录数量。
- 新事件 `DELIVERY_ISSUE_EVIDENCE_APPENDED` 表示给原问题追加证据，分为归档上下文、原过程事实、
  归档后已核对身份的完整结果三种。原问题、原投递、原命令及归档摘要必须一致。
- 两事件均为可靠事实，不复用旧人工 `QUARANTINE_DELIVERY_RECOVERY` 服务或
  `DELIVERY_RECOVERY_QUARANTINED` 事件；没有伪造操作人员、现场确认或扩大旧接口权限。
- 不生成正常 `DELIVERY_COMPLETE`，不释放本地占用、不完成永久许可，也不改袋/皮重或后续业务。
  本批网络确认只能代表传输接收，不能代表后台问题处理、关门检查或恢复接单完成。

例如首重、末重和结束按钮都已保管，但未取得完整最终包就确认 MCU 重启：先保留原归档，
随后可靠上传原上下文及全部已有过程证据。以后取得原完整包，只新增完整结果证据，不重发正常投递完成。

## 证据分片而非截断

OneNet 生成器的字符串字段上限为 512 个字符，完整业务上下文可能超过此限制。
每片最多承载 256 个原始字节的十六进制文本，携带完整证据摘要、总字节数、片数、片号和原证据编号。
不截断诊断文字、不丢已有测量，不新增 COS 授权或照片流程来绕过大小限制。

归档上下文摘要覆盖本地原归档 JSON 的精确 ASCII 字节（键排序、紧凑分隔、非 ASCII 转义），
不是重新按 JCS 序列化后的字节。过程事实使用原指纹对象的精确字节；完整结果使用原 UART 正文字节。
事件外层的 `payloadSha256` 仍采用原 OneNet JCS 规则，两种摘要不能混用。

每个问题/证据种类/证据序号/片号唯一，对应发件事件和原文同时提交。
一次生成最多 100 个新事件，默认 50 个；分批中断后重新调用从原绑定续作。
重复调用不换编号、不刷新原事件、不重发新语义；迟到完整包只增加原问题的结果分片。

## 后台入口已接，事务处理尚未接

`OneNetEventDispatcher` 已解码两事件、校验原身份和分片结构，并通过永久设备身份解析器交给
可靠收件边界，独立来源命名空间为 `onenet.delivery-issue`，不会映射成正常投递完成。
`NativeDeliveryIssueEvidence` 对原 START 命令摘要、业务/投口/启动身份和正向启动回复作有界校验。
单片证据还验证完整 SHA-256；多片完整摘要须在后续后台组装时校验，不能只靠每片格式放行。

**尚未实现**后台新问题表、原投递收尾事务、跨分片组装/完整结果身份复核和专用业务确认。
`TrustedPlatformDeviceAssetFactService` 尚未注册这两类处理器。因此本批“接收入口测试通过”只证明
格式及可靠收件适配可用，不代表生产问题落库或任务已完成。不得先导入物模型/部署候选再等待补齐处理。
原人工问题接口和正常后端结算服务未在本批改动。
