# 原生 UART 2 动作记录预留核心 P1T

日期：2026-09-12，承接 [P1S 动作结果校验](uart2-actuator-events-p1s-2026-09-12.md)。
仅本地实现和测试，没有 SSH、真实串口、GPIO、部署、烧录、HMI 或云端操作。
Registry 仍为 `2.0.0-rc.11 / ACTUATOR_EVENT_GUARDS_NOT_RUNNABLE`，SQLite schema22 不变。
本批是可靠动作交接的 **MCU 内存预留部分**，不是串口交接、香橙派落盘或机械执行已经完成。

## 完成的模块

新增 `hardware_mcu/USER/mcu_actuator_event_journal.c/.h`：
每个 MCU 启动共用一份、由单一前台执行者访问的 8 条动作记录池。
无动态内存分配、Flash 写入、GPIO 操作、计时器或自动发送行为。
只接受 P1S 的投递门输出、安全关门结果、清运锁供电变化三类合法原始报文。

未来执行器在清运锁通电之前，应先申请两条位置，分别用于通电与断电。
申请成功后，即使通电记录一直没有收到保存确认、其他位置也全部占满，
断电原文仍可写入已经预留的位置，不需要等香橙派腾出容量。
当前测试证明的是这个存储行为，**并未证明实际断电调度或硬件输出已经接入**。
容量不足只返回申请失败，不抢占别人的位置、不覆盖原文，也不直接设置故障或结束业务；
是否拒绝新动作由尚未接入的业务执行器处理，不能让它妨碍已经安排的断电。

### 对外接口及边界

| 接口 | 实际行为 | 不代表什么 |
|---|---|---|
| `Reserve` | 一次性申请 1～8 条位置，全成或全不成，返回含启动编号的预留凭据 | 不是动作授权，不预留全局事件编号 |
| `Freeze` | 校验完整内容、当前启动和新事件序号后，复制不可变原文 | 不生成动作，不替代原命令/业务归属检查 |
| `CopyNextHeld` | 按事件序号读取下一条未确认原文，不改变记录 | 返回空不是从未动作，也不是业务完成 |
| `ConfirmSaved` | 逐字节匹配原始消息后，只释放该条数据 | 是本地 API，不是新 UART 消息或 SQLite 提交证明 |
| `Cancel` | 仅在整组尚未发布任何记录时取消容量预留 | 调用者仍须确认动作未开始，不能拿来取消已开始动作的后续断电记录 |
| `Init` | 实际 MCU 重启/新绑定时初始化 | 禁止用于 Pi 重连、丢确认或清业务占用 |

本地保存确认使用现有结果状态枚举表示：本次释放、已经释放、记录不在缓存中、身份冲突、
启动不一致；非法入参为 0。它不新增线级确认格式，不扩展测量用 `PROCESS_EVENT_SAVED`，
也没有挂到旧的传输 ACK 上。以后串口交接层只能在香橙派真实提交并精确确认后调用它，
不能仅凭报文收到、写操作返回或从本模块读到了原文就自行调用。

## 关键保证

1. 预留失败不消耗部分位置，也不修改输出凭据。已经预留、尚未发布的位置不会被其他申请占用。
2. 同一位置首次成功后原文不可改写；相同原文重交是幂等调用。
   保存确认后的相同原文重交不会重新成为待处理数据；真正的新事件仍可独立保留。
   本模块只负责事件数据去重，**不负责证明业务命令不会重复执行**。
3. 保存确认先验证完整报文，再比对当前启动、事件序号、消息类型和所有原文字节。
   错误命令、操作编号、投口、供电状态、时刻或消息类型均不能释放另一条记录。
   保存通电记录后，仍预留的断电位置不能被整组取消；通电位置被复用也不改变这个事实。
4. 已确认的身份和原文优先暂留，申请新容量时先用从未占用/已取消的位置。
   确实需要复用已确认位置时才淘汰其缓存；以后旧确认返回 NOT_FOUND，不能推断原动作没发生。
   未确认原文和仍需使用的预留位置从不自动过期、淘汰或覆盖。
5. 预留编号在本启动内递增、不回绕；凭据同时绑定 MCU 启动编号。
   新启动即使再次分配相同的局部预留编号，旧凭据和旧确认也不能作用于新记录。
   MCU RAM 仍不做掉电保存，重启丢数据按已确认的上层分类规则处理，不补造原事件。
6. 新发布事件序号必须大于本模块已见的高水位，不允许跨类型/跨预留重复使用；
   序号达到最大值后不能回绕。读出和确认仍可工作。
   本模块不拥有系统全局序号分配器，不能用自己的计数另发一套事件编号。
7. 所有操作都只扫描固定 8 条记录，不等待串口、磁盘或其他执行者。
   调用方缓冲区与记录池不允许别名重叠，实际运行须只有一个共同记录池/前台所有者。

## 本轮未接入的前提

- **全局事件编号额度**：只有 RAM 空位不够。若通电后其他生产者耗尽全局事件序号，
  仍会没有合法的断电事件编号。实际执行前必须由统一分配器同时保证后续事件额度，
  不能临时回绕、给断电重复编号、预先伪造断电事实或延迟断电。本批明确保留这个缺口。
- **实际原命令/业务关联**：预留凭据仅标识容量，不是开始命令、首次授权、自动关门、
  清运再次开锁或安全命令的替代身份。执行器仍需依据原业务保存这些关系。
- **串口和 Pi 落盘**：`McuControlEndpoint` 尚未持有/查询本池，未新增动作保存回执消息，
  Pi 没有对应 SQLite 动作表/回执事务，不能把本地 `ConfirmSaved` 称为端到端交接。
- **动作**：100 毫秒换向等待、单次输出、自动关门、独立断电调度、真实按钮请求和恢复仍待接。
  本池不检查照片、期限、实际安全/更新互斥或配置应用，不能由容量申请成功推出可开门。

数据交接不会产生订单、余额、审核或提现，不释放业务占用，也不决定下一单资格。
PB5 只暂停关门、解除继续，OPEN 忽略 PB5，以及逻辑门状态取最近有效方向的共识均未修改。

## 验证证据

使用 `tdd` 技能逐步推进：先写通电未确认仍可记录断电的测试，确认缺少实际 C 入口后实现；
随后分别补精确保存释放和预留取消测试，确认链接失败后扩展模块。
最后测试发现新申请过早淘汰已释放身份，即使还有空位也会丢失重复确认依据；
用真实 C 行为得到预期 ALREADY_RELEASED、实际 NOT_FOUND 的失败后，改为优先使用空位。
没有用 Python 替代 C 数据结构或执行逻辑；Python 只提供边界输入与断言。

- 新模块 **45 项测试通过**，含三类原文、全占满与部分预留失败、错误确认、启动切换、
  容量复用、非法长度/身份、最大事件序号及 100 轮共 800 条记录的发布/乱序确认/重交。
