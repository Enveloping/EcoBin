# P1AK：原生动作身份持久关联与永久账本核对

日期：2026-09-12。范围：本地原生 UART 2.0 候选、实际 MCU C 动态库、Python 3.11、
隔离的业务 SQLite 和永久更新器 SQLite。没有连接设备、操作真实串口/GPIO、修改 HMI、
烧录、部署或改真实数据。P3/P4 仍未整体完成。

## 本批行为

香橙派发送第一次投递开门或第一次清运解锁前，先把原业务许可、动作号、回执号、动作摘要
与完整串口命令共同保存。永久更新器仍独立负责动作许可；只有事前关联保存成功，才继续
申请永久动作记录并授权一次发送。保存失败时既不授权输出，也不写串口。

单片机的实际 C 控制模块执行后，输出记录经既有精确交接保存到香橙派。新的核对器从当前
业务占用和持久关联中找回原动作，检查完整原命令、原开始命令、二者的实际受理回复、
原首重精确保存关系、原启动编号/业务/投口，以及两条实际输出记录。

- 投递：仅首次授权，必须是第一轮原开/关方向输出，均已交给控制模块、没有拒绝原因，
  输出先后关系和原自动关门时间一致。这里不是推杆实际位置或物理关门到位测量。
- 清运：仅首次解锁，必须是原命令的通电和断电记录，顺序正确，且通电持续时间不少于
  原命令要求的脉冲时间。不能由此推定线圈健康、清运门已经开启或人工已经关门。
- 缺少原受理、原首重保存关系、任一输出，或只有短暂/中断脉冲时，不生成正常执行证明；
  仍保留原动作待核对和业务占用，不补零、不声明未执行或安全失败。
- 报文身份冲突、错误启动/业务/投口、额外重复输出、错误时间顺序，以及回执身份冲突，
  均拒绝确认。已有原始证据和冲突原文继续保留。

核对通过只将这次机械输出动作记为 `CONFIRMED / EXECUTED`（账本已确认执行），原业务许可
仍为 `ACTIVE`（尚未结束），业务占用不释放。没有创建订单、清运完成、新袋基准、余额、
自动提现或云端上报。后续还需业务最终结果、清运员确认、恢复及分类等独立条件。

例如清运锁已正常通断电，随后清运过程因其他原因中断：正常脉冲事实与业务中断是两件事。
本核对只证明原输出，不把后续业务变成成功，也不消除中断原因。后续异常策略不能直接用
这条动作确认当作清运完成或放行新业务的依据。

## 两个数据库之间的恢复

业务库和永久更新器库不共享事务。核对器先保存不可变完整证据包、带用途前缀的 SHA-256
摘要及 `PENDING`（待永久确认）记录，提交后才调用既有永久确认接口。证据包包含原命令、
原受理报文、首重及精确保存回执、两条输出及其回执、原许可和动作身份，最多 8192 字符。
这不是新的 OneNet/UART 消息，也不使用旧固定帧仅本进程有效的结果令牌。

如果永久账本已提交但回复丢失，香橙派重启后读取同一条持久关联和同一份证据，先查询
永久账本：原回执和摘要完全一致才确认本地完成；未提交时仅重试相同账本确认，不重发
串口、不重新申请动作授权，也不换回执号。新增相同受理查询不会改写已固定证据的摘要。

数据库快照内核对原文；外部调用前和本地最终确认前再次检查。不能假设两个数据库能够
原子阻止调用期间新到达的矛盾记录：该情况保留永久库已确认的原历史证据，同时保留业务
库的新冲突及待处理状态，继续阻止错误业务完成。测试明确覆盖这个边界，不宣称跨库原子性。

“先查询尚未见到，随后延迟命令被接受”不是事后矛盾；“已经接受后又声称尚未见到”仍由
命令存储锁存冲突。完整历史输出不因当前时间较晚而失效，但本批自动核对只处理仍由原业务
占用、原永久许可仍活动的动作；不是放宽新动作的时效、安全或当前启动检查。

## 文件与存储

- `hardware/mcu_action_evidence.py`：持久关联校验、原始事实组合、永久身份核对和待办恢复入口。
- `hardware/mcu_session.py`：永久 PREPARE/ARM（登记/允许发送）前提交业务库原身份关联，并复核原期限。
- `hardware/edge_store.py`：候选 schema **28**，新增 `native_action_binding` 与
  `native_action_confirmation`。命令、动作、业务动作键和回执保持唯一；读回重新核验身份/摘要。
  候选待办按当前占用查询，每批最多 32 条，每个首次动作最多取 3 条输出以识别重复记录。
- `hardware/tests/test_native_action_reconciliation.py`：新专项；复用
  `test_mcu_delivery_execution.py` 的实际 C/Pi/永久账本/SQLite 联合场景。
  其他原生存储迁移测试仅更新当前版本断言及历史数据库的构造，不放宽生产规则。

schema27→28 保留原记录，迁移中创建表或写版本失败则整体回滚。没有事前关联的已发送旧
命令，不能在迁移后补造许可/回执再宣称核对成功。当前签名运行清单的 schema25 声明和
禁止候选直接运行/发布的边界保持；新模块打包、版本接收面和成对发布仍属后续发布工作。

UART Registry 仍为 **2.0.0-rc.20 / CLEAN_INTERRUPTION_CUSTODY_NOT_RUNNABLE**；没有改线协议、
生成物、OneNet、永久更新器 RPC 规则或 MCU C 源码。此前 ROM51648/RAM6096 只代表 P1AJ 核心
探针，不是本批新固件构建，更不是整机资源/真实驱动/栈容量证明。
