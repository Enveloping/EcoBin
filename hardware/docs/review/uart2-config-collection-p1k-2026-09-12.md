# 原生 UART 2 完整配置集合 P1K

日期：2026-09-12，承接 [P1J 配置分段校验](uart2-configuration-guards-p1j-2026-09-12.md)。本地实现，未操作设备。

## 本批完成

新增实际 C 的 `McuConfigCollection`：独立、前台单所有者、最多 512 字节的候选集合。
收到开始、设备、全部投口和提交分段后，按投口号排序计算完整 `mcuPayloadSha256`；
共享同一应用编号、配置版本、内容摘要、单片机配置摘要及分段数才能组成一套。

- 缺段不输出完整配置；之后补齐原段可以完成。每条命令摘要正确不代表整套摘要正确。
- 相同分段内容重复到达不覆盖；别的配置、同一位置不同内容、错误启动号均不改原集合。
- 原集合完成后保持不变，交付或丢弃后须由所有者明确开始下一集合。
- 输出是精确的摘要原文字节，不是带填充的 C 结构体；短缓冲区不写入。
- `COMPLETE` 仅表示收齐且核对成功，**不是 `APPLIED`（已经生效）**。不改正在使用的配置、
  GPIO、Flash、业务或会话序号；命令受理仍须经过实际会话防旧命令检查。

## 证据和边界

- 新增 15 项测试：实际 C 动态库、两投口全部到达排列、缺段、混入其他配置、重复/冲突、
  整套摘要错误、错误启动号和六投口最大容量；输出及状态尾部内存边界检查通过。
- ARMCC5 / Cortex-M3 / C99 / O2 编译无错误警告；独立对象 Code 9644（含数据 154）、
  RO 335，无 RW/ZI。不等于整机链接后的 ROM 或调用栈预算。
- 契约 24 项、0 notes；103 个生成文件一致，31 帧、735 流轨迹、4 摘要向量通过。
- 扩大回归：643 passed、34 skipped、1616 subtests passed，98.46 秒。
  Windows 跳过项不代表 Linux 或真机已验证。

本批保持 rc.7/schema20。生成器新增配置摘要原文布局常量，旧 3 个运行制品仍冻结。
P1K 测试中的配置样例仍是旧 6 秒/10 点参数，因此只能作为完整候选，不能宣称新称重策略已生效。
