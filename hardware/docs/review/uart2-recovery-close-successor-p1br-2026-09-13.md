# P1BR：未授权准备退役后的独立关门尝试

日期：2026-09-13，接续 [P1BQ 未授权准备退役](uart2-recovery-close-retirement-p1bq-2026-09-13.md)。
继续原计划 P4（重启恢复与动作账本），本批不是完整恢复接单，也未部署到设备。

## 本批解决什么

例：香橙派已把恢复关门 A 保存到本地，但还没取得永久管理层的发送授权就重启。
P1BQ 能保留 A 并证明它从未授权，本批进一步允许基于这份证明创建独立关门 B。
“退役”只表示 A 不再取得发送资格，不表示推杆已停止、门已关到位或原投递处理完成。

1. 香橙派明确指定前一次关门编号，核对原问题、原投递占用和原开门证据；当前单片机启动编号必须等于原目标编号。
   前一次准备必须已在两端确认为“从未授权，因此未执行”，仅保存撤回意图还不够。
2. 香橙派在一个事务中为 B 保存新动作编号、回执编号、恢复尝试编号、串口命令序号和完整父证明。
   新记录指向 A，A 的命令及全部证明保留；不能覆盖 A 或复活其旧发送令牌。
3. 永久管理层独立核对原许可、完整历史链和前一次未授权退役证明，才允许 B 取得新授权。
   发送仍需当前检查和原期限内的最后核验。只有本次实际创建者持有内存发送资格，最多写串口一次。
4. 重试“以 A 为前一次准备”只返回原来的 B；即使 B 也已退役，也不会自动跨过 B 创建 C。
   创建 C 必须明确指定 B。香橙派重启后取回 B 的记录，不恢复 B 的发送资格。
5. 同一单片机启动编号内可顺序创建多次独立尝试，数据库唯一约束阻止同一前一次准备出现两个后继。
   已授权、已执行或仅本地等待退役的动作不能充当这种未授权父动作。

本批只覆盖同一原目标启动编号。期间单片机再次重启时，不能顺手修改 B 的目标编号；
跨新启动编号的恢复、已授权动作处置仍须继续实现，不把这些未完成路径定义为必须人工处理。

## 数据及接口

业务 SQLite **38→39**：关门绑定增加唯一的“前一次动作编号”，取消问题编号只能绑定一次关门的限制。
根准备指向原首次开门，后继准备指向原退役关门；原问题、原投递和原重启证据不换根。
子表的原始证明、摘要、状态和外键在同一迁移事务中保留；任何一步失败整体回滚。

新增 `dispatch_retired`，表示已可靠证明这条准备不会发送。它和本地最终退役状态同事务提交，
并在启动、准备新命令及发送登记前核对原始证明。它不是单片机回复，也不是单片机重启标记。
未决命令查询及唯一索引只排除这种有证明的退役命令，原决定、原序号和所有历史命令保留。

永久数据库基础版本仍为 **3**。恢复绑定扩展表从五列演进为六列：增加唯一父动作关系，
允许同一原开门有多个顺序恢复尝试。合法旧表在普通启动时不改写；第一次成功的后继准备或退役
才在同一事务升级。未知附加索引或触发器明确拒绝，不能重建表时静默删除。

新增专用本地接口 `PREPARE_NATIVE_RECOVERY_CLOSE_SUCCESSOR`、`RETIRE_NATIVE_RECOVERY_CLOSE_SUCCESSOR`，
分别表示准备新后继及退役原后继。原接口继续只接受原字段；新接口必须完整提供父动作编号、
父账本序号、父回执和父退役证据摘要四项。业务客户端按完整字段集合选择接口，不接受部分祖先字段。
默认关闭、调用身份限制、人工停机和维护门禁保持；旧人工异常隔离接口不放宽。

## 业务效果保持不变

- 原问题仍为“单片机重启，未取得最终结果包”，不写成重量全部丢失。
- 已归档后收到原完整结果，只关联追加证据，不恢复正常订单、余额或提现。
- 本地编译的单片机 C 语言控制代码所产生的关门 B 输出，可单独确认 B 的动作账本；
  这不完成原投递许可、不释放占用、不恢复接单，也不代表已在真机验证。
- 不改当前袋、皮重或后续业务；不改变清运恢复、非重启称重失败和仅通信超时的处理规则。
- 完整最终包在归档前已可靠保存仍优先；本批不修改该分支。
