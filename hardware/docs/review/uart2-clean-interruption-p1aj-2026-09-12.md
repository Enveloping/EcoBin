# P1AJ：清运解锁后的中断事实与可靠保存

日期：2026-09-12。范围：本地原生 UART 2.0 候选、真实 C 控制入口与隔离 SQLite。
本批没有连接设备、运行真实串口/GPIO、修改 HMI、烧录、部署或清理旧卡数据。

## 本批实现了什么

MCU（单片机）在原清运已经接受解锁后，检测更新停止、原操作窗口到期、所需控制状态丢失，
或记录“解锁命令已受理但最终检查未能开始通电”。这些情况各自保留独立中断原因；香橙派
可靠保存后，原操作仍为 `CLEAN_RECOVERY_REQUIRED`（需要恢复的清运），仍阻止新业务。

例如清运员已经打开清运门，末重采集一条后发生更新停止：MCU 保存本次测量中断、实际
采样数及耗时，再以独立原因事件引用该测量；不会将它冒充秤超时、测得零克或人工关门。
已有稳定末重或已经到期的测量终态不会被覆盖。若清运员已请求再次开锁，原候选末重不再
用于此次中断，但旧原文继续保留。按钮意图、通断电、测量和中断分别交接，不相互覆盖。

中断事件保存成功只表示“香橙派已经拿到这份记录”，不是恢复成功、清运完成或门已关闭。
没有生成新袋基准、清运完成上报、余额、自动提现或可接单授权。Pi（香橙派）的正式业务
驱动与永久动作账本核对仍待接，本批保存的是 MCU 报告的身份，不冒充账本匹配证明。

## 协议与单片机实现

- Registry **2.0.0-rc.20** / `CLEAN_INTERRUPTION_CUSTODY_NOT_RUNNABLE`，新增消息
  `CLEAN_OPERATION_INTERRUPTED`（101 / 0x65，载荷 61 字节）。这是独立中断事实，不是动作
  输出或人工关门确认；使用既有独立动作记录池及精确保存协议，不占用称重过程槽。
- 字段包含启动编号、事件编号、首次观察时间、最近已受理的解锁命令、原清运操作、投口、
  当前按钮步骤、原中断阶段、原因及实际末重事件引用。后续仍须核对原解锁的父 START
  命令和配置；原文字段本身不是“确已受理/执行”的永久账本证明。
- 完整三语言守卫拒绝错误身份、越界字段、矛盾阶段/原因和无效末重引用。已冻结人工确认
  的 `CLEAN_FINALIZING`（最终交接阶段）不允许事后改写成中断。
- 首次通电前一起保障 ON/OFF 两条记录和一条独立中断记录的内存与全局编号额度；不足则
  拒绝首次解锁、不漏预留。再次解锁继续使用原中断预留；正常人工确认精确保存、最终结果
  冻结成功后才归还未使用的预留。仅剩三个事件编号时也能保留真实 ON、OFF 和中断原因。
- 脉冲正常时长仍由定时器独立断电。前台观察到操作到期或控制异常时，新增精确脉冲停止
  接口只停止本次匹配的脉冲，不伪造更新锁存、不替其他动作停机；已断电时间不被重写。
  **不是**“整场操作期限已移入定时中断”的证明，前台未运行时仍按原脉冲时长断电。
- 受理与实际通电间可能发生计时推进：保留原 ACCEPTED 回复，用独立原因记录未开始通电，
  不补造 ON/OFF。旧命令重复到达只返回原决策，不重新驱动。
- 更新恰好发生在中断检查与脉冲退休之间时，退休前锁存原阶段/原因，下一次轮询补发原文，
  不因提前切换到恢复阶段而丢原因。仅 PB5 防夹触发不产生清运中断或物理关门事实。
- 控制状态本身丢失且未保留 ON/OFF 时，只报告已知原因，不猜测丢失边沿。不取消可能已经
  发生动作的未完成预留，仍保留恢复占用；这不是已完成此类状态损坏的恢复。

SQLite **schema27 不变**：新 61 字节消息可直接进入既有 64 字节动作证据表。运行制品
清单仍保持旧版本，不因此解除候选禁止运行、自动升级或成对发布限制。
