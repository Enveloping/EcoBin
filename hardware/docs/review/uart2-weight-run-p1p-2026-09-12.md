# 原生 UART 2 配置驱动测量运行 P1P

日期：2026-09-12，承接 [P1O 过程精确交接](uart2-process-handoff-p1o-2026-09-12.md)。
本地候选实现，不是已部署功能；没有连接 SSH、操作串口/GPIO、烧录或修改 HMI/云端。
Registry 仍为 2.0.0-rc.10 / PROCESS_EVENT_HANDOFF_NOT_RUNNABLE，SQLite schema22 不变。

## 本批实现

新增 `hardware_mcu/USER/mcu_weight_run.c/.h`，将已经验证完整的配置投影、单次测量调度、
实际 `ScaleReader` 解码与 `WeightMeasurement` 取值组合为一个前台所有者。无动态分配、
Flash 写入或串口发送。对象静态上限512字节；只在真实 MCU 启动初始化，不因 Pi 重连或换阶段清计数。

- 开始本阶段时复制原配置、配置版本、校准版本和量程。外部配置随后改变，不影响正在采集的结果。
  输入必须来自完整校验的配置；此接口不是 HMI/云端配置的另一套校验入口，也不证明全机配置已应用。
  配置暂存、完整应用、业务受理及投口路由仍由上层检查。禁用投口、无效基本参数不开始采集，
  失败不会擦除上一份已经留存的结果。
- 请求按配置中的250毫秒目标间隔、以实际请求开始时刻调度；单个在途请求，错过周期不突发补发。
  前台通过 `StartOwnedAttempt` 预留本地编号，**返回编号不是物理通道可用的证明或发送许可**。
  本地请求超时按配置的200毫秒候选值；这不是称重模块实测响应上限。
- `FinishOwnedAttempt` 只接收采集入口已经建立归属的完整响应，核对当前测量/请求编号、
  实际完整捕获时间、请求期限及阶段期限。错误身份、重复完成、未来/请求前时间不能进入本次样本。
  CRC、地址、长度、范围错误会消耗本次响应但不生成样本；后续合法新请求仍可恢复采样。
  该方法返回1只表示本次响应被消费，不能当作“称重成功”；成功由复制出的测量类型/可用标志判断。
- 原配置驱动最近5点跨度不超过100克取均值；5秒纯波动取全部合法点中位数。
  缺值、少于5点、过旧数据不变成有效零值；重量零和负数仍允许通过合法范围校验。
  使用64位单调时间并转为本阶段有界相对时间，不因低32位回绕或延迟超过一圈延长采集窗口。
  捕获队列必须在 `Poll` 前按时间顺序排空，不能用主循环处理时间替代捕获时间。
- 终态结果保持冻结，后续测量不能覆盖。业务层先把原结果保存到过程槽等保留区，
  再按精确本地测量编号 `Retire`（退休这块测量工作缓冲）。退休不会清过程槽、最终结果或业务占用，
  也不代表香橙派已经落盘。测量/请求编号不因退休重置；新阶段拒绝旧测量编号。

`WeightMeasurement_ConfigValid` 从原核心提取为无副作用检查，原核心行为不变。
测量所有者据此先检查再写入，不需要在栈上另外复制整块采样缓冲。

## 仍未解决的真实串口边界

当前 `usart1.c::Weight_Read_Start` 每次发送相同的8字节寄存器查询；
`scale_reader.c` 解析的9字节响应不包含请求编号。旧入口会清接收缓冲并在超时后回到空闲，
不能据此认为原生采集归属已经建立。本批没有把这个旧入口直接接到新测量模块。

反例：请求A在100毫秒发出，300毫秒本地超时；请求B在350毫秒发出，A的响应在370毫秒才到。
响应里的地址、功能码、CRC乃至重量可以与B的正常回复完全相同。
如果接收函数直接把“当前编号B”贴上去，新模块无从区分。这是缺少传输事实，不是添加计数器能修复的。

串行规范规定同一时刻一个事务，其串行帧由地址、功能码、数据和校验组成；超时由主站配置。
这些规定不提供本设备“200毫秒后绝不再响应”的实测保证。
参见 [Modbus 官方串行规范 V1.02，第7–9页](https://www.modbus.org/file/secure/modbusoverserial.pdf)。
上述晚到反例是结合本仓库相同读请求作出的推论，不是声称规范承诺了额外恢复能力。

后续真实采集入口必须提供可验证的响应延迟/通道重建边界、完整帧捕获时间和有界交接，
再连接 `Start/FinishOwnedAttempt`。本地 `Poll` 清在途位不代表旧响应已消失；
禁止以清缓冲、静默一小段时间或给收到的数据重新贴号代替证明。
未据此新增用户人工解锁规则，也未改变5秒失败/恢复的既有业务共识；独立业务模块仍可继续实施。

- 新测量运行测试33项：来自实际C完整配置集合的参数，实际9字节响应、250/200毫秒边界、
  5秒中位数、32位回绕/超长前台延迟、坏包恢复、缺值、跨阶段配置/编号隔离、冻结/退休。
- 其中8项跨模块闭环：稳定均值/中位数各走四类投递/清运过程事件，实际C组装与保留槽，
  真实 EdgeStore SQLite 原文+原步骤关系同一提交，提交后精确确认。
  使用实际取得的原配置/校准版本；本地测量号12不冒充事件号17。
  查询保存记录与业务状态确认未产生最终上报任务、业务放行或资金效果。

  探针标记 `DO_NOT_FLASH`，不运行/烧录；没有启动/真实驱动/完整业务，也不是完整中断与调用栈证明。
