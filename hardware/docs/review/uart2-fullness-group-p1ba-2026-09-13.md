# P1BA：真实超声波多样本采集与整组结果

日期：2026-09-13。状态：本批候选本地实现与验证完成，未部署、未烧录。
上一批见 [P1AZ 原始超声波采集](uart2-ultrasonic-source-p1az-2026-09-13.md)。

## 1. 本批接通的实际路径

新增 McuFullnessRun：从实际完整配置及全机已应用记录核对开始，经过原始驱动的真实
触发/回波/超时中断，逐次发布设备原始事实，最后保留整组结果。测试只模拟 GPIO、
定时器和时钟边界，没有用预制距离数组替换 C 采集驱动或结果计算器。

本板仍只支持投口1的超声波来源。数字红外、其他投口、禁用投口、未应用或正在暂存的
配置不会启动采样。投口使能状态、静置时间、回波期限、采样数量、最少有效数量、距离
阈值都读取原始配置，没有另设默认值；版本、完整配置摘要和 MCU 子集摘要随组结果冻结。

- Begin 只建立一组采集并预留唯一传感器，不立即发送脉冲。
- 前台 Poll 在原静置时间结束后发起真实请求，一次最多发起一个；驱动中断继续负责
  触发脉冲与回波期限。前台延后不会补造缺失样本、重复计算一次观察或突发补采。
- 完成观察先发布到设备事实，成功后才按原请求号退役并累积一次；失败不复用旧距离。
- 采够原配置数量后冻结组结果；重复 Poll、Copy、Interrupt 不改变原值或时间。
- 结果包括组内单调编号、原配置身份、开始/冻结/最后采集时间、请求数量、已完成数量、
  有效数量、取值依据和可选代表距离。原始事实仍保留最后一次实际读取，不替换为中位数。
- Retire 必须匹配仍保留的原组编号；下一组清空计数/结果但不重置编号，不串入上一组数据。

例如，原配置要求5次、最少3次有效：200、1000、300、400、250毫米得到代表距离300毫米；
若只取得200和100毫米两次有效观察，其余三次失败，则保留有效数2，不把旧距离补成第3次。

## 2. 整组取值与业务边界

遵循现有 UART 合同中的三种取值依据：

- 有效数达到原配置要求：对本组全部有效毫米距离取中位数，MEASURED_MEDIAN。
  偶数项取中间两项平均，四舍五入到整数毫米，半毫米向上；代表距离严格小于配置阈值
  才为 BLOCKED（传感器判断被遮挡），等于阈值为 CLEAR（传感器判断未遮挡）。
  例如中间两项100和103毫米，代表值为102毫米。
- 有效数为0：NO_ECHO_CLEAR_FALLBACK，保留 CLEAR 和无代表距离。
- 有效数大于0但不足要求：INSUFFICIENT_VALID_SAMPLES_CLEAR_FALLBACK，同样保留 CLEAR
  和无代表距离，同时如实记录实际有效数量。

回退不冒充一次有效读数，不新增称重故障。原始设备事实可以是 UNAVAILABLE，整组结果
同时明确采用已约定的 CLEAR 回退；这两个字段描述不同层次，不能混成“传感器测得零距离”。
没有自动校准、修改距离阈值或推导袋容量百分比。

**本批不是完整满溢业务上线。** 组编号仅是本地采集身份，不是 MCU 启动编号、UART
全局事件序号或后端检测编号。后续整合者必须绑定原业务/袋/配置，并将原组结果形成
可靠过程记录，取得香橙派精确保存确认；本地 Copy/Retire 不能代替串口确认或 SQLite 落盘。

不恢复 [V25](../../../docs/architecture/fullness-reporting-v25.md) 已退役的后端主动检测任务：
正常投递/清运仍由香橙派在对应业务被后端确认后，根据本次观察计算当前袋状态，按既有
FULLNESS_STATE_CHANGED 链路上报。这里不会修改当前袋 FULL/NOT_FULL、释放业务占用、
阻止下一单或产生资金；实际业务接线和袋状态转换仍未完成。

## 3. 独占、取消与时间

原始 UltrasonicReader 新增同一前台内的独占预留。整组所有者使用稳定内存地址作为本地
所有者标识；原始诊断入口不能开始、复制或退役它的观察，另一组也不能插入或取走结果。
只有无请求且无待取观察时才能释放传感器。完成组会释放物理采集资源，但仍保留组结果；
随后退役旧组不会错误释放已经交给下一组的传感器。

调用 Interrupt 或发现原配置身份/暂存状态发生变化时，尚未冻结的组停止继续采样：

- 先保存已经真正完成的观察和数量，再取消仍在等待的触发/回波请求。
- 返回本地 INTERRUPTED，另记调用方取消或配置变化；无传感器判断、无回退依据，
  不把部分组改成 CLEAR，不把主动取消改成超时，不触发任何业务后果。
- 若原始事实暂时无法接收，或中断恰好在“读取结果”与“取消请求”之间产生真实完成，
  取消接口拒绝丢弃该观察；后续 Poll 继续交接同一原文，停止原因不丢失、不重开采样。
- 这仍是本地 RAM 保留，不是掉电持久化；不把 MCU 重启数据丢失政策视为已实施。

本轮行为测试暴露并修复两处时序细节：

1. 原时钟在板上按10毫秒节拍推进。100毫秒无回波之后立即开始短距离采样，可能得到
   同一个捕获时间但内容不同的两条观察，原始事实正确拒绝覆盖后会卡住采集。
   整组和配置驱动的单次诊断入口现在都等待事实时钟真实前进后再触发下一次采集，
   包括跨组切换；没有篡改旧时间或放宽冲突校验。原始驱动至少70毫秒的请求起点间隔保留。
2. 原始事实发布期间时钟可以前进；组冻结时间改为在释放物理资源后重新读取实际时钟，
   不能沿用前台 Poll 进入时的时间，原采集时刻保持不变。

对新的共享原始发布入口也增加来源范围检查：拒绝零有效脉宽、超过支持期限的脉宽、
失败状态携带非零脉宽、零请求号和未知状态，不让整数乘法溢出变成有效毫米值。
