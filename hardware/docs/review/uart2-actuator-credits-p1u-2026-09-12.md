# P1U：MCU 动作记录的共享事件编号额度

日期：2026-09-12。用户已授权按既定计划继续本地实施。

## 完成范围

单片机的原生控制入口现持有唯一一份八条动作记录池。预留动作记录时，
同时检查记录空间和全局事件编号的剩余额度；已经预留但尚未生成的每条记录，
都保留一个将来可用的编号名额。无需另外维护一份可能与记录池不一致的额度账本。

例如清运锁准备通电时预留两条记录：通电记录生成后，中间即使产生称重记录，
也不能用掉断电记录所需的最后一个编号。实际编号在各条记录生成时才分配，
不会提前把尚未发生的断电排在后来的称重之前。

这是**记录资源的本地实现**，不是已经接通动作执行或 MCU—香橙派可靠交接。
未连接设备、SSH、真实串口、GPIO、HMI、云端或生产数据库；未部署、烧录。
协议仍为 `2.0.0-rc.11 / ACTUATOR_EVENT_GUARDS_NOT_RUNNABLE`，SQLite schema22不变。

## 具体规则

1. 现有 `McuControlEndpoint_ReserveEventSequence` 仍是普通事件的共享分配入口。
   只有“剩余编号数大于已预留的未生成记录数”时才分配一个编号。
   真实业务准备中的前置称重记录已使用这个入口，不另外复制一份分配逻辑。
2. `ReserveActuatorEvents` 一次检查编号与内存空间，全部满足才建立预留。
   失败不修改记录、计数或调用者的凭据；预留凭据绑定当前 MCU 启动编号。
3. `PublishActuatorEvent` 接收仅在本机使用的模板：事件编号暂为零，其余字段已确定。
   它填入下一个共享编号，经过现有完整协议校验并冻结原文后，才推进全局计数。
   编号为零的模板不是合法线级报文，不能发送；发布函数本身也不发送串口数据或驱动输出。
4. 已发布成员的完全相同重试返回原编号，不占新额度，也不让已确认的数据重新待确认。
   改动正文、错类型、错成员、旧启动凭据和已被容量复用的旧成员均拒绝。
5. 未生成记录的预留数直接从固定八个槽读取。成功发布消耗一份额度；
   精确保存确认只释放对应的原文空间，不释放另一条未生成记录的额度。
   编号耗尽后仍可查询、确认和返回原发布结果，不回绕或复用编号。
6. 只有整组尚未生成过任何记录时才能取消，取消同时归还未使用的空间和编号额度。
   已生成过通电记录后，即使其原文已保存且槽位被复用，也不能取消仍预留的断电记录。
   调用者仍必须在取消前证明动作未开始；本模块没有动作状态机，不能替调用者作此判断。
7. 香橙派重新探测或重复绑定，不重置编号、预留或已保留原文。
   只有真实 MCU 重启后重新绑定才清空 RAM；旧启动凭据不能作用于新启动的同号预留。
8. 单一前台所有者、固定八槽扫描，无动态内存、阻塞等待或 Flash 保存。
   已附着的生产者必须走控制入口的动作 API，不能绕过入口直接修改底层记录池或计数器。

对已发布/尚待发布记录的任何确认或取消都不产生订单、余额、审核、提现或云端业务效果，
不释放作业占用，也不决定下一单资格。PB5、逻辑门状态和称重取值共识均未改变。

## 实现位置

- `hardware_mcu/USER/mcu_control_endpoint.h/.c`：拥有唯一动作记录池，统一额度预留、
  发布、取消、只读复制和本地精确保存入口；新绑定时初始化。
- `hardware_mcu/USER/mcu_actuator_event_journal.h/.c`：未填槽计数、原编号幂等发布，
  复用原有完整正文校验与冻结逻辑；保留底层独立 RAM 模块的明确边界。
- `hardware/tests/test_mcu_actuator_event_credits.py`：28项实际C控制入口测试。
- `hardware/tests/test_mcu_work_preparation.py`：增加真实称重生产者与动作额度竞争的联合测试。
- 原控制入口测试/主机辅助代码更新接口和对象空间；核心容量探针把独立记录池移入控制入口，
  不再重复计入第二份池。未改 MCU 主程序或 Keil 正式工程。

## 验证

本轮使用 `tdd` 技能，依次先编写额度保护、交错发布、取消和精确保存测试，
确认实际 C 入口缺失导致失败后，再逐项实现；通过后合并重复的成员查找代码。
测试直接编译调用真实 C 模块，不用 Python 模型代替实现。
最大序号由测试专用接口注入，避免真的执行四十多亿次调用；生产没有该接口。

- 28项新控制入口测试与38项业务准备、1项目标链接检查：**67 passed**。
- 最终相关集合：**216 passed**（47.90秒），含45项既有记录池、55项首次开门检查、
  49项动作协议守卫；没有实际机械动作。
- 契约验证：**25 passed / 0 notes**。38帧、1167流轨迹、5摘要跨 Python/Java/C 一致；
  **104**生成物与权威源一致，未重写生成物或修改三个冻结的旧运行制品。
- 最终 ARMCC5 核心链接探针：Code32024、RO1540、RW40、ZI5232；
  ROM **33604**、RW+ZI **5272**字节，比P1T增加480字节ROM，静态RAM不增加。
  新入口均作为链接根保留；`DO_NOT_FLASH`只是链接探针，不能烧录或执行，
  不是主程序、驱动、中断及完整栈的空间证明。
- 两个修改的C模块通过Clang静态分析，无诊断；生成物检查、`git diff --check`及
  本轮12个源码/测试/证据文件的行尾空白检查通过。
- 最终扩大回归不排除用例：**1017 passed、34 skipped、1620 subtests passed**
  （223.65秒），零失败；覆盖契约、原生控制/测量/数据交接、EdgeStore、强杀恢复、
  旧固定帧/UART1适配、发布安装及更新边界。34个跳过项不算通过，也不代表真机验证。
  前几批的 `DeviceAsset.listStatus` 接口声明测试本轮也已通过；本批没有修改该接口、
  后端或测试预期，不把其他工作流的修复归因于本轮。
  SQLite强杀恢复本轮通过，但历史偶发WAL I/O错误的根因仍未确定，不宣称已修复。

## 后续

下一步是动作记录与原命令/业务的关系、串口原文查询、精确保存回执及香橙派同事务保存。
现有测量保存回执不能直接当作动作保存回执；本轮 `ConfirmActuatorEventSaved` 仍是本地API，
调用方必须先取得真实持久保存证明，当前没有将它接到串口ACK或Pi写库。

随后再接100毫秒换向等待、单次输出、自动关门、清运再次开锁与独立断电调度。
记录不足不能成为延迟断电的理由，额度申请成功也不代表拥有开门授权。
P3整体尚未完成，旧适配层仍未移除，当前无需用户操作设备或重新烧录。
