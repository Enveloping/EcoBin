# 原生 UART 2 业务准备阶段 P1Q

日期：2026-09-12，承接 [P1P 配置驱动测量](uart2-weight-run-p1p-2026-09-12.md)。
本批只做本地候选实现，没有连接 SSH、操作串口/GPIO、部署、烧录或修改 HMI。
Registry 仍为 2.0.0-rc.10 / PROCESS_EVENT_HANDOFF_NOT_RUNNABLE，SQLite schema22 不变。

## 已接通的路径

新增 `hardware_mcu/USER/mcu_work_preparation.c/.h`：实际 C 字节流入口接收配置分段及
开始投递/开始清运命令，经过原会话去重和配置核对后，建立原业务的前置称重阶段。
它使用实际配置集合、测量运行模块、重量解析/取值核心、过程事件组装与保留槽，
不是另写一套模拟状态机。无动态分配、Flash 写入、机械输出或串口主动发送。

1. 香橙派发来 CONFIG_BEGIN/DEVICE_BLOCK/PORT_BLOCK/COMMIT 时，现有完整内容校验先处理
   字段、摘要和启动/命令身份，再由真实配置集合收齐、核对并保留候选配置。
   每次只回复真实命令决定，不把“完整收到”宣称为“整机配置已应用”。
2. 香橙派发来 START_DELIVERY_SESSION / START_CLEAN_OPERATION 时，先查询是否已有原命令决定。
   重复命令返回原决定，不重新采样、覆盖业务或重置受理时间。
   新命令必须对应当前启动、当前投口、启用的完整配置，以及外部已发布的同版本、同完整摘要、
   同 MCU 子集摘要的应用事实；配置仍在暂存、原业务仍运行或结果仍占用时拒绝新业务。
   投递命令中的继续等待、自动关门、负重量阈值和单价还须与原配置精确一致。
3. 受理后保存完整原始 START 字节及 64 位单调受理时间，建立投递的首次开门前测量阶段，
   或清运的首次解锁前测量阶段。START 本身不打开投递门或清运锁。
   后续 `CopyStart` 只读导出原字节/时间，供后续授权窗口检查，不是延长窗口或重发许可。
4. 已建立响应归属的采集入口把实际原始帧交给测量运行模块；前台非阻塞 `Poll` 更新测量事实。
   稳定均值或 5 秒中位数形成第一份过程记录；5 秒真正无可用数据形成 UNAVAILABLE/WEIGHT_TIMEOUT，
   不用 0 克冒充有效重量。原始样本归属的真实硬件限制仍见 P1P，本批没有接旧 RS485 收包入口。
5. 原过程记录先冻结到 C 保留槽，再退休本地采样缓冲。可用重量进入等待首次开门授权/首次解锁的阶段；
   不可用重量进入对应的 FINALIZING（准备形成最终记录）阶段，不进入开门等待阶段。
   **这不表示最终 WORK_RESULT 或失败上报已经产生**，最终收口执行器仍待实现。
6. 香橙派按原业务和原步骤查询，可取回保留的完整事件；通过既有真实 EdgeStore 保存原文与步骤关系，
   同一 SQLite 提交成功后才精确确认。确认只释放这份过程交接槽，不清除原业务、首次重量或最终结果，
   不代表接单放行、开门、上云、结算或资金处理。

## 接口边界与修复

- `McuControlEndpoint` 新增仅在启动绑定前安装一次的命令/绑定回调。默认不挂业务回调时，仍保持原只读
  控制入口行为。只有完成帧/内容校验后才调用业务模块；不支持的开门授权、解锁等命令不伪造受理。
  单个前台拥有该端点及准备对象，回调有界、不得重入，外部缓冲不得重叠。
- 必须提供显式的上层前置检查回调，核对尚未纳入本模块的整机配置消费者、安全、能力、准入和授权条件。
  本模块另行检查实际发布的配置事实；回调返回“无错误”也不能绕过配置缺失。
  **正向测试显式建模了“其他消费者已完成应用”的边界**：测试调用真实配置事实发布 API。
  这不是实际各消费者已经接通或真机能够接单的证据；生产模块本身没有发布全机 APPLIED。
- 抽出 `McuWorkState_CanBegin` 无副作用预检查，复用原业务记录的全部约束。
  修复先回复 ACCEPTED、随后才发现复用了上一笔已释放业务编号的问题：现在先拒绝，旧记录不变。
  该检查不代替会话授权；正式写入仍须在真实会话接受后执行。
- 增加端点级、启动内共享的关键事件序号分配器；未绑定/耗尽返回 0，不回绕。
  第一次重量身份采用 `EBM1 + MCU 启动编号 + 关键事件序号` 的非随机 16 字节标识，
  不把本地测量号或传输号当作事件号。香橙派重连/重复绑定不重置它，实际 MCU 启动才初始化。
- 修复延迟发布刷新重量新鲜度的问题。终态时间来自“本次开始时间 + 核心冻结耗时”，而非后来执行 Poll
  或查询的时间。例如 1020 毫秒已完成的测量到 60000 毫秒才发布，设备事实与过程记录仍保留 1020。
  5 秒超时记录仍保留 5000；历史结果可以交接，但不能因此被当作刚测得的健康数据。
- 原始 START、首次测量与业务记录在香橙派重连后保持；实际 MCU 重启清空这些 RAM 数据，并回到未绑定。
  新启动绑定后旧 START/原业务查询返回启动不匹配，不补造旧数据。

缺重量未留下证据、未实际应用却接受业务、原窗口丢失、复用旧业务编号以及延迟刷新时间。
正向测试使用实际 C 配置/会话/业务/重量/事件核心和真实 SQLite，不以 Python 替代这些逻辑。

- 新准备阶段测试 37 项：两类 START、配置版本/摘要/应用/暂存核对、重复/忙碌/上层拒绝、完整原参数/时间、
