# P1BS：主入口中的独立原生恢复候选

日期：2026-09-13，接续 [P1BR 独立关门尝试](uart2-recovery-close-successor-p1br-2026-09-13.md)。
继续原计划 P4（设备重启后的业务恢复与动作核对）；这是已归档投递的恢复运行入口，
不是完整原生业务网关，也未部署。

## 入口和业务边界

`main.run_gateway()` 在构造网关前作明确分派：无参数保持现有网关；仅显式
`--native-recovery-candidate` 进入本批恢复候选，未知参数拒绝，不回退旧协议。
未修改服务启动命令、配置默认值或发布清单，因此现用设备不会自动切到候选。

候选使用独立前台循环，不调用旧 `boot_sequence()` 的中断处理，不创建旧 `WorkManager`，
不启动云端、相机或旧串口事件线程，不发送 systemd 的 READY 就绪通知。
每次状态都明确 `admissionAllowed=false`，表示不允许接新业务；入口还会拒绝错误返回的允许接单状态。
没有把旧固件或旧协议兼容适配混进新循环。

候选只打开显式指定、已经存在的原生候选数据库。SQLite使用 `mode=rw`，防止路径错误时创建新库；
接受已有版本36至当前39，按既有事务迁移和完整性规则检查。旧生产25、空库、缺失和损坏库拒绝。
这个专用打开入口不恢复云端正在发送的事件，也不清空原业务。构造或轮询失败关闭资源，不换旧协议继续。

## 启动后实际推进什么

这里的“准备”是已经落盘的关门命令及其编号，不代表已获授权或已经发送；
“永久账本”是永久管理层保存的动作记录，确认只更新对应动作的证据和结论，不等于完成原投递。

1. 从同一SQLite事务保存启动时的原投递占用、原问题和全部既有恢复关门编号快照。
   原设备、工作编号、工作类型、投口及原占用必须一致；不根据后来新出现的准备扩大启动处理范围。
2. 用实际原生启动会话重新查询单片机。旧库里保存的启动号不冒充当前在线；仅超时不当成再次重启。
3. 对启动时已有且未登记发送的准备，查询永久账本，再经P1BQ专用通道确认其从未获得授权并退役。
   原账本已经授权的动作不走这一通道，不误写成“从未授权”。
4. 对已登记可能发送的旧关门，只查询原命令、获取并精确保存执行器事实，再核对原受理与输出证明。
   执行器确认只在SQLite提交原文后发送；不重发旧开关门。单片机说“没有见过命令”仍不能证明未执行。
5. 已经可靠保存、且通过上述原受理和输出证明校验的完整关门输出，可在单片机离线或再次重启后完成永久账本确认。
   这只确认历史动作；当前启动号不同仍显示需处理换代，不据历史输出允许新动作。
6. 归档后收到原投递最终包，经原完整身份和正文校验后追加问题证据；不恢复正常上报、袋或皮重。
   本批循环尚未接结果查询交接，因此对收到的迟到包只保存，不发送 `RESULT_SAVED`（结果已保存确认）。
   具备完整查询关联后的确认/释放由已有结果交接组件负责，接入此循环仍是后续任务。

启动快照之后的新准备不会被退役，也不会被误认为不存在。它会显示
`PREPARATION_CREATED_AFTER_STARTUP`（发现启动后新准备），留给该准备自己的所有者处理。
旧准备均退役时显示 `NEW_CLOSE_REQUIRED`（后续需要独立关门），本循环并不创建或发送它。
旧关门输出确认完成也不完成原业务许可、不释放占用、不恢复接单、订单、余额或提现。

读写均在同一前台线程，每次读取最多512字节，写入只尝试一次且有超时，不刷新/重传/后台排队。
循环每次最多推进一个动作的永久核对，并对失败核对保留一秒间隔；本地接口和存储各自有有界超时，
不是宣称整轮必在50毫秒内完成。循环间隔50毫秒，退出时关闭串口和数据库，恢复信号处理器。

## 串口所有权边界

候选要求POSIX独占打开；补齐旧 `uart_link.py` 的 `exclusive=True`，与已有固定帧适配器使用同一
串口文件的协作锁。Linux真实伪终端验证旧/新两种打开顺序均互斥，关闭后可接管。

这不是对任意进程的强制隔离。外部 `stm32flash`、独立HIL脚本及历史硬件层尚未证明参与同一锁。
候选不能与这些操作并行，不能因本批测试通过就在现场启动它；受控维护交接仍需后续集成。
本批没有执行真实串口、SSH、GPIO、烧录或维护操作。

## 审查与验证

使用TDD技能逐段复现并实现，子代理独立核对运行入口、已授权边界及POSIX串口锁，主代理统一集成。
doc-coauthoring技能用于业务边界和独立读者检查；两项投递结果取舍保持已确认，不再待裁决。

测试从 `main.run_gateway → native_recovery_entry → NativeRecoveryRuntime` 运行，使用本地编译的
真实C语言控制代码、原问题数据、两份业务SQLite连接及永久账本；只替换串口/本地套接字系统边界。
不以无原业务的空循环或策略函数通过，冒充启动恢复已接通。

实际复现并修复了以下问题：当前启动号不匹配导致历史输出无法确认；多代记录的已退役父动作
阻挡后继历史输出核对；启动后新准备被状态误报为不存在；旧UART1.0未参与候选协作锁。
独立读者检查对默认选择、禁止新动作、未见命令、历史确认、问题证据和锁边界六项均回答正确；
依据反馈补充了准备/永久账本含义及结果确认尚未接入的边界。

扩大回归 **1148通过、10跳过，196.27秒**，无失败。该组合启动后补了离线/换代多代轮询反例，
其修正与最终相关集成另行复跑，不把首次扩大组合当作新增反例已覆盖。
修正后最终相关集成 **197通过、4跳过，64.59秒**；新增专项最终 **47通过、4跳过，8.89秒**。
新增专项包含原生循环16项、主入口29项、串口参数2项及4项POSIX实际互斥用例；后四项已在Linux补验。
以上测试进程均退出0，JUnit已核对零失败、零错误，不把扩大组合与最终相关组合重复相加。
完整契约 **25通过、0 notes**，109生成物精确匹配，Python/Java/C共享向量通过。
Linux伪终端及UART1.0回归 **30通过，1.96秒**，四种实际打开顺序均通过，未下载依赖。
使用缓存Python3.11、Java21、Clang及已有WSL离线环境。

临时JUnit：`ecobin-p1bs-regression.xml`、`ecobin-p1bs-final-integration.xml`、
`ecobin-p1bs-new-tests.xml`、`ecobin-p1bs-posix-serial.xml`。Windows跳过项不当作Linux已验收；
Linux本批只补串口协作锁及UART1.0，不把它当作所有POSIX权限和服务场景通过。

## 原计划后续，不改成人工兜底规则

- 已授权但未登记发送：需要准确的专用持久撤回处置，不能放宽从未授权退役或冒用旧活进程令牌接口。
- 已登记发送且同启动号只查到NOT_SEEN：查询本身不封禁迟到命令，不能据此重发；继续取证与封禁设计。
- 再次单片机重启：可隔离旧目标命令，不等于重启前从未执行；需保留未知效果并接新代独立动作。
- 本候选还未负责首次问题归档、清运恢复、正常原生业务、新关门的当前安全检查和最终接单，
  也未连接云端消费者、Java/Pi联合交接或问题展示。P4/P5和完整main切换仍未完成。

业务39/永久3、UART rc.22、OneNet2.2.0、MySQL V79/权限40均未变；发布25/39不匹配门禁保留。
没有构建镜像、部署或烧录，RS485现场、HMI、完整固件容量和成对发布仍有门槛，当前无需用户操作。
